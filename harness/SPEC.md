# 룰 선언 패턴 v1

여러 프로젝트를 동시에 굴리는 1인 작업공간을 위한 에이전트 하네스 규격.
이 파일은 규격 자체이며 특정 프로젝트에 속하지 않는다. 새 저장소로 이식할 때 `harness/`를 통째로 복사한다.

기준일 2026-08-15 · 근거: Claude Code 공식 문서(memory·context-window·hooks·skills), agentskills.io, AGENTS.md 규약

## 0. 왜 이 규격인가

에이전트 하네스가 실패하는 방식은 두 가지다.

1. **유실** — 확정한 사실이 컴팩션·세션 종료로 사라져 처음부터 다시 조사한다.
2. **무시** — 룰이 파일에 멀쩡히 있는데 지켜지지 않는다.

1번은 로딩 메커니즘 문제이고, 2번은 분량 문제다. **둘의 해법이 반대 방향이라 한 파일에 다 넣으면 반드시 하나가 깨진다.**
유실을 막으려면 상시 로드해야 하고, 무시를 막으려면 상시 로드를 줄여야 한다.

그래서 계층을 나눈다. 각 계층은 서로 다른 메커니즘에 얹히고, 서로 다른 예산을 갖는다.

## 1. 4계층

| 계층 | 메커니즘 | 로드 시점 | 컴팩션 후 | 예산 |
|---|---|---|---|---|
| **L0 강제** | `.claude/hooks/` | 코드 실행 | 무관 (컨텍스트 아님) | 없음 |
| **L1 헌법** | `AGENTS.md` + `CLAUDE.md` 어댑터 + 학습로그 | 항상 | 재주입됨 | **합계 145줄** |
| **L2 지식** | `.claude/skills/<name>/SKILL.md` | 설명만 상시 · 본문 온디맨드 | 호출된 것만 재주입 | 파일당 200줄 |
| **L3 상태** | `project_state.md` + SessionStart 훅 | 훅이 주입 | 매 세션 새로 주입 | 없음 |

**배치 판정 한 줄** — 어겼을 때 사고가 나면 L0. 항상 참이면 L1. 특정 일을 할 때만 참이면 L2. 다음 주에 바뀌면 L3.

애매하면 아래 순서로 내려간다. 위로 올리지 않는다 — L1이 커지면 전체 준수율이 떨어진다.

### 근거

- 상시 로드 파일의 금전 비용은 프롬프트 캐싱이 대부분 상쇄한다(캐시 읽기 = 표준 입력가의 약 10%). **상시 로드의 진짜 비용은 돈이 아니라 준수율이다.**
- 모델이 안정적으로 지키는 지시는 150~200개이고 시스템 프롬프트가 이미 약 50개를 쓴다. L1 100줄은 이 예산 안에 머물기 위한 값이다.
- 컴팩션 생존 여부는 로딩 방식이 결정한다. 루트 `CLAUDE.md`와 `paths:` 없는 `.claude/rules/*.md`는 재주입되고, `paths:` 붙은 룰과 하위 폴더 `CLAUDE.md`는 유실된다. **호출된 스킬 본문은 재주입된다** — 온디맨드와 생존을 동시에 만족하는 유일한 메커니즘.
- 스킬 본문 재주입에는 스킬당 5,000토큰·합계 25,000토큰 상한이 있고 **잘릴 때 파일 앞쪽을 남긴다.** 그래서 3번의 본문 순서가 규격이다.

## 2. 선언 헤더 — 이 규격의 본체

L2의 모든 파일은 프로젝트 성격과 무관하게 아래 8필드를 동일한 형식으로 선언한다. **본문 구성은 자유다.**
이것이 2층 계약이다 — 등록 형식은 하나, 작업 방식은 여럿.

```markdown
---
name: <슬러그, 폴더명과 동일>
description: <무엇에 대한 것인가. 그리고 어떤 단어가 나오면 로드할 것인가>
---

> 모드: <PM조율|개발|사무|조사> · 정본: <경로 하나> · 상태: project_state.md#<앵커>
> 마감: <YYYY-MM-DD|없음> · 패턴: <대장형|페르소나형|...> · 갱신: <YYYY-MM-DD>
```

| 필드 | 값 | 이 필드가 막는 사고 |
|---|---|---|
| `name` | 폴더명과 동일한 슬러그 | 호출 불일치 |
| `description` | 대상 + 트리거 단어 | 필요할 때 로드가 안 되는 것 (온디맨드의 유일한 실패 모드) |
| 모드 | 4종 중 하나 | 공정 혼동 |
| **정본** | **경로 정확히 하나** | **같은 사실에 문서가 다른 말을 하는 것. L0 훅이 존재를 검증한다** |
| 상태 | 현황판 앵커 | 룰에 진행 상황이 섞여 룰이 낡은 사본이 되는 것 |
| 마감 | 절대 날짜 | D-day 오산 |
| 패턴 | 내부 작업 방식 이름 | 프로젝트마다 다른 방식을 억지로 통일하는 것 |
| 갱신 | 절대 날짜 | 문서 간 모순 발견 시 어느 쪽이 최신인지 판정 불가 |

**정본이 이 헤더의 핵심이다.** 경로를 정확히 하나만 적기 때문에 기계가 검증할 수 있다.
`description`은 사람이 아니라 에이전트가 읽는다 — "관세청 프로젝트 정보"가 아니라 실제 등장할 단어를 넣는다.

### 이식성 제약 (2026-08-15 실측 정정)

**`name`은 소문자 영문·숫자·하이픈만.** 1~64자, 하이픈으로 시작·종료 불가, 연속 하이픈 불가, **폴더명과 정확히 일치**. 한글 폴더명은 Claude Code에서는 동작하지만 규격 위반이라 `skills-ref validate`와 타 도구 패키징에서 실패한다. 한글 트리거는 `description`에 넣으면 매칭 성능 손실 없이 유지된다.

**프론트매터는 표준 필드로 제한한다** — `name` · `description` · `license` · `compatibility` · `metadata` · `allowed-tools`. Claude 전용 필드를 넣으면 타 도구 패키징이 하드 에러로 실패한다. 선언 헤더를 프론트매터가 아니라 본문 첫 줄 인용 블록으로 두는 이유가 이것이다.

**탐색 경로가 도구마다 다르다.** 스킬 포맷은 표준이지만 위치는 아니다.

| 도구 | 탐색 경로 | 이 저장소 |
|---|---|---|
| Claude Code | `.claude/skills/` | **정본** |
| Cursor | `.claude/skills/`·`.codex/skills/` | 그대로 동작 |
| Codex CLI | `.agents/skills/`·`.codex/skills/` | 정션 필요 |

`.claude/skills/`를 정본으로 두고 `.agents/skills`는 **기기별 디렉터리 정션**으로 만든다. git은 정션을 추적하지 못하므로 `.gitignore`에 넣고 새 기기에서 1회 생성한다 — 사본을 커밋하면 정본이 둘이 되어 사고 유형 4가 된다.

```cmd
mklink /J .agents\skills .claude\skills
```

**훅(L0)은 Claude Code 전용이라 이식되지 않는다.** 이식 후 남는 것은 마크다운 계층 구조 + 강제력 0이다. 다른 도구로 옮길 때는 그 도구의 훅·게이트 수단으로 L0를 다시 만들어야 하며, 그 전까지는 이 하네스의 핵심 이점이 없다.

## 3. 본문 순서 — 재조사 비용이 큰 것부터

컴팩션 재주입은 스킬당 5,000토큰까지, **앞쪽을 남긴다.** 그러므로 위쪽은 특권 자리다.

정렬 기준은 "중요도"가 아니라 **재조사 가능성**이다. 정본 문서를 다시 읽어 복구되는 것은 뒤로, 어느 원본에도 없어 겪어야만 아는 것은 앞으로.

1. **한 줄 정의** — 무엇인가
2. **절대 규칙** — 어기면 사고가 나는 것. 번호 매김
3. **함정** — 규격·문서와 실제 동작이 다른 지점. **어느 원본에도 없다. 잃으면 복구 불가**
4. **확정 사실** — 정본 문서에 있으므로 최악의 경우 다시 읽으면 된다. `- [YYYY-MM-DD] 내용 (출처: …)`
5. **파일 지도** — 폴더를 보면 재구성된다
6. **지침 로그** — 누적 기록

> `[2026-08-15 정정]` 종전 순서는 확정 사실이 3번, 함정이 4번이었다. 관세청 스킬에서 확정 사실 15항목이 함정을 5,000토큰 밖으로 밀어내 **컴팩션 후 함정 전체가 사라지는 것을 실측으로 확인**했다. 재조사 비용 기준으로 3·4번을 맞바꿨다.

**요구사항은 "파일이 5,000토큰 이하"가 아니라 "잃으면 안 되는 것이 앞 5,000토큰 안에 전부 들어간다"이다.** 파일이 더 길어도 뒤쪽이 버려도 되는 내용이면 통과다. 확인 방법:

```bash
awk '{h=gsub(/[가-힣]/,"&"); o=length($0)-h; tk+=h+int(o*2/7);
      if(/^## /) printf "%6d %s %s\n", tk, $0, (tk>5000?"◀잘림":"생존")}' SKILL.md
```

앞 5,000 안에 안 들어가면 **줄이지 말고 옮긴다** — 상세를 `references/*.md`로 빼고 본문에는 경로와 한 줄 요약만 남긴다. 스킬은 보조 파일 온디맨드 로딩을 지원하므로 이 파일들은 필요할 때만 읽힌다. Agent Skills 규격도 `SKILL.md` 본문 5,000토큰·500줄 이하를 권고하고 상세는 별도 파일로 빼라고 명시한다.

## 4. L0 — 문장으로 막히지 않는 것만

훅은 비싸다. 만들기도 어렵고 디버깅도 어렵다. **같은 실수를 두 번 지적받은 것만** 훅으로 승격한다.

승격 기준: 룰 파일에 문장을 적었는데 그 뒤에 또 어겼다. 이때 세 번째 문장을 쓰지 말고 훅을 쓴다.

| 훅 | 이벤트 | 하는 일 |
|---|---|---|
| `commit_gate.py` | `PreToolUse` (Bash·PowerShell) | 커밋 시 ① **스테이징 대량 삭제 차단** ② 메시지 형식 ③ 저장소 전역 죽은 참조 ④ L2 정본 실재 |
| `session_boot.py` | `SessionStart` | 현황판 주입 + L1 분량·스킬 설명 계측 + 정본·앵커 경고 |
| `block_dangerous.py` | `PreToolUse` | 파괴적 명령 · 무차별 스테이징(`git add -A`) 차단 |
| `protect_paths.py` | `PreToolUse` (Write·Edit) | 시크릿·원본 문서·하네스 자기 보호 |

> `[2026-08-15 정정]` 종전 규격은 `정본_무결성.py`(`Stop`)와 `커밋_형식.py` 2개로 나눴으나, 두 검사가 모두 커밋 시점에 의미가 있어 `commit_gate.py` 하나로 합쳤다.

**정본 검사만으로는 D1이 막히지 않는다.** 2026-08-14 사고는 20파일 8,129줄이 메시지 없이 커밋된 것이고, 정본 dangling은 그 부작용 중 하나일 뿐이다. 직접 방어는 **스테이징 삭제량 검사**이며 정본 검사는 보조다.

**하네스 자기 보호는 유지한다.** `.claude/hooks/`와 `settings.json`은 에이전트가 직접 수정할 수 없다.
차단되면 우회하지 않는다 — 변경안을 diff로 제시하고 사람이 반영한다. 우회하는 순간 그 보호의 의미가 사라진다.

## 5. 새 프로젝트를 여는 절차

1. `harness/templates/SKILL.md` 를 `.claude/skills/<name>/SKILL.md` 로 복사
2. 선언 헤더 8필드를 채운다. **정본 경로부터 정한다** — 정본이 없으면 프로젝트가 아직 프로젝트가 아니다
3. 본문은 1·2번(한 줄 정의·절대 규칙)만 먼저 쓴다. 나머지는 일하면서 쌓인다
4. `project_state.md`에 앵커 절을 만든다
5. L1은 건드리지 않는다

새 프로젝트가 L1에 한 줄이라도 추가를 요구하면, 그건 프로젝트가 아니라 원칙이 바뀐 것이다. 별도로 판단한다.

## 6. 성장 관리

| 대상 | 임계 | 초과 시 |
|---|---|---|
| L1 합계 (`AGENTS.md` 100 + `CLAUDE.md` 어댑터 15 + 학습로그 30) | 145줄 | 즉시 L2로 강등. 예외 없음 |
| L2 `SKILL.md` 본문 | 앞 5,000토큰 안에 함정까지 | 초과분을 `references/`로 이동 |
| L2 스킬 개수 | 제한 없음 (토큰) / **주의** (지시 수) | 아래 단서 참조 |
| L3 `project_state.md` | 60줄 · 프로젝트당 6줄 | 초과분은 각 프로젝트 상태 문서로 |
| 학습로그 각 절 | 10건 | 오래된 것부터 아카이빙 |

L1 합계는 **세 파일의 합**이다. 도구 어댑터를 빼고 계산하면 실측과 어긋난다 (2026-08-15 실제로 겪음 — 훅 계측이 산식 오류를 먼저 잡아냈다).

**스킬 개수 단서** — 토큰으로는 설명만 상시라 선형 증가가 안전하다. 그러나 각 설명은 "이 상황이면 이걸 불러라"는 **지시 1개**이므로 지시 수 예산(150~200)에는 개수만큼 잡힌다. 스킬 20개면 토큰은 그대로여도 지시는 20개 늘어난다. **L3에도 예산이 필요한 이유가 같다** — 현황판은 매 세션 전문이 주입되므로 온디맨드 설계가 여기서 샌다.
| L2 파일 하나 | 200줄 | 정본 문서로 상세를 빼낸다 |
| L2 파일 수 | 제한 없음 | 설명만 상시 로드되므로 선형 증가해도 안전 |
| 학습로그 각 절 | 10건 | 오래된 것부터 아카이빙 |

**L2는 늘어도 된다.** 이것이 계층을 나눈 이유다 — 프로젝트가 20개가 되어도 상시 로드되는 것은 설명 20줄뿐이다.
관리해야 할 것은 L1 하나다.

## 7. 유실 방지 (계층 무관)

- 덮어쓰기 전에 읽는다. 무엇이 사라지는지 먼저 확인한다.
- 정정은 삭제가 아니다. `[YYYY-MM-DD 정정] 종전 X → 신규 Y (근거)` 로 남긴다.
- 요약이 원본을 대체하지 않는다. 요약본에는 원본 경로를 붙인다.
- **문서를 삭제·통합하는 커밋에는 그 문서를 가리키는 선언 헤더와 현황판 수정을 반드시 포함한다.** 이 항목은 L0 훅이 검사한다.
- 모순을 발견하면 조용히 고르지 말고 갱신일을 나열해 비교한 뒤 보고한다.

## 8. 이 규격이 답하지 않는 것

- **자동 메모리**(`~/.claude/projects/…/memory/`)는 기기 로컬이라 동기화되지 않는다. 기기가 바뀌어도 살아야 하는 것은 저장소 안에 둔다.
- **서브에이전트는 부모의 지시 파일을 상속하지 않는다.** 위임하는 순간 L1이 사라지므로, 서브에이전트에게는 필요한 사실을 프롬프트에 직접 넣는다.
