마켓빅시 기능 확장 기획

기준일: 2026-08-13 문서 상태: 제품 요구사항 초안. 실제 코드 검토 전 공수는 범위 추정.

1. 제품 방향

기존 제품:

여러 플랫폼에서 시장·키워드 기회를 조사한다.

확장 제품:

조사한 기회를 콘텐츠와 상품에 연결하고 실제 판매 결과까지 확인한다.

제품 확장 순서는 다음과 같습니다.

  1. Research: 시장·키워드·채널 조사
  2. Create: 근거 기반 콘텐츠 초안
  3. Activate: 캠페인·채널 배포 준비
  4. Measure: SKU별 유입·구매·환불 측정
  5. Learn: 다음 키워드·콘텐츠·상품 실행 추천

2. MVP 목표와 제외 범위

목표

한 명의 마케터가 다음 흐름을 끝까지 완료할 수 있어야 합니다.

SKU 등록 → 키워드 조사 → 블로그 초안 → 사람 승인 → 추적 링크 생성 → 주문 연결 → 콘텐츠별 매출 확인

이번 MVP에서 제외

  • 숏폼 영상 자동 렌더링
  • 네이버 블로그 무인 대량 게시
  • 모든 쇼핑몰·광고 플랫폼 동시 연동
  • 자체 결제·주문 처리
  • 복잡한 다중 접점 기여도 AI
  • Salesforce와 같은 전체 CRM 구축
  • 브랜드가 작성한 가짜 구매 후기

세일즈포스 측정 시스템이 Salesforce 제품 연동을 뜻한다면 외부 커넥터 단계에서 다룹니다. 일반적인 판매 성과 측정을 뜻한다면 이 문서의 SKU·캠페인·주문 성과판이 해당 요구를 충족합니다.

3. 기능 모듈

A. 브랜드·프로젝트 설정

필수 입력:

  • 브랜드명·회사명
  • 업종·주요 고객
  • 브랜드 문체와 금지 문체
  • 사실로 사용할 수 있는 회사·상품 정보
  • 법적·광고상 금지 표현
  • 기본 CTA와 판매 채널
  • 경쟁 브랜드와 비교 기준

목적은 AI가 없는 사실을 만들어내지 않도록 승인된 지식 경계를 설정하는 것입니다.

B. SKU 상품 허브

SKU 등록 방식:

  • 직접 입력
  • CSV 업로드
  • 향후 스마트스토어·카페24·Shopify 동기화

필수 필드:

필드설명
SKU ID변하지 않는 내부 상품·옵션 식별자
상위 SKU색상·용량 옵션을 묶는 상품군 ID
외부 상품 ID스마트스토어·카페24·Shopify 등 채널 ID
상품명·브랜드·카테고리표시·분석용 기본 정보
옵션색상·용량·사이즈 등
판매가·원가매출과 공헌이익 계산
재고·상태품절 상품 홍보 방지
상세페이지 URL콘텐츠 CTA 목적지
승인 사실성분·규격·배송·보증 등
금지 주장효능 과장·비교 비방 등
타깃·핵심 질문생성 입력과 조사 연결

Google Merchant Center는 상품마다 안정적인 고유 ID를 유지하고 가능하면 SKU를 ID로 사용하도록 권장합니다. 옵션 상품은 상위 그룹 ID와 옵션별 고유 ID를 구분합니다. Google Merchant Center 상품 ID

C. 조사 기반 콘텐츠 브리프

사용자가 조사 결과에서 다음을 선택해 브리프로 저장합니다.

  • 목표 SKU 또는 상품군
  • 퍼널 단계
  • 목표 고객
  • 주 키워드와 보조 질문
  • 플랫폼별 근거와 수집 시점
  • 경쟁 콘텐츠의 빈틈
  • 사용 가능한 공식 출처
  • 글의 목표와 CTA

자동 생성되는 브리프:

  • 고객 문제
  • 검색 의도
  • 콘텐츠 관점
  • 반드시 다룰 질문
  • 피해야 할 주장
  • 제목 후보
  • 구조와 근거 목록

D. 블로그 콘텐츠 스튜디오

생성 흐름:

  1. 브리프·SKU·브랜드 지식 불러오기
  2. 제목 5안과 글 구조 생성
  3. 사용자가 구조 선택·수정
  4. 본문 초안 생성
  5. 문장별 사실·출처·상품 주장 검사
  6. 광고·협찬 표시 필요 여부 확인
  7. 사람이 승인
  8. Markdown·HTML·복사 형식으로 내보내기
  9. 콘텐츠 ID와 추적 링크 발급

산출물:

  • 제목·소제목·본문
  • 메타 설명
  • 이미지 제안과 대체 텍스트
  • CTA 문구
  • 네이버 블로그용 문단 버전
  • 자사몰 SEO용 HTML 버전
  • 숏폼 대본 전환용 요약
  • 출처와 생성·검수 이력

품질 안전장치:

  • 승인된 SKU 사실 외 효능·수치 자동 차단
  • 출처 없는 통계·고객 사례 경고
  • 타 사이트 문구 유사도 경고
  • 동일한 글의 대량 변형 제한
  • 경제적 이해관계 표시 템플릿
  • 의료·건강·식품 등 고위험 업종 별도 검수 플래그
  • 자동 게시 기본값 끔

E. 리뷰·UGC 운영

MVP 이후 기능:

  • 구매 확정·배송 완료 기준 리뷰 요청 작업 생성
  • 리뷰 링크와 QR 생성
  • 긍정·부정 모두 포함한 리뷰 요약
  • 반복 불만·질문·상품 개선점 추출
  • 브랜드 답변 초안
  • UGC 사용 동의 상태
  • 리뷰에서 다음 블로그·FAQ 주제 추천

리뷰 원문, 고객 사진, 연락처에는 최소 권한과 보존기간이 필요합니다. 보상형 후기는 관계 표시를 강제하고 플랫폼 정책에 따라 보상 자체가 금지될 수 있도록 채널별 정책 검사를 둡니다.

F. 캠페인·추적 링크

필수 개념:

  • campaign_id: 캠페인
  • content_id: 글·대본·광고 소재
  • sku_id: 상품·옵션
  • channel: 네이버 블로그·자사몰·인스타그램 등
  • UTM: source·medium·campaign·content·term

사용자는 콘텐츠를 승인할 때 자동으로 추적 링크를 받습니다. 링크 클릭 후 상품 조회·장바구니·구매 이벤트가 들어오면 콘텐츠와 SKU에 연결합니다.

G. SKU·콘텐츠 성과판

첫 화면에서 보여줄 지표:

  • SKU별 콘텐츠 수
  • 콘텐츠 조회와 CTA 클릭
  • 상품 조회·장바구니·결제 시작·구매
  • 전환율
  • 주문 매출·환불 매출·순매출
  • 광고비가 있을 경우 ROAS
  • 원가가 있을 경우 공헌이익·이익 기반 ROAS
  • 신규·반복 구매
  • 콘텐츠별 최초·최종 접점 매출

과도한 정밀도를 주장하지 않습니다. MVP는 최초 접점, 마지막 비직접 접점, 보조 전환을 나란히 보여주고 계산 규칙을 공개합니다.

H. 숏폼 준비 기능

영상 생성 전 단계:

  • 조사 브리프에서 후크 5안
  • 15초·30초 대본
  • 장면·자막·촬영 목록
  • 썸네일 문구
  • 캡션·해시태그
  • 연결 SKU·캠페인 링크
  • 게시 후 수기 또는 API 성과 입력

영상 렌더러는 이 기능의 사용 빈도와 지불의사가 확인된 뒤 개발합니다.

6. 개발 단계와 추정 공수

실제 코드 검토 전 범위 추정이며, 풀스택 개발자 1명과 기획·디자인 지원을 가정합니다.

단계기간 추정결과
0. 기반 점검1~2주코드 구조, 계측, 워크스페이스 경계, 이벤트 규격
1. 수동형 MVP6~8주SKU·브리프·블로그·추적 링크·주문 CSV·성과판
2. 국내 연동6~10주GA4＋스마트스토어 또는 카페24 한 곳
3. 대행사 제품6~12주팀·권한·고객 폴더·리포트 브랜딩
4. 플랫폼화8~12주공개 API·웹훅·추가 커넥터

기존 코드가 개인 계정에 강하게 결합되어 있거나 사용량 차감이 클라이언트에만 있으면 기간이 늘어납니다.

7. MVP 완료 조건

  • 사용자가 SKU를 1개 이상 등록할 수 있음
  • 등록 SKU와 조사 결과로 블로그 브리프를 만들 수 있음
  • 승인된 사실과 출처가 포함된 초안을 생성함
  • 사용자 승인 없이 자동 게시하지 않음
  • 콘텐츠별 추적 링크와 ID를 발급함
  • 주문 CSV를 SKU와 연결함
  • 콘텐츠 조회·클릭·구매·환불을 한 퍼널에서 확인함
  • 같은 주문을 중복 집계하지 않음
  • 고객별 AI·API·저장 비용을 계산할 수 있음

8. 검증 지표

파일럿 3~10곳에서 다음을 봅니다.

  • 조사 완료→브리프 생성률
  • 브리프→초안 생성률
  • 초안→승인·실제 게시율
  • 승인까지 걸린 사람 검수시간
  • 콘텐츠당 AI 원가
  • 게시 콘텐츠당 연결 SKU 비율
  • 콘텐츠→상품 클릭률
  • 클릭→구매율
  • 콘텐츠별 매출 연결률
  • 4주차 반복 사용률

중단 또는 수정 신호:

  • 초안은 만들지만 30% 미만만 실제 게시
  • SKU 등록을 완료하는 고객이 절반 미만
  • 주문 연결을 하지 않아 성과판이 비어 있음
  • 검수시간이 직접 작성시간과 비슷함
  • AI 원가보다 고객지원·수정 공수가 더 큼

9. 과금 축

최종 가격은 원가 측정 후 결정하지만 과금 가능한 단위는 다음과 같습니다.

  • 좌석 수
  • 고객 워크스페이스 수
  • 활성 SKU 수
  • 월 콘텐츠 초안·승인 수
  • 연결 스토어 수
  • 주문·이벤트 처리량
  • 외부 API 호출량
  • 데이터 보존 기간
  • 리포트 브랜딩과 권한

기본 구독에는 예측 가능한 사용량을 포함하고, AI 초안·대용량 이벤트·API는 초과 사용량으로 분리하는 혼합형이 적합합니다.

10. 제품 리스크와 대응

리스크대응
범용 AI 글쓰기와 차별 부족조사 근거·SKU 사실·매출 성과를 묶음
자동 콘텐츠 스팸사람 승인, 대량 생성 제한, 유사도·품질 검사
허위·과장 표현승인 사실·금지 주장·고위험 업종 검수
허위 리뷰리뷰 생성 금지, 실제 구매자 요청·요약만 지원
기여도 과장계산 규칙 공개, 최초·최종·보조 전환 분리
연동 API 변경커넥터 계층 분리, 버전·재시도·동기화 상태 표시
개인정보 과수집SKU·주문 집계 우선, 고객 PII 최소화·분리 저장
너무 넓은 제품 범위블로그＋SKU＋CSV 측정 MVP로 시작

11. 제품 결정

블로그 자동 홍보 글 작성 기능은 진행할 가치가 있습니다. 단 다음 조건을 지킵니다.

  1. 범용 프롬프트 창이 아니라 마켓빅시 조사 결과에서 시작
  2. 모든 콘텐츠를 SKU·캠페인·퍼널 단계에 연결
  3. 사람 검수와 출처·광고 표시를 기본값으로 설정
  4. 자동 게시보다 내보내기와 측정을 우선
  5. 리뷰는 생성하지 않고 실제 구매자 리뷰 운영을 지원
  6. 성과 데이터가 다음 조사와 콘텐츠 추천으로 돌아오게 설계
