연결형 대시보드 관리 규칙

구조

  • 진입점은 dashboard/index.html이다.
  • 상세 화면은 dashboard/pages/str.html, mkt.html, prd.html, sal.html, fin.html, tec.html, rsk.html이다.
  • 모든 화면은 같은 상단 내비와 dashboard/assets/styles.css, app.js를 사용한다.
  • 내비게이션에는 전체 현황과 등록된 7개 역할만 표시한다.
  • 전체 현황은 사업 KPI·실행 단계·역할별 최근 작업과 결과·다음 행동·결정·리스크를 표시한다.
  • 역할 화면은 책임·목표·현재 작업·결과·작업 목록·업데이트 이력·근거 경로를 표시한다.
  • 한 행에는 하나의 상위 섹션만 배치하고, 설명을 줄 수로 잘라 숨기지 않는다.
  • [2026-08-16 정정] 종전 별도 증거 페이지를 만들지 않는다에서 내비를 늘리지 않고 생성형 자료 상세 페이지를 제공한다로 변경한다. 상세 페이지는 dashboard/records/에 만들며 내비 항목으로 추가하지 않는다.
  • 전체 현황과 역할 화면의 전체 자료에서 질문지·설계·과업·예정·결정·결과·이력을 검색한다.
  • 페이지가 독립적인 의사결정 단위로 너무 길어질 때만 dashboard/pages/에 화면을 추가한다.

정본

  • 사업 사실은 Markdown에서만 바꾼다.
  • HTML은 읽기 전용 생성물이며 직접 편집하지 않는다.
  • 각 페이지에 정본 경로·생성 시각·소스 해시를 표시한다.
  • 과거 결정을 삭제하지 않고 대체됨과 대체 ID를 남긴다.
  • 현재 상태는 state.md·output.md, 과업은 inbox.md, 날짜별 업무 결과는 updates.md를 사용한다.
  • 통합 레코드와 확장자 책임은 system/data/RECORD_SCHEMA.md를 따른다.
  • 측정하지 않은 사업 지표를 0이나 추정값으로 표시하지 않는다.

토큰 절약 로딩

  1. system/dashboard/SECTION_REGISTRY.md에서 요청과 맞는 화면을 찾는다.
  2. 해당 행의 먼저 읽을 정본 하나만 먼저 읽는다.
  3. 역할 결론이 필요하면 그 persona의 output.md를 읽는다.
  4. 근거나 충돌이 있을 때만 state.md, research.md, reference/를 추가한다.
  5. 생성된 HTML 전체를 AI 작업 컨텍스트로 읽지 않는다.
