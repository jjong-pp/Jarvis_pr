# 마켓빅시 운영·대시보드 갱신 규약

## 1. 정본 원칙

- Markdown만 사업 내용의 편집 정본입니다.
- `dashboard/` 아래 HTML과 `dashboard.html`은 읽기 전용 생성물입니다.
- HTML과 Markdown이 다르면 Markdown이 맞습니다.
- 같은 사실은 하나의 상세 정본에만 기록합니다.
- 쉬운 현황 화면의 단계·행동·완료 기준은 `15_execution_control.md`에서 관리합니다.

## 2. 사람이 보는 화면

| 화면 | 목적 |
|---|---|
| `dashboard/index.html` | 현재 단계·이번 주 행동·사용자 결정 |
| `dashboard/stages.html` | 0~6단계 목표·할 일·완료 기준·중단 조건 |
| `dashboard/growth.html` | 네이버·Google·Meta·TikTok 순서와 개인→B2B 흐름 |
| `dashboard/partnership.html` | 15% 제안·90일 시험·조건 승급·협상 문장 |
| `dashboard/roles.html` | 7개 페르소나의 현재 판단과 차단 요인 |
| `dashboard/evidence.html` | 전체 표·가설·결정·문서·상세 근거 |

루트 `dashboard.html`은 쉬운 홈으로 이동시키는 호환용 진입 파일입니다.

## 3. 쉬운 표현 순서

현황을 설명할 때 다음 순서를 지킵니다.

1. 지금 단계
2. 이번 주 할 일
3. 끝났다고 보는 기준
4. 멈추거나 고칠 조건
5. 사용자가 내려야 할 결정
6. 필요한 경우에만 전문 용어와 상세 근거

기간이 지났다는 이유로 다음 단계로 이동하지 않습니다. 완료 기준을 통과해야 합니다.

## 4. 새 세션 로딩

총괄 작업:

1. `README.md`
2. `00_project_status.md`
3. 단계·광고·협업 질문이면 `15_execution_control.md`
4. `personas/registry.md`
5. 관련 역할의 `output.md`
6. 충돌과 근거 확인이 필요할 때만 `state.md`, `research.md`, 상세 문서

개별 역할 작업:

1. `personas/START_HERE.md`
2. 자신의 `inbox.md`, `state.md`, `output.md`
3. 직접 관련된 루트 문서 1~2개
4. 필요한 `research.md` 범위

AI는 생성된 HTML이나 전체 Markdown을 기본 컨텍스트로 읽지 않습니다.

## 5. 페르소나 작업

- 주 담당 하나와 필요한 검토 역할을 정합니다.
- `inbox → research → state → output` 순서를 사용합니다.
- 사실·가설·제안·사용자 결정을 구분합니다.
- 역할 간 충돌은 `08_decision_log.md`의 결정 요청으로 올립니다.
- 전사 현재판 변화는 `00`, 쉬운 실행 순서 변화는 `15`, 결정은 `08`, 검증 증거는 `09`를 갱신합니다.

## 6. 사용자 피드백 반영

1. 사용자는 관련 대시보드 페이지에서 상태를 확인합니다.
2. 입력을 사실·가설·결정·행동·아이디어로 분류합니다.
3. 담당 페르소나 파일을 갱신합니다.
4. 전사 상태가 바뀌면 루트 정본과 `15_execution_control.md`를 갱신합니다.
5. 대시보드를 재생성합니다.
6. 페이지 수·카드 수·링크·템플릿·JavaScript·소스 해시를 검증합니다.

## 7. 대시보드 생성

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-dashboard.ps1
```

빌드 순서:

1. 루트 현황·결정·가설의 상세 대시보드를 생성합니다.
2. 7개 페르소나의 `state.md`, `output.md`를 취합합니다.
3. 긴 상세판을 `dashboard/evidence.html`로 보존합니다.
4. `15_execution_control.md`로 홈·단계·광고·협업 페이지를 생성합니다.
5. 페르소나 등록부로 역할별 페이지를 생성합니다.
6. 루트 `dashboard.html`을 쉬운 홈 진입점으로 생성합니다.

## 8. 상태와 증거

쉬운 화면 상태:

- `진행`: 지금 실제로 수행 중
- `입력 대기`: 자료나 상대 답변이 필요
- `미시작`: 해야 하지만 아직 시작하지 않음
- `대기`: 앞 단계가 끝나야 시작
- `협상 대기`: 조건을 문서로 정해야 함
- `준비 전`: 측정·소재가 없어 실행하면 안 됨
- `완료`: 사전에 정한 완료 기준을 충족

증거 강도는 결제·반복 사용, 실측 시간·원가, 고객 행동, 공식 자료, 인터뷰 의견, 내부 아이디어 순서로 봅니다.

## 9. 품질 점검

- 6개 HTML 화면이 모두 존재하는가
- 단계 7개, 광고 채널 4개, 협업 구간 3개, 페르소나 7개가 출력되는가
- 내부 링크가 실제 파일로 연결되는가
- `미측정`을 0으로 바꾸지 않았는가
- 가설을 확정으로 표현하지 않았는가
- HTML에만 있는 사업 사실이 없는가
- 미치환 `{{...}}`와 JavaScript 구문 오류가 없는가
- 생성 해시에 모든 Markdown이 포함되는가

## 10. 보존

- 과거 결정과 근거를 삭제하지 않습니다.
- 대체된 전략에는 대체 날짜와 이유를 남깁니다.
- 기존의 긴 대시보드는 상세 근거 페이지로 보존합니다.
- 페이지를 나누더라도 각 사실의 정본 위치는 바꾸지 않습니다.
