# BIGSEE 로컬 작업 규칙

이 파일은 `C:\MyMain\market-bigsee`와 모든 하위 디렉터리에 적용됩니다.

## 세션 시작

1. `README.md`로 문서 지도를 확인한다.
2. `00_project_status.md`로 전체 사업 상태를 확인한다.
3. 현재 단계·이번 주 행동·광고·협업 조건 질문이면 `15_execution_control.md`를 읽는다.
4. `personas/registry.md`에서 주 담당을 정한다.
5. 담당 역할의 `inbox.md`, `state.md`, `output.md`와 직접 필요한 상세 문서만 읽는다.

전체 Markdown이나 생성 HTML을 한꺼번에 읽지 않는다.

## 정본과 화면

- Markdown만 편집 정본이다.
- `dashboard/` 아래 HTML과 진입용 `dashboard.html`은 생성물이며 직접 수정하지 않는다.
- 사람이 보는 기본 화면은 `dashboard/index.html`이다.
- 긴 표와 전체 근거는 `dashboard/evidence.html`에만 둔다.
- `15_execution_control.md`는 쉬운 실행 순서의 정본이다.
- 루트 전사 현황은 `00`, 결정은 `08`, 가설·증거는 `09`가 정본이다.
- 역할별 최신 상태와 결과는 각 `state.md`, `output.md`가 정본이다.
- 같은 사실을 여러 정본에 복제하지 않고 링크와 현재 결론만 사용한다.

## 쉬운 현황 표현 규칙

- 먼저 `지금 상태`, `이번 주 할 일`, `완료 기준`, `멈출 조건`, `사용자 결정`을 말한다.
- CAC·PLS·PQL 같은 용어는 필요한 경우에만 쓰고 바로 쉬운 뜻을 붙인다.
- 기간이 지났다는 이유로 단계를 완료 처리하지 않는다.
- 미측정은 0으로 바꾸지 않는다.
- 광고 클릭·가입보다 첫 가치·결제·4주 반복 사용·팀 전환을 우선한다.

## 페르소나 하네스

- 복합 과업은 주 담당 하나와 필요한 검토 역할을 정한다.
- 작업은 `inbox → research → state → output` 순서를 따른다.
- 사실·가설·제안·사용자 결정을 구분한다.
- 역할 간 충돌은 임의로 합치지 않고 결정 요청으로 올린다.
- 역할은 순차 실행이 기본이며 상위 지침이 허용할 때만 병렬화한다.

상세 계약은 `12_persona_harness.md`를 따른다.

## 대시보드 반영

Markdown 변경 후 다음 명령을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-dashboard.ps1
```

빌드는 다음 순서로 동작한다.

1. 전체 표 기반 상세 대시보드를 만든다.
2. 페르소나 `state.md`, `output.md`를 취합한다.
3. 상세판을 `dashboard/evidence.html`로 보존한다.
4. `15_execution_control.md`에서 홈·단계·광고·협업 페이지를 만든다.
5. 역할별 현황 페이지와 루트 진입 경로를 만든다.

생성 후 다음을 확인한다.

- 홈, 단계, 광고, 협업, 역할, 상세 근거 6개 HTML 존재
- 7단계, 광고 채널 4개, 협업 구간 3개, 페르소나 7개 출력
- 모든 내부 페이지 링크 정상
- 미치환 템플릿과 JavaScript 구문 오류 없음
- 소스 해시에 모든 Markdown 포함
- HTML에만 존재하는 새로운 사업 사실 없음

## 사용자 피드백

1. 입력을 사실·가설·결정·행동·아이디어로 분류한다.
2. 담당 페르소나의 작업 파일을 갱신한다.
3. 전사 상태가 바뀌면 루트 정본과 `15_execution_control.md`를 갱신한다.
4. 페이지를 다시 만들고 검증한다.

## 보존 원칙

- 과거 결정과 근거를 삭제하지 않는다.
- 코드·원가·계약을 확인하지 않은 추정을 확정하지 않는다.
- 외부 최신 정보는 다시 확인하고 출처와 확인일을 남긴다.
- 협업 조건이 합의되기 전 세부 캠페인 자산과 전체 실행 자료를 무조건 이전하지 않는다.
