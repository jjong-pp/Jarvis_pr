# BIGSEE 로컬 작업 규칙

이 파일은 `C:\MyMain\market-bigsee`와 하위 디렉터리의 모든 작업에 적용됩니다.

## 세션 시작

1. `README.md`로 문서 지도를 확인한다.
2. `00_project_status.md`로 최신 사업 상태를 확인한다.
3. `12_persona_harness.md`와 `personas/registry.md`로 담당 페르소나를 정한다.
4. 담당 페르소나의 `inbox.md`, `state.md`, `output.md`를 읽는다.
5. 질문에 직접 필요한 루트 상세 문서 1~2개만 추가로 읽는다.

전체 Markdown이나 `dashboard.html`을 기본 컨텍스트로 한꺼번에 읽지 않는다.

## 정본과 생성물

- Markdown이 유일한 편집 정본이다.
- `dashboard.html`은 생성물이며 직접 수정하지 않는다.
- 루트 전사 현황은 `00_project_status.md`, 결정은 `08_decision_log.md`, 가설·증거는 `09_validation_board.md`가 정본이다.
- 역할별 최신 작업 상태와 결과는 `personas/<role>/state.md`, `output.md`가 정본이다.
- 같은 사실을 여러 문서에 독립적으로 복제하지 않는다. 역할 출력에서 전사 결론으로 승격할 때 루트 정본을 갱신하고 링크만 남긴다.

## 페르소나 하네스

- 모든 복합 과업은 주 담당 페르소나 하나와 필요한 검토 역할을 정한다.
- 작업 흐름은 `inbox.md → research.md → state.md → output.md`를 따른다.
- `research.md`에는 출처·확인일·관찰·추론을 구분해 누적한다.
- `state.md`의 `## Harness State` 표와 `output.md`의 `## Dashboard Output` 표 제목·필드는 바꾸지 않는다.
- 역할 간 충돌은 임의로 합치지 말고 양쪽 출력에 표시한 뒤 `08_decision_log.md`에 결정 요청을 남긴다.
- 사실·가설·제안·사용자 결정은 명시적으로 구분한다.
- 역할은 순차 실행이 기본이며, 사용자나 상위 지침이 병렬 역할 작업을 허용할 때만 독립 실행을 병렬화한다.

상세 계약은 `12_persona_harness.md`를 따른다.

## 대시보드 반영

관련 Markdown을 갱신한 뒤 반드시 다음을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-dashboard.ps1
```

빌드는 루트 정본과 등록된 모든 페르소나의 `state.md`, `output.md`를 취합한다. 생성 후 다음을 확인한다.

- 필수 페르소나 파일 누락 없음
- 미치환 `{{PLACEHOLDER}}` 없음
- JavaScript 구문 오류 없음
- 생성 해시에 `personas/` 아래 Markdown 포함
- HTML에만 존재하는 사업 결론 없음

## 사용자 피드백 처리

사용자가 대시보드를 보고 내용을 주면 다음 순서로 처리한다.

1. 입력을 사실·가설·결정·행동·아이디어로 분류한다.
2. `personas/registry.md`로 주 담당을 선택한다.
3. 담당 `inbox.md`에 과업을 등록하고 탐색·상태·출력을 갱신한다.
4. 전사 상태가 바뀐 경우에만 루트 정본에 승격한다.
5. 대시보드를 재생성하고 결과를 검증한다.

## 보존 원칙

- 과거 결정과 근거를 삭제하지 않는다. 대체 상태와 새 근거를 남긴다.
- `미측정`을 숫자 0으로 바꾸지 않는다.
- 코드·인프라·원가를 확인하지 않은 추정을 확정 사실로 쓰지 않는다.
- 외부 최신 정보는 다시 확인하고 출처와 확인일을 남긴다.
