# 마켓빅시 사업 운영·대시보드 갱신 규약

## 1. 정본 원칙

- Markdown만 편집 가능한 정본입니다.
- `dashboard.html`은 생성한 읽기 전용 파생물이며 직접 수정하지 않습니다.
- HTML과 Markdown이 다르면 Markdown이 맞습니다.
- 같은 사실은 한 상세 정본에만 적고 요약 문서는 링크와 현재 결론만 둡니다.
- 역할별 출력은 전사 결정이 아니며 승격 규칙을 통과해야 루트 정본이 됩니다.

## 2. 문서 계층

| 계층 | 정본 | 용도 |
|---|---|---|
| 프로젝트 지도 | `README.md`, `AGENTS.md` | 새 환경 진입과 자동 작업 규칙 |
| 전사 현재판 | `00_project_status.md` | 단계·지표·위험·다음 행동 |
| 사업 상세 | `01~07` | 서비스·판매·시장·제품·기술·경쟁 근거 |
| 거버넌스 | `08`, `09` | 결정 이력과 검증 증거 |
| 운영 계약 | `10`, `11`, `12` | SSOT·토큰·페르소나 하네스 규칙 |
| 역할 작업 | `personas/<role>/` | 입력·탐색·상태·출력 |
| 사람용 화면 | `dashboard.html` | 모든 최신 출력의 탐색·피드백 화면 |

## 3. 세션 로딩 규칙

총괄 세션:

1. `README.md`
2. `00_project_status.md`
3. `personas/registry.md`
4. 관련 역할의 `output.md`
5. 충돌·근거 확인이 필요할 때만 `state.md`, `research.md`, 상세 루트 문서

역할 세션:

1. `personas/START_HERE.md`
2. 자신의 `inbox.md`, `state.md`, `output.md`
3. 직접 관련된 루트 문서 1~2개
4. 필요한 `research.md` 범위

금지:

- 매번 모든 Markdown 읽기
- AI가 대시보드와 원본을 함께 읽기
- 동일한 결론을 여러 역할 폴더에 독립 정본으로 복제
- 아이디어를 곧바로 사실이나 확정 결정으로 기록
- 과거 결정·근거 삭제

## 4. 페르소나 작업

상세 계약은 `12_persona_harness.md`를 따릅니다.

1. 등록부에서 주 담당 하나와 검토 역할을 정합니다.
2. 주 담당 `inbox.md`에 ID·입력·산출물·완료 기준을 등록합니다.
3. 출처·확인일·관찰·추론을 `research.md`에 기록합니다.
4. 현재 과업·차단·다음 행동을 `state.md`에 유지합니다.
5. 결론·근거·한계·제안·결정 요청·다음 전달을 `output.md`에 합성합니다.
6. 역할 간 충돌은 숨기지 않고 `08_decision_log.md`의 결정 요청으로 올립니다.
7. 필요한 결론만 루트 정본으로 승격합니다.

## 5. 사용자 피드백 반영

1. 대시보드 입력을 사실·가설·결정·실행·아이디어로 분류합니다.
2. 페르소나 등록부로 주 담당을 선택합니다.
3. 역할 폴더에서 탐색과 출력을 갱신합니다.
4. 현재 상태 변화는 `00`, 결정은 `08`, 실험·고객 증거는 `09`에 반영합니다.
5. 관련 상세 설명은 `01~07`의 한 정본에만 둡니다.
6. 대시보드를 재생성하고 검증합니다.

## 6. 상태와 증거

상태는 `확정`, `진행`, `기획`, `미검증`, `미측정`, `주의`, `입력 대기`, `대기`, `보류`, `완료`, `대체됨`을 사용합니다.

증거 강도는 다음 순서입니다.

1. 실제 결제·구매·반복 사용
2. 관찰된 작업 시간·제품 이벤트·운영 원가
3. 고객의 구체적 요청과 파일럿 행동
4. 공식 통계·공식 API·공시
5. 인터뷰 의견
6. 내부 추정·아이디어

## 7. 갱신 주기

- 즉시: 결제·가격·제품 결정·중요 리스크
- 매주: 현황·다음 행동·지표·역할별 과업·실험
- 매월: 전략·가격·경쟁·원가·유지율 종합 검토
- 중요한 투자 전: 경쟁사 가격·법·API 정책 최신성 재확인
- `00_project_status.md`가 14일 넘게 갱신되지 않으면 오래된 상태로 표시

## 8. 대시보드 생성

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-dashboard.ps1
```

빌드 단계:

1. `build-dashboard-core.ps1`이 루트 사업 현황을 생성합니다.
2. `build-persona-dashboard.ps1`이 등록부와 각 역할의 필수 파일을 검증합니다.
3. 각 `state.md`, `output.md`를 페르소나 탭에 취합합니다.
4. 루트와 `personas/` 아래 모든 Markdown으로 전체 소스 해시를 계산합니다.

## 9. 품질 점검

- 등록된 모든 역할에 `inbox`, `state`, `research`, `output`이 있는지 확인
- 표준 표 제목과 필드가 유지되는지 확인
- 대시보드 생성 시각과 소스 해시가 최근인지 확인
- `미측정`을 0으로 표시하지 않았는지 확인
- 가설을 확정으로 표현하지 않았는지 확인
- HTML에만 존재하는 사업 사실이 없는지 확인
- 미치환 `{{...}}`, JavaScript 구문 오류, diff 공백 오류가 없는지 확인

## 10. 페르소나 완료 정의

1. 질문과 완료 기준에 답했습니다.
2. 가장 강한 증거와 가장 큰 한계를 함께 제시했습니다.
3. 현재 상태·차단·다음 행동이 최신입니다.
4. 의사결정 요청과 후속 담당이 명확합니다.
5. 루트 정본 승격 또는 역할 인계가 끝났습니다.
6. 대시보드 빌드와 검증을 통과했습니다.
