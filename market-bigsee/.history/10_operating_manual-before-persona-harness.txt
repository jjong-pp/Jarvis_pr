# 마켓빅시 사업 운영·대시보드 갱신 규약

## 1. 정본 원칙

- Markdown만 편집 가능한 정본입니다.
- `dashboard.html`은 Markdown에서 생성한 읽기 전용 파생물입니다.
- HTML과 Markdown이 다르면 Markdown이 맞습니다.
- HTML을 직접 수정하지 않습니다. MD 수정 후 생성 스크립트를 실행합니다.
- 같은 사실은 한 상세 문서에만 적고 `00_project_status.md`에는 현재 결론과 링크만 둡니다.

## 2. 문서 역할

| 문서 | 역할 | 읽는 시점 |
|---|---|---|
| README.md | 문서 지도와 시작 방법 | 새 환경 첫 진입 |
| 00_project_status.md | 현재 단계·상태·지표·위험·다음 행동 | 모든 새 작업 시작 |
| 01~07 문서 | 서비스·판매·시장·제품·기술·경쟁 근거 | 관련 질문이 있을 때만 |
| 08_decision_log.md | 왜 그 결정을 했는지와 대체 이력 | 방향 변경·충돌 확인 시 |
| 09_validation_board.md | 가설·시험·증거·통과 기준 | 고객·시장·MVP 검증 시 |
| 10_operating_manual.md | 갱신과 토큰 사용 규칙 | 운영 방법이 불명확할 때 |
| 11_operating_system_research.md | 이 방식의 전문 근거와 평가 | 운영 체계 재설계 시 |
| dashboard.html | 사람이 보는 현재 상태 | 사용자 피드백 전 |

## 3. 사용자 피드백 반영 절차

1. 사용자는 `dashboard.html`을 보고 사실 변경, 의견, 아이디어, 우선순위를 말합니다.
2. 작업자는 입력을 `확정 사실`, `가설`, `결정`, `실행 항목`, `아이디어`로 분류합니다.
3. 상세 내용은 해당 01~07 문서 한 곳에 반영합니다.
4. 현재 상태가 바뀌면 `00_project_status.md`의 해당 행만 갱신합니다.
5. 방향 결정은 `08_decision_log.md`에 추가합니다.
6. 실험·고객 증거는 `09_validation_board.md`에 추가합니다.
7. `scripts/build-dashboard.ps1`을 실행합니다.
8. 생성 시각·소스 해시·문서 링크와 `git diff --check`를 확인합니다.

## 4. 토큰 절약 로딩 규칙

새 세션의 기본 로딩 순서:

1. `README.md`
2. `00_project_status.md`
3. 사용자의 질문과 직접 관련된 상세 문서 1~2개
4. 방향 충돌이 있을 때만 결정 기록
5. 검증 수치가 필요할 때만 검증 대장

금지:

- 매번 모든 Markdown을 읽기
- AI가 `dashboard.html`과 원본 MD를 함께 읽기
- 동일한 전략 설명을 여러 문서에 복사
- 사용자 아이디어를 곧바로 확정 사실로 기록
- 과거 결정을 삭제하고 현재 결정만 남기기

HTML은 사람의 인지 비용을 줄이기 위한 화면입니다. AI의 토큰은 짧은 현황 MD와 선택적 상세 문서 로딩으로 줄입니다.

## 5. 상태와 증거 표준

상태:

- `확정`: 사용자 승인 또는 강한 증거로 현재 방향으로 채택
- `진행`: 실행 또는 조사가 진행 중
- `기획`: 범위는 정의됐지만 구현·검증 전
- `미검증`: 주장은 있으나 고객 행동 증거 없음
- `미측정`: 지표 정의는 있으나 수치 없음
- `주의`: 법·비용·신뢰 등 선행 통제가 필요
- `대기`: 선행 단계 완료 후 시작
- `보류`: 현재 범위에서 의도적으로 제외
- `완료`: 완료 기준을 충족하고 검증됨
- `대체됨`: 새 결정이 이전 결정을 교체

증거 강도:

1. 실제 결제·구매·반복 사용
2. 관찰된 작업 시간·제품 이벤트·운영 원가
3. 고객의 구체적 요청과 파일럿 행동
4. 공식 통계·공식 API·공시
5. 인터뷰 의견
6. 내부 추정·아이디어

## 6. 갱신 주기

- 사건 발생 즉시: 고객 결제, 가격 변경, 제품 결정, 중요 리스크
- 매주: 현황·다음 행동·지표·실험 상태
- 매월: 전략·가격·경쟁·원가·유지율 종합 검토
- 중요한 투자 전: 경쟁사 가격·법·API 정책의 최신성 재확인
- 14일 이상 현황 정본이 갱신되지 않으면 대시보드에서 오래된 상태로 취급

## 7. 대시보드 생성

PowerShell에서 프로젝트 폴더를 기준으로 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-dashboard.ps1
```

출력:

- `dashboard.html`

대시보드는 다음 정본을 읽습니다.

- `00_project_status.md`
- `08_decision_log.md`
- `09_validation_board.md`
- 현재 폴더의 Markdown 문서 목록

## 8. 품질 점검

- 대시보드 생성 시각이 최근인지 확인
- 대시보드 소스 해시가 생성 결과에 표시되는지 확인
- 정본 링크가 모두 열리는지 확인
- `미측정`을 0으로 표시하지 않았는지 확인
- 가설을 확정으로 표현하지 않았는지 확인
- 완료 기준 없는 `완료` 상태가 없는지 확인
- HTML에만 존재하는 사업 사실이 없는지 확인
