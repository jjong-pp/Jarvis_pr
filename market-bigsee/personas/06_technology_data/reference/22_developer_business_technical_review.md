# BIGSEE 개발자 사업·기술 점검 질문지

기준일: 2026-08-15  
상태: 발송 전 초안  
목적: 기능 요청을 늘리기 전에 현재 제품·사용자·비용·운영 한계와 30일 개발 우선순위를 증거로 합의한다.

## 개발자에게 먼저 보낼 배경

```text
BIGSEE의 판매·마케팅을 시작하기 전에 현재 제품이 누구에게 어떤 결과를 안정적으로 제공할 수 있는지 확인하려 합니다.
이번 회의는 코드 평가나 기능 목록 회의가 아니라, 고객에게 약속할 범위·사용자당 원가·계측·30일 우선순위를 합의하는 사업회의입니다.
확인되지 않은 값은 추정하지 않고 미확인으로 두겠습니다. 가능하면 답변과 함께 화면·로그·청구서·코드 위치 등 근거를 부탁드립니다.
```

## 회의 전에 요청할 자료

비밀번호·API 키·개인정보 원문은 받지 않는다. 아래는 읽기 전용 또는 비식별 자료로 요청한다.

1. 서비스 소스 저장소와 최근 배포·릴리스 이력의 읽기 권한
2. 운영·개발 환경, 호스팅, DB, 스토리지, 인증, 결제, 외부 API 목록
3. 공급자별 최근 청구 내역과 무료 구간·쿼터·초과 단가
4. 사용자 약 20명의 테스트·관리자·실사용·유료 여부를 구분한 비식별 목록
5. 최근 28일 로그인·첫 리포트·반복 리포트·결제·환불·오류 이벤트 집계
6. 주요 데이터 객체와 사용자·조직·프로젝트 소유 관계를 보여주는 스키마 또는 설명
7. 현재 백로그, 알려진 장애·기술부채, 다음 30일에 개발자가 잡아둔 일정

## 필수 질문 15개

### 고객과 판매 가능 범위

1. 처음 제품을 만들 때 떠올린 가장 구체적인 사용자는 누구였고, 어떤 업무 순간에 BIGSEE를 켠다고 보았는가?
2. 현재 사용자가 가입해서 첫 유용한 리포트를 얻을 때까지 실제 화면과 처리 순서는 무엇인가?
3. 약 20명 중 실제 사람·테스트·관리자·최근 28일 핵심 행동·반복·유료 사용자는 각각 몇 명인가?
4. 지금 돈을 받고 약속할 수 있는 결과와 아직 약속하면 안 되는 기능·품질·지원 범위는 무엇인가?

### 코드·데이터·원가

5. 소스 저장소, 배포 환경, 도메인, DB, 스토리지, 인증, 결제와 외부 API의 실제 구성은 무엇인가?
6. user·workspace·project·report 데이터 소유와 접근 권한은 어디에서 어떻게 검사하는가?
7. 기능 호출을 서버에서 요금제·권한·잔여 사용량으로 차단할 수 있는가? 중복 차감과 동시 호출은 어떻게 막는가?
8. 외부 API·AI 호출마다 user/workspace/job/provider/request/token/success/failure/retry/latency/cost를 기록할 수 있는가?
9. 현재 월 고정비와 공급자별 변동비·무료 구간·쿼터·초과 단가·결제 수수료는 무엇인가?
10. 사용자 1명의 월 직접원가를 계산하려면 현재 로그에서 무엇을 바로 얻을 수 있고 무엇을 새로 계측해야 하는가?
11. 동시 작업·대량 CSV·외부 API 속도 제한·Functions·DB 중 현재 첫 병목은 어디이며, 1,000 활성 사용자를 가정하면 어떤 값부터 검증해야 하는가?

### 운영·개발 이력

12. 실패 재시도·타임아웃·알림·로그 보존·백업·복구·개인정보 삭제·감사 기록은 각각 어느 수준인가?
13. 요구사항, 기능 추가, 버그, 배포, 롤백, 기술부채 이력은 지금 어디에 기록하며 우선순위는 누가 어떻게 결정하는가?
14. 워크스페이스·SKU·UTM·경량 CRM·UsageLedger 중 30일 안에 매출과 반복 사용을 가장 크게 막는 1~2개는 무엇이며, 코드 근거와 예상 공수는 무엇인가?
15. 운영자가 볼 수 있는 읽기 전용 사용자·결제·원가·오류 현황과 주 1회 제품 우선순위 회의는 어느 범위까지 가능한가?

## 답변 기록 형식

| ID | 답변 | 근거 위치·화면 | 확인일 | 후속 담당 | 결정 영향 |
|---|---|---|---|---|---|
| DEV-01~15 | 미확인 | 미확인 | 2026-08-15 이후 | 미정 | 가격·광고·P0·계약 |

답변이 없는 항목은 0이나 불가가 아니라 `미확인`으로 남긴다. 비용·사용자 수·공수는 기준 기간과 출처를 함께 적는다.

## 90분 회의안

| 시간 | 안건 | 종료 조건 |
|---:|---|---|
| 0~15분 | 원래 고객·현재 사용자·판매 가능 범위 | 지금 팔 수 있는 결과와 금지 약속 구분 |
| 15~45분 | 시스템·계측·원가·병목 | 자료 위치와 추가 계측 담당 확정 |
| 45~65분 | 장애·보안·백업·고객 대응 | 장애·환불·삭제 요청 책임자 확정 |
| 65~80분 | 30일 개발 우선순위 | P0 1~2개와 완료 증거 합의 |
| 80~90분 | 정보권·회의·변경 통제 | 읽기 권한과 주간 의사결정 방식 합의 |

## 받아야 할 산출물

1. 현재 시스템·공급자 구성 1장
2. 사용자·활성·결제·환불·원가의 확인값과 미확인값 표
3. 이벤트·UsageLedger 추가 목록과 담당·일정
4. 고객에게 약속 가능한 범위와 알려진 제한
5. 30일 P0 1~2개, 완료 조건, 예상 공수, 차단 요인
6. 사용자·결제·비용·오류에 대한 운영자 읽기 권한과 주간 회의 방식

## 발송 문안

```text
90분 동안 BIGSEE의 현재 사용자·판매 가능 범위·원가·계측·30일 개발 우선순위를 맞추고 싶습니다.
기능을 많이 요청하려는 회의가 아니라, 지금 팔아도 되는 결과와 먼저 계측하거나 보완할 1~2개를 합의하는 회의입니다.

가능하면 회의 전에 비식별 사용자 집계, 최근 28일 핵심 이벤트, 공급자별 청구·쿼터, 현재 백로그와 배포 이력을 공유해 주세요. 비밀번호·API 키·개인정보 원문은 제외해 주세요.
회의 결과는 시스템 구성 1장, 확인값/미확인값 표, 30일 P0 1장, 역할·정보권 1장으로 남기겠습니다.
```
