# 연결형 대시보드 관리 규칙

## 구조

- 진입점은 `dashboard/index.html`이다.
- 상세 화면은 `dashboard/pages/str.html`, `mkt.html`, `prd.html`, `sal.html`, `fin.html`, `tec.html`, `rsk.html`이다.
- 모든 화면은 같은 상단 내비와 `dashboard/assets/styles.css`, `app.js`를 사용한다.
- 내비게이션에는 전체 현황과 등록된 7개 역할만 표시한다.
- 전체 현황은 사업 KPI·실행 단계·역할별 최근 작업과 결과·다음 행동·결정·리스크를 표시한다.
- 역할 화면은 책임·목표·현재 작업·결과·작업 목록·업데이트 이력·근거 경로를 표시한다.
- 한 행에는 하나의 상위 섹션만 배치하고, 설명을 줄 수로 잘라 숨기지 않는다.
- [2026-08-16 정정] 종전 `별도 증거 페이지를 만들지 않는다`에서 `내비를 늘리지 않고 생성형 자료 상세 페이지를 제공한다`로 변경한다. 상세 페이지는 `dashboard/records/`에 만들며 내비 항목으로 추가하지 않는다.
- 전체 현황과 역할 화면의 `전체 자료`에서 질문지·설계·과업·예정·결정·결과·이력을 검색한다.
- 페이지가 독립적인 의사결정 단위로 너무 길어질 때만 `dashboard/pages/`에 화면을 추가한다.

## 정본

- 사업 사실은 Markdown에서만 바꾼다.
- HTML은 읽기 전용 생성물이며 직접 편집하지 않는다.
- 각 페이지에 정본 경로·생성 시각·소스 해시를 표시한다.
- 과거 결정을 삭제하지 않고 `대체됨`과 대체 ID를 남긴다.
- 현재 상태는 `state.md`·`output.md`, 과업은 `inbox.md`, 날짜별 업무 결과는 `updates.md`를 사용한다.
- 통합 레코드와 확장자 책임은 `system/data/RECORD_SCHEMA.md`를 따른다.
- 측정하지 않은 사업 지표를 0이나 추정값으로 표시하지 않는다.

## 토큰 절약 로딩

1. `system/dashboard/SECTION_REGISTRY.md`에서 요청과 맞는 화면을 찾는다.
2. 해당 행의 `먼저 읽을 정본` 하나만 먼저 읽는다.
3. 역할 결론이 필요하면 그 persona의 `output.md`를 읽는다.
4. 근거나 충돌이 있을 때만 `state.md`, `research.md`, `reference/`를 추가한다.
5. 생성된 HTML 전체를 AI 작업 컨텍스트로 읽지 않는다.

## 생성 코드

| 경로 | 역할 |
|---|---|
| `scripts/build-dashboard.ps1` | 생성 진입점 |
| `scripts/dashboard/build-data-catalog.ps1` | MD 문서·표를 통합 레코드와 상세 화면으로 변환 |
| `scripts/dashboard/build-linked-dashboard.ps1` | MD 로딩·HTML 페이지·내비·검증 생성 |
| `dashboard/data/catalog.js` | 서버 없이 읽는 검색 카탈로그 생성물 |
| `dashboard/data/manifest.json` | 원본·레코드·유형·역할 집계 생성물 |
| `dashboard/records/` | 레코드별 정적 상세 화면 생성물 |
| `dashboard/assets/styles.css` | 공통 스타일 |
| `dashboard/assets/app.js` | 내비·자료 검색·필터·더 보기 동작 |

과거 단일·주제별 HTML을 직접 수정하던 스크립트는 재사용하지 않는다.

## 완료 조건

- 진입 페이지와 역할 상세 7페이지가 존재한다.
- 모든 페이지에서 전체 현황과 7개 역할 내비 링크가 정상 상대경로를 사용한다.
- 사업 정본에만 있는 최신 핵심 결론이 화면에 반영된다.
- 전체 화면에 현재값·목표·측정 조건이 있는 사업 KPI가 표시된다.
- 역할 화면에 현재 작업·현재 판단·다음 행동·과업·업데이트 이력이 표시된다.
- 상위 섹션은 단일 열이며 데스크톱에서도 서로 옆에 배치되지 않는다.
- 문장과 표 셀은 줄 수 제한으로 숨기지 않는다.
- 질문지·설계·과업·예정·결정·결과·이력을 검색할 수 있다.
- 모든 카탈로그 레코드에 상세 화면과 Markdown 원본 경로가 있다.
- 내부 파일 링크와 외부 출처 링크가 유효한 형식이다.
- 공통 JavaScript의 구문 오류가 없다.
- 모든 페이지에 정본 경로·생성 시각·소스 해시가 있다.
- 320 CSS 픽셀에서 표를 제외한 본문이 가로로 넘치지 않는다.
