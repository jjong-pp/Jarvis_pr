## 2. 최우선 회귀 테스트

### BR-04 연락처 입력 단일화

- [ ] PC 주문서에서 연락처가 한 번만 입력되는지 확인한다.
- [ ] 모바일 주문서에서 전화번호 입력란이 중복 노출되지 않는지 확인한다.
- [ ] 주문 완료 후 주문자·수취인 연락처가 관리자 주문정보에 정상 저장되는지 확인한다.

### BR-05~06 결제방식 혼합 차단

- [ ] 포인트 상품 장바구니에 입금 상품을 추가하면 차단되는지 확인한다.
- [ ] 입금 상품 장바구니에 포인트 상품을 추가하면 차단되는지 확인한다.
- [ ] 이미 혼합된 장바구니가 있다면 결제 진입 시 모달 안내와 함께 차단되는지 확인한다.
- [ ] 포인트 상품은 포인트만, 입금 상품은 무통장만, 후불 상품은 발주하기만 가능한지 확인한다.
- [ ] 안내 문구가 사용자가 이해할 수 있게 표시되는지 확인한다.

### BR-07 마이페이지 정보 수정 권한

- [ ] 아이디(사업자번호 또는 사번)가 수정 불가능한지 확인한다.
- [ ] 기본 배송주소가 수정 불가능한지 확인한다.
- [ ] 우편번호 검색 버튼이 숨겨져 있는지 확인한다.
- [ ] 비밀번호·이메일·연락처 등 허용 항목은 정상 수정되는지 확인한다.

### BR-13 관리자 검색 기본 기간

- [ ] 회원 목록의 기본 조회 기간이 전체인지 확인한다.
- [ ] 주문 목록의 기본 조회 기간이 전체인지 확인한다.
- [ ] 페이지 재진입·새로고침 후에도 기본값이 전체인지 확인한다.

## 3. 회원 등급별 주문 시나리오

계정 ID와 비밀번호는 별도 보안 저장소를 사용한다.

### 물품계약 선불

- [ ] 일반 물품은 포인트로만 결제된다.
- [ ] 분유/입금 상품은 무통장 입금으로만 결제된다.
- [ ] 서로 다른 결제방식의 상품을 함께 주문할 수 없다.

### 물품계약 후불

- [ ] 일반 물품은 포인트로만 결제된다.
- [ ] 후불 대상 상품은 입금·포인트 차감 없이 발주 접수된다.

### 분유 선불

- [ ] 무통장 입금 결제만 노출된다.
- [ ] 주문 후 뱅크다 자동매칭 대상에 정상 등록된다.

### 분유 후불

- [ ] 결제 버튼이 `발주하기`로 표시된다.
- [ ] 입금·포인트 차감 없이 주문 접수된다.
- [ ] 발주 금액·수량 한도가 잘못 적용되지 않는다.

## 4. 주문서 UI 및 프론트엔드

- [ ] 마일리지·쿠폰 등 불필요한 결제 UI가 숨겨져 있다.
- [ ] 입금 결제 시 입금자명을 정확히 입력해야 한다는 강조가 노출된다. `AR-02`
- [ ] 모바일 상단 내비게이션을 방해하는 미리보기 UI가 제거되어 있다.

### 프론트엔드 1회차 취합 목록

- [ ] 요청 전 기본 하자와 단순 화면 조정을 분리한다.
- [ ] 1회차 소진 여부와 포함 항목을 서면으로 확정한다.

현재 회차 사용량: **0/2회차**
