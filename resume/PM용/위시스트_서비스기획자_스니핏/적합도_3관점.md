## 이견·쟁점

- 세 평가의 축이 서로 달라 같은 축 2점 차 비교 대상은 없다.
- **첫 화면:** A는 간략 소개가 `테스트 약 100건` 같은 활동량만 보여 SCM 운영자로 읽힌다고 봤다. C는 같은 소개의 `B2B·백오피스·연동 영역의 주니어 PM`이 스스로 범위를 좁힌다고 봤다. 둘 다 간략 소개 재작성을 가리킨다.
- **SCM 대시보드:** B만 아이베 경력 줄에 대시보드(C-077·080) 추가를 제안했다. 데이터 해석·업무용 소프트웨어·AI 코딩 도구 근거가 된다는 이유다. 공고분석(S1)도 같은 방향이다. A·C는 언급하지 않았다.
- **마켓빅시:** A·B가 허용 여부를 물었다. 허용하면 AI·마케팅 우대 근거가 E0에서 E1~E2로 오른다는 판단이다. 정본은 바로에이아이 제출본에만 허용했고 기본틀 포트폴리오는 p11~17에 넣고 있어 서로 엇갈린다(B 지적).

## 지원 결정 시 S4 작성 지시

1. **학력:** `2025.02 편입~YYYY.MM 졸업 예정`. 사용자 확인값만 쓴다.
2. **간략 소개:** B2B 결과 수치(C-040) 하나를 넣는다. `B2B·백오피스·연동 영역` 한정 문장은 빼고, 사용자와 동료의 반복 확인을 줄이는 업무용 제품을 만드는 방향으로 쓴다. 문체는 2026-10-03 SCM본 비교 분석에 대한 사용자 결정을 따른다.
3. **B2B 프로젝트:** 문제(AS-IS 수기 흐름) → 대안과 제외 이유 → 정책 → 운영 서버 QA → 가동 후 CS 관찰과 기능 반영(N-092, CS 2주 32 → 19건은 비교 기간이 다름을 함께 씀, C-042) → 결과.
4. **아이베 경력:** SCM 대시보드 한 줄 추가를 검토한다(C-077·080, 취합 시간 한정). 사용자 확인 후 넣는다.
5. **표현 정정:** 경력 줄 `자동·수기 테스트` → `자동 생성과 수기 생성을 포함한 테스트`. 관세청 30건에 `테스트`를 붙인다.
6. **관세청:** 판단 수정 사례(협의 방식 전환, 선출고 요청 철회 C-127) 중심으로 줄이고 규제 세부는 줄인다.
7. **쓰지 않는 것:** 인터뷰·A/B 테스트·이벤트 로깅·Figma·Amplitude·스타트업 근무 경험. 마켓빅시는 사용자 결정 전에는 넣지 않는다.
8. **포트폴리오:** 원문에 제출 요구가 없다. 낼 경우 p1 학력, p3 공급사 수, p10 관찰 기간, p1 Git을 먼저 정정한다(`PPT 반영` 지시 시).
