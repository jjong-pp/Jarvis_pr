# 누비랩 [북미] Product Manager - B2B SaaS 공고 분석

## 지원 판단

**현재 권고: 보류**  
**전환 조건: 북미 고객과 실시간으로 업무를 진행할 수 있는 영어 수준과 실제 사용 사례가 확인되면 조건부 지원**

경력 연차는 공고 범위에 들어가고, 실제 B2B 시스템 출시·운영, API 정책 설계, 기술 조직과의 협업 경험은 강하다. 반면 이 직무의 필수 조건인 영어 고객 커뮤니케이션과 실제 고객 데이터를 이용한 PMF 반복 실험은 현재 경력 원장에서 확인되지 않는다.

## 이 회사가 실제로 뽑으려는 사람

공고의 직함은 경력 5년 이하 PM이지만 업무 범위는 초기 북미 제품을 책임지는 사업형 PM에 가깝다.

- 북미 병원·파트너와 영어로 문제를 발견하고 요구를 정리하는 사람
- 고객 인터뷰부터 가설, MVP, 출시, 행동지표와 피벗을 짧은 주기로 반복하는 사람
- 개발·디자인뿐 아니라 영업·마케팅·고객 성공을 연결하는 사람
- 대형 고객의 개별 요구를 반복 판매 가능한 SaaS 제품으로 바꾸는 사람
- ARR·MRR·Churn·LTV/CAC, 활성·전환·리텐션을 직접 정의하고 개선하는 사람
- AI·API의 기술적 맥락과 병원 현장의 정확성·규제 위험을 함께 판단하는 사람

공고 문구만 보면 누비랩은 북미 시장 진입과 전략 고객 계약은 확보했지만, 반복 가능한 SaaS 제품·시장 적합성과 그로스 운영 체계를 만들어가는 단계로 해석된다. 이는 공고가 계약 성과를 강조하면서 동시에 0→1, PMF, 고객 세그먼트 실험, 피벗과 지표 정의를 요구한다는 점에 근거한 추론이다.

| 불확실한 환경에서 주도 실행 | 강한 적합 | 낯선 규정의 시스템 요건화, 서비스 가동과 후속 개선(C-031·C-112·C-126)이 확인된다. |

## 우대사항 적합도

| 우대사항 | 증거 수준 | 판단 |
|---|---|---|
| 0→1 제품 개발 전체 주기 | 강한 전이 증거 | B2B몰은 기획·대안 선택·정책·개발 조율·가동·측정까지 연결됐다. SaaS GTM 사례는 아니다. |
| 북미 B2B SaaS 출시·그로스 | 무증거 | BIGSEE는 공개 SaaS지만 북미·그로스 결과는 확인되지 않았다. |
| GTM 탐색 | 설계 수준 | 고객군·제안·채널 실험과 예산 상한 가설은 있으나 실제 획득·활성·전환 결과는 없다. |
| PLG | 무증거 | 제품 주도 성장 전략을 설계하거나 실행한 근거가 없다. |
| API·플랫폼 | 강한 전이 증거 | 관세청 API 연동의 처리 단위·상태·오류 복구 설계가 직접 증거다. 개발자 대상 제품 경험은 아니다. |
| SQL·Python 사용자 행동 분석 | 기술 적합, 용도 공백 | Python·FastAPI·SQLite·pandas 구현 경험은 있다. 디지털 제품 행동 분석 경험은 없다. |
| Figma·Jira·Notion·Amplitude/Mixpanel | 미확인 또는 무증거 | 확인 전 이력서에 기재하지 않는다. |
| 포트폴리오 | 충족 가능 | BIGSEE→B2B몰→관세청 순서의 누비랩 맞춤 구성이 필요하다. |

## 후보자의 강한 증거

1. **실제 B2B 제품 가동**: 계약 조건과 주문 예외를 정책·요구사항으로 바꾸고 외부 개발사와 전체 가동·운영 QA까지 연결했다.
2. **API·데이터 구조 이해**: 주문·포장·운송장과 처리 상태를 구분하고 오류 수정·재제출 기준을 설계했다.
3. **AI 제품 정책**: AI 출력의 출처·미확인값·금지 표현·사람 승인 조건을 정의했다.
4. **검증 설계 규율**: 가설에 시험 방법·통과 기준·증거 수준과 다음 행동을 붙이고, 가설 수정 이력을 삭제하지 않았다.
5. **출시 후 확인**: 개발 완료 통보와 운영 서버에서 실제 사용할 수 있는 상태를 구분해 검수했다.

## 핵심 공백과 예상 탈락 사유

1. 영어 업무 능력을 증명할 사례가 없다.
2. 실제 고객 인터뷰와 주 단위 PMF 실험 결과가 없다.
3. 북미 병원·헬스케어 SaaS와 GTM·PLG 경험이 없다.
4. North Star Metric과 ARR·MRR·Churn·LTV/CAC를 실제 운영한 경험이 없다.
5. 공식 직함이 SCM이어서 첫 화면에서 제품 역할이 명확하지 않으면 내부 시스템 기획자로만 읽힐 수 있다.

## 공고 문구에서 분리해 볼 부분

`AI 기업 최초`, `아시아 최초`, `글로벌 스탠다드`, `세계 최고 수준`, `1년이 3년의 경험`은 채용 홍보 문구다. 제공된 공고만으로 최초 여부, 수천 개 병원의 실제 활성 범위, 반복 매출과 유지율은 확인할 수 없다. 독점 계약도 시장 진입의 근거일 수 있으나 PMF와 반복 가능한 SaaS 매출을 자동으로 증명하지는 않는다.

## 조직과 역할의 숨은 리스크

- 제품전략·리서치·분석·GTM·고객성공을 한 역할에 모은 업무 과밀 가능성
- 북미 고객 대응에 따른 한국 시간 외 회의 가능성
- 병원의 긴 구매·보안·규제 절차와 주 단위 실험 요구 사이의 충돌
- 대형 전략 고객 맞춤 개발과 범용 SaaS 제품화 사이의 충돌
- 초기 분석 인프라와 지표 체계를 PM이 직접 만들어야 할 가능성

## 제출 전략

- 포지셔닝: `북미 SaaS 경험자`로 포장하지 않고, 규제·운영 제약이 큰 B2B 현장에서 문제 정의부터 정책·QA·운영 전환까지 실행한 기술 기반 주니어 PM으로 제시한다.
- 이력서: 첫 화면에서 BIGSEE의 제품·실험 설계와 B2B몰의 실제 출시 증거를 함께 보여준다. 관세청은 API·기술 협업 근거로 배치한다.
- 포트폴리오: BIGSEE → B2B몰 → 관세청 순서로 구성한다. BIGSEE의 미검증 상태를 공개하고 B2B몰이 실제 실행·측정 증거를 보완하도록 한다.
- 제외: Figma·Notion, BIGSEE 시작월, 자동 입금 매칭 완료, 비교 범위가 열린 정산 단축 수치, PMF·CAC·리텐션 성과를 확인 전까지 쓰지 않는다.

## 결과를 바꾸는 미확인 사항

- `Q-FACT-NUVILAB-ENGLISH [OPEN]`: 영어로 해외 고객·공급사와 회의, 통화, 메일, 요구사항 문서, 발표 또는 협상을 직접 수행한 사례와 빈도
- `Q-EVIDENCE-NUVILAB-EXPERIMENT [OPEN]`: BIGSEE 또는 다른 서비스에서 실제 고객 반응을 받아 가설·범위·화면·가격·채널을 바꾼 사례와 그 결과

첫 질문은 지원 여부를 결정하는 하드 게이트다. 두 번째는 보류 판정을 뒤집을 수 있는 제품 경험 증거다.
