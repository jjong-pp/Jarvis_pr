- 기준 원본: `../기본틀_PM_포트폴리오.pptx` 24장
- 목표: 제목 → 상황·문제 → 판단·해결 과정 → 구현·검수 → 결과·피드백 패턴을 세 프로젝트에 반복 적용
- 순서: B2B 주문몰 → 관세청 통관 연동 → 신규 ERP 주문·물류 연계
- 상태: 내용 계획 확정. 사용자가 `PPT 반영`을 지시하기 전까지 PPTX는 수정하지 않는다.

## 1. 전체 작성 원칙

### 프로젝트 공통 패턴

1. **프로젝트 제목:** 기간·역할·서비스 상태를 한 줄로 제시
2. **상황과 문제:** 사용자 또는 운영자가 겪은 장면을 화면·Flow와 함께 설명
3. **판단과 해결 과정:** 검토한 대안, 선택 기준, 제외 범위를 보여줌
4. **정책·Wireframe·Flow:** 실제로 정의한 화면 구조·권한·상태·예외를 시각화
5. **구현과 검수:** 본인과 개발사 역할을 분리하고 QA·수정 과정을 설명
6. **결과와 피드백:** 수치, 관찰 기간, 사용자의 반응, 남은 한계를 함께 기록

한 장에 위 내용을 모두 넣지 않는다. 각 장은 제목 하나와 시각 자료 하나를 중심으로 구성하고, 본문은 그 그림을 읽는 데 필요한 설명만 남긴다.

### 화면·산출물 라벨

- `실제 운영 화면`: 배포 후 직접 확인한 화면
- `재구성 Wireframe`: 당시 Wireframe 원본이 남아 있으면 원본과 현재 운영 화면을 함께 참고한다. 원본이 없으면 확정 정책과 운영 화면을 기준으로 다시 정리하고 `원본 미보존·운영 화면 기반 재구성`이라고 표시한다.
- `정책 설계 자료`: 실제 정책·요구사항을 제출용으로 재작성한 표
- `계획 화면`: 구현·성과가 확인되지 않은 제안 또는 정의안
- 모든 장에 `기획·검수: 본인 / 구현: 외부 개발사`처럼 역할을 표시

### 첨부 화면 처리

- 사용자 첨부 화면 1·2에는 상품 가격이 노출되고, 화면 3에는 회원 등급·포인트 값이 노출된다. 원본 그대로 제출하지 않는다.
- 화면 구조를 설명할 때는 기존 제출용 자산을 우선 사용한다.
  - `../증거/b2b/submission_safe/home_feature_banner.png`
  - `../증거/b2b/submission_safe/mypage_menu.png`
  - `../증거/b2b/submission_safe/mypage_order_status.png`
  - `../증거/b2b/submission_safe/account_policy_matrix.png`
- 첨부 화면은 `재구성 Wireframe`의 정보 구조와 실제 화면 배치 확인에만 사용한다. 가격·회원명·등급·포인트·주문번호는 모두 제거하거나 마스킹한다.

## 3. B2B 핵심 장 상세 문안

### p4 문제 설명

**제목:** 분산된 주문 정보와 반복 확인

주문은 구글 설문, 입금은 계좌 내역, 상품과 계약 정보는 Excel에서 확인했습니다. 운영자는 주문마다 조리원 계약과 상품 종류를 다시 대조했고, 그 과정에서 오출고와 입금 확인 문의가 반복됐습니다.

**그림:** `주문 접수 / 입금 확인 / 상품·계약 확인 / 출고 대상 정리`가 서로 다른 자료에 놓인 AS-IS Flow.

### p7 해결 과정

**제목:** 화면 구조와 주문 상태

초기 기획에서 홈, 상품 목록, 마이페이지의 핵심 구조와 주문 흐름을 간단한 Wireframe으로 정리했습니다. 운영 화면에서는 상품군 탐색, 주문 상태 확인, 문서 출력이 한 흐름으로 이어지도록 구성했습니다.

**그림:** 왼쪽 `재구성 Wireframe`, 오른쪽 `실제 운영 화면`. 두 자료가 같은 구조를 어떻게 표현하는지 선으로 대응시킨다.

### p9 피드백 반영

**제목:** 운영 문의에서 찾은 개선 항목

영업담당자 CS 회의와 주간 보고서에서 문의 유형을 3주간 관찰했습니다. 배송 현황과 거래명세서·견적서 요청이 대다수임을 확인했고, 주문 상태 확인과 거래명세서 출력으로 반복 문의를 줄이는 방향을 반영했습니다.

**그림:** `CS 기록 / 유형 분류 / 기능 반영 / 운영 확인` 피드백 Flow.

### p10 결과와 한계

**제목:** 주문 확인 업무와 오류 감소

- 2026-07-16 가동 후 월 주문 약 300건, 실제 주문 조리원 약 130곳
- 오출고: 직전 6개월 월평균 2~3건 → 2026-09-26까지 약 2개월 이상 0건
- 월말 정산: 매월 2명이 각 2~3시간 → 1명 30~60분
- CS 32건→19건은 2026.01~06의 2주 환산치와 2026.07~08 배포 구간 집계를 비교한 값이므로 보조 지표로만 표시
- 모바일·키오스크 경험과 장기 제품지표는 아직 없음

## 4. PPT 반영 전 필요한 자료
