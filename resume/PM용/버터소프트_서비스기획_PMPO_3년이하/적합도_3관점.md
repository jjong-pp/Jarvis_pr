- 실행일: 2026-09-28
- 모드: 외부 조사·확정 전 검토
- 평가: A·B·C 독립 서브에이전트, 병렬·상호 비공개
- 입력: 공고 원문 + PM 기본틀 이력서 + PM 성과 해당 절 + 포트폴리오 슬라이드 지도

|---|---|---|
| A 채용 의도 | 조건부 | 출시·운영·백오피스 경험은 강하지만 IA·Wireframe·Figma 산출물이 즉시 확인되지 않음 |

| C 탈락 위험 | 조건부 / 문서 BLOCK | 후보자 사실보다 제출 예정 포트폴리오의 비공개 값·관찰 기간·Git 정본 충돌을 먼저 정리해야 함 |

## 공통 결론

- **강점:** 운영 예외를 관리자 정책·권한·상태로 구조화하고, 개발사 조율·QA·운영 전환까지 닫은 경험.
- **가장 가까운 사례:** B2B 주문몰. 관리자 설정, 계정 권한, 혼합주문, 포인트 안전장치, 운영 데이터 기반 개선이 공고와 직접 대응한다.
- **차별점:** 월 약 300건 규모의 실제 운영과 오출고·정산·CS 결과를 측정 범위와 함께 제시할 수 있다.
- **핵심 공백:** IA·Wireframe 실물, 소비자용 모바일·키오스크 UX, 사내 제품 스쿼드, Figma·Notion.
- **금지:** 공백을 제품 경험처럼 포장하지 않는다. 사용자 인터뷰·사용성 테스트·Figma 숙련을 새로 만들지 않는다.

## 지원 결정 시 S4 작성 지시

1. 첫 문장: `B2B·백오피스의 운영 규칙을 정책과 화면·데이터 흐름으로 구체화하고, 개발 협업과 QA를 거쳐 운영 전환한 서비스 기획자`.
2. 공식 직함과 프로젝트 역할을 함께 쓴다: `SCM팀 사원 / 프로젝트 PM`.
3. 이력서 프로젝트 순서: B2B 주문몰 → 신규 ERP 주문·물류 연계 → 관세청 통관 연동.
4. 포트폴리오 순서: B2B → 관세청 → 마켓빅시 축소. p6~10, p20~23을 핵심 증거로 배치한다.
5. B2B에 `영업담당자 CS 회의 + 주간 보고서 3주 관찰 → 문의 유형 분류 → 기능 반영`을 추가한다. 정식 인터뷰로 쓰지 않는다.
6. 산출물은 확인된 명칭만 쓴다: 요구사항 대장, 정책 매트릭스, 권한표, UAT 시나리오, 운영 매뉴얼, API 필드 매핑표, 정책 결정 이력.
7. IA·Wireframe·Figma·Notion은 사용자 답변과 증거 확인 전 넣지 않는다.
