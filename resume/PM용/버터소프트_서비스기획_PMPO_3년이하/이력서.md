- 프로젝트 순서를 B2B 주문몰 → 신규 ERP → 관세청 통관 연동으로 조정

## 간략 소개

B2B·백오피스의 운영 규칙을 정책과 화면·데이터 흐름으로 구체화하고, 개발 협업과 QA를 거쳐 운영 전환한 서비스 기획자입니다. 산후조리원 전용 B2B 주문몰에서는 초기 화면 구조와 핵심 사용자 흐름을 간단한 와이어프레임으로 정리하고, 계정 유형·상품 카테고리별 결제와 권한 정책을 설계했습니다. 운영 서버에서 주문·마이페이지·포인트·예외 조건을 검수했으며, 실제 운영 데이터를 보고 개선 항목을 정리했습니다.

공식 소속은 SCM팀이며 개발은 외부 개발사가 담당했습니다. 저는 B2B 주문몰과 관세청 연동에서 프로젝트 PM으로 기획·요건 정의·관계사 조율·QA·운영 전환을 담당했습니다. 관세청 프로젝트에서는 Notion 공유 파일을 사용해 관계사와 자료를 공유했고, 신규 ERP에서는 주문 수집부터 WMS·통관 API 매핑까지 요건을 정의한 뒤 자동·수기 생성을 포함한 테스트 약 100건의 결과를 추적하고 있습니다.

## 경력 및 프로젝트

### 1. 산후조리원 전용 B2B 주문몰

- **기간:** 2026.06~2026.08.31
- **문제:** 구글 설문·계좌 내역·Excel로 주문과 정산이 나뉘어 있었고, 계정 유형과 상품에 따라 결제 방식이 달라 운영자가 매번 주문 조건을 확인해야 했습니다.
- **역할:** 맞춤형 개발, 타 쇼핑몰 솔루션, 기존 솔루션의 정책 맞춤안을 비교해 고도몰5 기반 구축을 선택했습니다. 초기 화면 구조와 주요 사용자 흐름을 간단한 와이어프레임으로 정리하고, 4개 계정 유형과 상품 카테고리에 따른 결제 설정, 혼합주문 차단, 월말 포인트 정리의 확인 절차와 권한 기준을 정의했습니다. 외부 개발사가 구현하고 본인은 운영 서버에서 기대 결과를 검수했습니다.
- **운영 개선:** 현장을 도는 영업담당자들과 CS 회의를 진행하고 주간 보고서에 문의 유형을 추가해 3주간 관찰했습니다. 배송 현황과 거래명세서·견적서 문의가 대다수임을 확인해 주문 상태와 문서 출력 기능으로 대체했습니다.
- **결과:** 2026-07-16 가동 후 월 주문 약 300건·실제 주문 조리원 약 130곳 규모로 운영했습니다. 직전 6개월 월평균 2~3건이던 오출고는 2026-09-26까지 약 2개월 이상 0건을 유지했습니다. 월말 정산은 매월 2명이 각 2~3시간 수행하던 방식에서 1명 30~60분으로 줄었습니다.

### 2. 신규 ERP 주문·물류 연계 정립

- **상태:** 진행 중. 구 SKU 코드와 병행 사용 중이며 WMS 정착 후 완전 이관 예정
- **문제:** 채널마다 주문 원본 양식과 상품 식별 기준이 달라 ERP·WMS·통관 시스템 사이에서 같은 상품과 주문을 일관되게 연결할 기준이 필요했습니다.
- **역할:** `브랜드_대분류_SKU명_SKU분류_단위` 규칙을 정해 SKU 40종을 정리했습니다. 채널별 주문 원본 양식 통일, 주문·상품 매핑, SKU Set, 해외창고 WMS, 통관사 API 필드 매핑의 요건을 정의했습니다.
- **검증:** 자동 생성·수기 생성을 포함한 테스트 약 100건을 수행했으며 현재도 결과를 추적하고 있습니다.

### 3. 관세청 전자상거래 통관 연동

- **일정:** 2026.02 시작, 2026.08.28 운영 전환
- **문제:** 관세법 개정과 전자상거래 통관플랫폼 도입에 맞춰 자사몰·외부 채널의 거래정보를 수입 전에 제출할 수 있도록 여러 시스템의 필드와 상태를 연결해야 했습니다.
- **역할:** 주문·상품·수하인 정보를 ERP·WMS·통관 시스템으로 연결하는 필드, 처리 상태, 분할·합배송, 오류 수정·재제출 기준을 정의했습니다. 자사몰 개발사·ERP 개발사·물류 개발사·통관대행사·본인확인기관과 요건을 조율하고, 관세청 프로젝트 공유 파일에 Notion을 사용했습니다.
- **예외 대응:** 기존 신고서가 P로 시작하는 개인통관고유부호만 수용하는 제약을 확인해, O부호가 생성되는 간편인증 경로를 제한하고 고객이 P부호를 입력하도록 처리 기준을 조정했습니다.
- **결과:** 운영 환경 30건에서 정상 접수, 의도한 오류 반환, 수정 후 재제출을 기대대로 확인했습니다. 2026-08-28~09-15 집계 일평균 약 300건이며 기존 방식과 신규 연동을 병행해 집계 대상 주문 전체의 통관 완료를 확인했습니다.

## 자기소개서

### 방향성 ― 운영 규칙을 사용자가 이해할 수 있는 서비스로 만드는 일

운영 현장에는 담당자가 머릿속으로 판단하는 규칙이 많습니다. 저는 그 규칙을 계정·권한·결제·상태·예외 조건으로 나누고, 사용자가 화면에서 확인할 수 있는 흐름으로 옮기는 일을 해 왔습니다. B2B 주문몰에서는 조리원별 계약과 상품 종류에 따라 달라지는 결제 기준을 관리자 설정과 사용자 화면에 연결했고, 관세청 연동에서는 여러 회사가 나눠 가진 필드와 처리 상태를 하나의 흐름으로 정리했습니다.

버터소프트 공고는 웹·모바일·키오스크와 백오피스를 함께 다루고, 요구사항 작성부터 구현 검수까지 맡는 역할을 제시합니다. 소비자용 모바일·키오스크 경험은 아직 없지만, B2B 웹 서비스에서 간단한 와이어프레임과 정책서를 만들고 운영 서버에서 결과를 검수한 경험이 있습니다. 세이치즈와 고객 프로젝트에서도 화면 뒤의 운영 규칙과 예외를 먼저 이해하고, 개발자와 디자이너가 구현할 수 있는 문서와 흐름으로 구체화하겠습니다.

### 성격의 장단점 ― 낯선 제약을 실행 기준으로 바꾸는 방식

강점은 처음 접한 문제도 필요한 지식과 관계자를 찾아 실행 기준으로 만드는 점입니다. 관세청 연동에서는 통관, 물류, 본인확인 규칙을 익히고 각 시스템의 필드와 책임을 정리했습니다. 관계사별 설명만으로는 전체 흐름의 빈틈을 찾기 어려워 통합 필드 매핑과 오류·재제출 기준을 만들고 공동 검토 방식으로 바꿨습니다.

단점은 문제를 발견하면 예외까지 한 번에 해결하려고 범위를 넓히는 경향입니다. B2B 주문몰 초기에 견적서 개발, PG 결제, 포인트 완전 자동화까지 검토했지만 비용·운영 위험을 비교해 범위를 줄였습니다. 현재는 발생 빈도와 사용자 영향, 운영 위험을 기준으로 첫 배포 범위를 정하고 이후 피드백으로 보완합니다.

### 직무 성공 및 실패 사례 ― B2B몰 운영 전환과 통관 연동 협의 방식 개선

**성공 사례.** 구글 설문·계좌 내역·Excel로 나뉜 주문·정산 업무를 B2B 주문몰로 전환했습니다. 초기 화면 구조와 사용자 흐름을 간단한 와이어프레임으로 정리하고, 4개 계정 유형과 상품 카테고리에 따른 결제 설정과 혼합주문 기준을 정의했습니다. 2026-07-16 가동 후 월 약 300건을 처리했고, 오출고는 직전 6개월 월평균 2~3건에서 2026-09-26까지 약 2개월 이상 0건을 유지했습니다. 운영 이후에는 영업담당자 CS 회의와 주간 보고서를 통해 문의 유형을 확인하고 배송 상태와 문서 출력 기능을 보완했습니다.

**실패 사례.** 관세청 연동 초기에는 관계사별 협의만으로 전체 연동을 맞출 수 있다고 판단했습니다. 각 담당사가 자신의 필드와 로직 중심으로 설명해 데이터 소유권과 인터페이스 불일치를 늦게 발견했습니다. 이후 주문부터 신고·출고까지의 흐름, 필드 매핑표, 책임 구분, 리스크·질의 대장을 통합하고 공동 검토로 전환했습니다. 최종 일정은 지연되지 않았고 운영 환경 30건에서 예상한 접수·오류·재제출 결과를 확인했습니다.
