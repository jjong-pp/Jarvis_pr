# 박종혁

지원 분야: Product Manager · 서비스 기획

## 간략 소개

처음 접하는 운영 문제도 필요한 규정과 시스템 구조를 익히고, SCM과 3PL 현장의 예외를 정책과 데이터 흐름으로 정리해 요구사항부터 QA·운영 전환까지 연결해 왔습니다. B2B 주문몰에서는 도입 대안과 범위, 계정·결제·주문 정책을 설계했습니다. 관세청 통관 연동에서는 주문·ERP·WMS·통관 사이의 필드와 상태, 오류 수정·재제출 기준을 정의했습니다.

공식 소속은 SCM팀이며 개발은 외부 개발사가 담당했습니다. 저는 두 프로젝트의 기획·요건 정의·관계사 조율·QA·운영 전환을 담당했으며, 신규 ERP에서도 주문 수집부터 WMS·통관 API 매핑까지 요건을 정의했습니다. 자동·수기 생성을 포함한 테스트 약 100건을 수행했으며 현재도 결과를 추적하고 있습니다. 이 경험을 바탕으로 B2B·백오피스·연동 영역의 주니어 PM으로 성장하고자 합니다.

## 경력 및 프로젝트

### 1. 산후조리원 전용 B2B 주문몰

- **기간:** 2026.06~2026.08.31
- **목적:** 구글 설문·계좌 내역·Excel로 나뉜 주문·정산 업무를 회원제 B2B 주문몰로 전환
- **역할:** 맞춤형 개발, 타 쇼핑몰 솔루션, 기존 솔루션의 정책 맞춤안을 비교해 고도몰5 기반 구축을 선택하고, 4개 계정 유형과 상품 카테고리에 따른 결제 설정, 혼합주문 차단, 월말 포인트 정리의 확인 절차와 권한 기준을 정의. 외부 개발사가 구현하고 본인은 운영 서버에서 기대 결과를 QA
- **결과:** 2026-07-16 가동 후 월 주문 약 300건·실제 주문 조리원 약 130곳 규모로 운영. 직전 6개월 월평균 2~3건이던 오출고는 2026-09-26까지 2개월 이상 0건 유지. 도입 후 매일 하던 주문 취합과 입금 대조 업무는 제거

### 2. 관세청 전자상거래 통관 연동

- **일정:** 2026.02 시작, 2026.08.28 운영 전환
- **목적:** 관세법 개정과 전자상거래 통관플랫폼 도입에 맞춰 해외직구 거래정보 제출 흐름을 자동화
- **역할:** 자사몰·외부 채널의 주문·상품·수하인 정보를 ERP·WMS·통관 시스템으로 연결하는 필드, 처리 상태, 분할·합배송, 오류 수정·재제출 기준을 정의하고 관계사와 조율
- **예외 대응:** 기존 신고서가 P로 시작하는 개인통관고유부호만 수용하는 제약을 확인해, O부호가 생성되는 간편인증 경로를 제한하고 고객이 P부호를 입력하도록 처리 기준을 조정
- **결과:** 운영 환경 30건에서 정상 접수, 의도한 오류 반환, 수정 후 재제출을 기대대로 확인. 2026-08-28~09-15 집계 일평균 약 300건이며 기존 방식과 신규 연동을 병행해 집계 대상 주문 전체의 통관 완료를 확인

### 3. 신규 ERP 주문·물류 연계 정립

- **상태:** 진행 중. 구 SKU 코드와 병행 사용 중이며 WMS 정착 후 완전 이관 예정
- **역할:** `브랜드_대분류_SKU명_SKU분류_단위` 규칙을 정해 SKU 40종을 정리. 채널별 주문 raw 양식 통일, 주문·상품 매핑, SKU Set, 해외창고 WMS, 통관사 API 필드 매핑의 요건을 정의
- **검증:** 자동 생성·수기 생성을 포함한 테스트 약 100건을 수행했으며 현재도 결과를 추적

## 자기소개서

### 방향성 ― B2B 운영 규칙을 시스템 요건으로 옮긴 경험

현장의 불편을 들으면 반복되는 원인과 예외 조건부터 확인합니다. B2B 주문몰에서는 상품 카테고리와 계정 유형에 따른 결제·권한 정책으로, 관세청 연동에서는 필드·상태·재처리 기준으로 문제를 구체화했습니다. 운영 문제를 기획에 반영하고 배포 후 지표와 예외까지 확인하는 PM으로 성장하겠습니다.

### 성격의 장단점 ― 리콜 절차 정리와 B2B 범위 축소

강점은 처음 접한 문제도 필요한 지식과 관계자를 찾아 실행 기준으로 만드는 점입니다. 약 30억 원·105,000캔 규모의 리콜에서 SGS 감사 요건을 조사하고 한국·중국 창고별 절차를 정리했습니다. 창고와 감사기관을 조율해 최종 보고서를 완성했고 본사 보상액 100% 환수로 연결됐습니다.

단점은 문제를 발견하면 예외까지 한번에 해결하려고 범위를 넓히는 경향입니다. B2B 주문몰 초기에 견적서 개발, PG 결제, 포인트 완전 자동화까지 검토했지만 비용·마진·운영 위험을 비교해 범위를 줄였습니다. 현재는 발생 빈도, 사용자 영향, 비용, 운영 위험을 기준으로 범위를 정합니다.

### 직무 성공 및 실패 사례 ― B2B몰 운영 전환과 통관 연동 협의 방식 개선

**성공 사례.** 구글 설문·계좌 내역·Excel로 나뉜 주문·정산 업무를 B2B 주문몰로 전환했습니다. 4개 계정 유형과 상품 카테고리에 따른 결제 설정, 혼합주문 차단, 월말 포인트 정리의 확인 절차를 정의하고 운영 서버에서 예외 조건을 검증했습니다. 2026-07-16 가동 후 월 약 300건을 처리했고, 월 기준 실제 주문 조리원은 약 130곳이었습니다. 오출고는 직전 6개월 월평균 2~3건에서 2026-09-26까지 2개월 이상 0건으로 유지됐습니다.

**실패 사례.** 관세청 연동 초기에는 관계사별 협의로 전체 연동을 맞출 수 있다고 판단했습니다. 각 담당사가 자신의 필드와 로직 중심으로 설명해 데이터 소유권과 인터페이스 불일치를 늦게 발견했습니다. 이후 주문부터 신고·출고까지의 전체 흐름, 필드 매핑표, 책임 구분, 리스크·질의 대장을 통합하고 관계사 공동 검토로 전환했습니다. 최종 일정은 지연되지 않았고 운영 환경 시나리오 30건에서 예상한 접수·오류·재제출 결과를 확인했습니다. 이 경험 후 시스템 연동은 개발 전에 전체 의존성과 실패 조건부터 같이 검토합니다.
