# resume 작업 규칙

이 폴더의 목적은 공고 지원을 위한 이력서·자기소개서·포트폴리오 작성, 공고 맞춤 적합도 분석, 지원 전략 수립이다. 새 대화에서도 기존 판단을 이어가며 이미 확정한 사실을 다시 묻거나 처음부터 재조사하지 않는다.

## 시작할 때 읽는 순서

1. `C:\MyMain\main\.claude\skills\resume\SKILL.md` 전체
2. `career_facts.md`의 0·6·8·12절과 현재 요청에 해당하는 프로젝트 절
3. `C:\MyMain\main\project_state.md`의 `이력서/구직` 절
4. 같은 회사의 `applications/{회사}_{직무}_{공고ID}/` 기존 파일
5. 감사 단계에서만 `_eval/rubric.md`

`_archive/`는 과거 판단의 기록이며 현재 사실·지침의 정본이 아니다. 원본 프로젝트 폴더는 정본 간 충돌이 의심될 때만 다시 연다.

## 정보의 저장 위치

- 경력·기간·수치·역할·증거: `career_facts.md`
- 반복 적용할 분석·작성 공정: `C:\MyMain\main\.claude\skills\resume\SKILL.md`
- 지원 현황·마감·다음 행동: `C:\MyMain\main\project_state.md#이력서/구직`
- 특정 회사에만 해당하는 판단과 문안: 해당 `applications/` 폴더

같은 사실을 여러 파일의 정본으로 만들지 않는다. 사용자가 사실을 정정하면 원장에 `[YYYY-MM-DD 정정] 종전 → 신규 (근거)`로 남기고 현재 제출본의 영향 범위를 검색한다.

## 공고 한 건 처리

1. 공고 원문·URL·확인일·상태를 `jd_snapshot.md`에 보존
2. 필수·우대·업무·조직 맥락·숨은 리스크를 분리하고 지원 자격 게이트 판정
3. `career_facts.md` claim ID로 요구사항-증거 매트릭스 작성
4. 공고에 맞는 트랙·핵심 메시지·프로젝트 순서·뺄 내용을 결정
5. 공고가 실제로 요구하는 산출물만 초안으로 만든 뒤, 결과를 바꾸는 미확인 사항만 질문
6. 작성자와 다른 관점으로 사실·일관성·가독성·공고 대응을 검증

합격 가능성은 근거 없는 단일 백분율로 말하지 않는다. `지원 권고/조건부/보류`, 자격 게이트, 증거 강도, 핵심 공백과 예상 탈락 사유로 설명한다.

## 사용자 질문 규칙

- 한 번에 1~3개만 묻고, 지원 판단이나 문안이 실제로 달라지는 질문부터 묻는다.
- 각 질문에 `왜 필요한지`와 `가능하면 받을 증거`를 짧게 붙인다.
- 반복 관리가 필요한 질문은 `Q-FACT / Q-EVIDENCE / Q-PREF / Q-JD` ID와 `OPEN / ANSWERED / DEFERRED` 상태를 붙인다.
- 이미 답한 내용은 다시 묻지 않는다. 날짜·수치·역할이 충돌하거나 기준 시점이 바뀐 경우에만 재확인한다.
- 답은 후보자 사실, 증거 범위, 장기 선호, 특정 공고 선택 중 하나로 분류해 해당 정본에 반영한다.
- 낮은 영향의 미확인 항목 때문에 초안 작성을 멈추지 않는다. `CONFLICT` claim은 항상 제외하고, 그 claim이 공고의 핵심 근거라면 작성을 차단한다.

## 문서별 책임

- 간략 소개: 지원 방향과 문제 해결 방식. 프로젝트 성과를 반복 나열하지 않음
- 이력서·경력기술서: 기간·역할·범위·검증 가능한 결과 중심
- 자기소개서: 지원동기와 공고에 가장 가까운 사례를 구체적 장면으로 설명
- 포트폴리오: 문제 근거 → 판단·대안·제외 → 정책·요구사항·흐름 → QA·배포 → 결과·한계
- 지원 전략: 왜 지원할지, 무엇을 앞세울지, 어떤 공백을 인정하고 보완할지 결정

핵심 메시지는 공유하되 문장을 그대로 복사하지 않는다. 제품·0→1·AI 공고는 BIGSEE, 커머스·운영 PM은 B2B몰, 규제·SI·연동은 관세청을 우선 배치한다. 광범위한 주니어 PM 공고는 완결된 실행과 측정이 있는 B2B몰을 기본 첫 사례로 둔다.

## 작성·검증 기준

- 한국어로 건조하고 구체적으로 작성. 불필요한 영한 병기와 방법론 이름 나열 금지
- `A가 아니라 B`, 추상명사 병렬, 과도하게 매끈한 성공 서사 등 AI 초안 문체 제거
- 숫자에는 기간·모수·비교 기준·원천·측정 상태를 가능한 범위까지 붙임
- 본인 역할과 개발자·디자이너·현업·외부사의 역할을 분리
- 기능·성과를 `운영 중 / 구현 완료 / 테스트 완료 / 정책 설계 / 제안 / 미계측`으로 구분
- 실제 화면, 재구성 화면, 계획 화면을 라벨로 구분하고 개인정보·단가·주문번호 마스킹
- 제출 전 이력서·자소서·포트폴리오의 회사명·직무명·기간·수치·역할·링크를 교차 대조
- 정본을 고친 뒤 `resume/` 전체에서 종전 값을 검색하고, 영향을 받은 기존 지원본은 수정하거나 `STALE`로 표시
- 외부 제출·지원·담당자 연락은 사용자의 최종 승인 전 실행하지 않음
