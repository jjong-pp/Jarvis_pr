### 1-1. 회사와 공고

**회사:** 차량 센서와 AI로 도로의 파손·위험 요소를 먼저 찾아내고, 원격 확인과 조치·유지관리까지 잇는 서비스를 만드는 스타트업. 도로에서 시작해 도시 문제 전반으로 넓히는 중이다.

**배경과 주요 사업** (공개 자료, 2026-10-03 조사)
- 제품: 탐지·대응·예측. 국민신문고 자동 접수, 자동 보고서, 현장 작업 지시와 연계
- 흐름: 버스·공무차량 데이터 수집 → AI와 위치 보정(RTK)으로 위험 감지 → 민원 자동 접수 → 담당 부서 처리 → 현장 작업 지시 → 처리 결과 축적
- 고객: 지자체(B2G). LG유플러스와 용인시에서 도로 위험 모니터링 운영

- 확장: 마을버스·관용차 300대로 확대, 철물 파손·동물 사체까지 대상 확대 계획. 프리A 약 10억 원 투자 유치(MYSC·더웰스인베스트먼트). `도로 민원 자동 검출 서비스 고도화 실증`(2025.11~2027.11)

**공고가 원하는 사람**

- 반복되는 문제는 다시 생기지 않는 구조로 재설계한다
- 우대: B2B·SaaS, 복잡한 현장 업무 개선, SQL·Python, AI 도구로 만든 도구·프로토타입, 개발자·영업·고객·경영진 사이에서 문제를 구조화한 경험

**Q2. B2B 전용몰: 문제를 어떻게 정의했고 무엇을 만들고 무엇을 뺐나** (자소서 성공 사례, 포트폴리오 9~14쪽)

**Q3. 관세청 연동: 가장 어려웠던 점과 실패에서 배운 것** (자소서 실패 사례, 포트폴리오 3~8쪽)

- 상황: 관세법 개정으로 직구 주문의 거래정보를 사전 제출해야 했다. 주문 한 건의 데이터가 자사몰(주문·결제·고객), 본인확인기관(통관부호 검증), 해외 ERP·WMS(상품·포장·운송장·실중량), 통관대행사(수입신고)에 나뉘어 어느 곳도 혼자 신고를 완성할 수 없었다.
- 구조 선택: 해외 ERP 중심안은 개인정보 국외 이전 우려로 뺐다. Excel 수기 제출은 상태·재처리·감사 추적이 안 돼 장애 때 쓰는 대비책으로만 남겼다. 국내 자사몰 DB가 신고 판단과 상태를 통제하는 안을 골랐다. 판단 순서는 개인정보 최소화 → 제출 상태 통제 → 원천별 책임 분리 → 개발 난이도. 원천 데이터는 각 시스템이 계속 책임진다.
- 실수: 관계사별로 협의하면 전체 연동도 맞출 수 있다고 봤다. 각 회사가 대외비를 이유로 자기 필드와 내부 로직만 공유하면서 데이터 소유권과 인터페이스 불일치가 늦게 드러났다. 관세청 API 변경까지 겹쳐 중간 개발 일정이 여러 번 밀렸다.
- 바꾼 방식: 주문부터 신고·출고까지의 전체 흐름, 필드 매핑표, 책임 구분, 리스크·질의 대장을 하나로 묶어 관계사가 함께 검토하게 했다. 전체 판을 펼치자 원인이 잡혔고 대외비 문제도 없었다. ERP 개발사와는 세관 제출 로직과 ERP 정보 로직을 잇는 중간 API로 조회 경로를 하나로 만들었다. 통관대행사에는 ERP용과 자사몰용 API를 따로 요청해 원천별로 나눴다.

**Q1. 자기소개와 왜 기영에프앤비인가**

**Q2. 입출고·재고·수발주·결산을 어떻게 했나** (공고 1·2번)

- 발주: 판매 전망을 모아 6개월 리드타임, 목표 재고, MOQ, 현금흐름을 보고 발주안을 만든다. 팀장 협의와 승인 후 PO를 내고 생산·선적·입항·통관·입고와 입고 정산까지 추적한다. 월 약 20개 SKU, 4~6만 캔 규모다(보충).

- 결산: 인구보건복지협회 특수분유와 산후조리원 판매상품의 월 정산, 물류비 정산. 회계 결산 전체는 아니다.

- 어필: 전산과 실물을 맞추는 순서가 몸에 배어 있음
- 피할 것: `선입선출`이라고 말하기(유통기한 기준이면 FEFO). 회계 결산 경험으로 넓히기

**Q3. 3PL과 협력업체를 어떻게 관리했나** (공고 3·5번)
- 패턴: 문제 발견 → 비교 기준 → 계약 조건 → 이관 결과 → 운영 중 조율
- 사례(보충, 이력서에 없음): 2026년 6월경 기존 풀필먼트의 정산 불안정과 CS 전달 문제를 확인하고 3PL 4곳을 입고·출고·보관·CS 대응 기준으로 비교·비딩했다. 두 곳의 물류를 한 곳으로 합쳐 3개 브랜드를 약 2주에 이관했고 재고 오차와 오출고는 없었다. 견적과 운영 2개월 실청구 기준으로 월 약 200만 원 관리비를 줄였다. 해지 통보 기간과 입고 파렛트 높이 같은 조건을 계약에 넣었다. 초기 30일 중 약 5일 출고 지연 뒤 안정됐다.
- 운영 조율: 3PL 소통방과 사내 CS를 연결했고, 이관 초기 유리병 제품의 CS가 많아 포장 방식을 협의했다.
- 서류에 있는 근거: 창고별 재고 배분과 입출고·배차 운영·물류비 정산, 공급사 보상 관리
- 어필: 비용과 함께 SLA, 계약 조건, 실청구까지 확인하고 문제를 끝까지 닫음
- 피할 것: 업체명·단가·평가표. 처리 시간이 빨라졌다는 말(측정값 없음)

**Q4. 품질 이상이나 클레임은 어떻게 처리하나** (공고 4·5·7번)
- 패턴: 내 사례 → 같은 원칙을 점포 클레임에 적용
- 사례(경력기술서 3): 2026년 105,000캔 규모 리콜. 대상 출고를 막고 오프라인 점포·물류센터·사입 센터·고객 반품·3PL 창고의 대상 재고를 모두 회수했다. 4~7월 한국·중국 창고에서 3자 대면으로 전면 폐기를 진행하며, 처음 접한 SGS 감사 요건을 조사해 창고별 증빙·입회·폐기·결과 보고 절차를 정리했다. 최종 보고서가 본사 보상액 100% 환수로 이어졌다(여러 사람이 조율한 결과).
- 여러 점포에서 같은 클레임이 오면: 같은 로트 출고를 막고 격리한다 → 로트·제조일·출고일·점포·사진·보관과 배송 조건을 모아 품질 담당과 판단한다 → 같은 로트가 나간 점포를 추적한다 → 교환·회수·공지를 같은 기준으로 진행한다 → 공급사·3PL·점포 중 어느 단계 문제인지 구분해 재발을 막는다.
- 점주가 강하게 항의하면: 영업 영향부터 인정하고 주문·품목·수량을 확인한다. ERP 주문과 3PL 작업·운송 상태를 대조해 확정된 사실과 확인 중인 내용을 나눠 안내하고, 약속한 시간에 먼저 연락한다.
- 어필: 격리·추적·회수·증빙이 빠지지 않게 하는 습관
- 피할 것: 외식 제조 공정이나 HACCP 운영 경험이 있다는 말. 프랜차이즈 점포 CS 경험이 있다는 말

**Q5. ERP 구축 경험과 더존 iCUBE** (공고 6번)
- 패턴: 실제로 맡은 범위 → 테스트 방식 → 경계 → iCUBE 학습 계획 → 입사 후 역할
- 범위(경력란 `신규 ERP와 WMS 연계 기획 및 테스트 참여`): SKU ID 규칙을 정해 40종에 적용했다. 채널마다 다른 주문 양식을 하나로 모으는 수집 기준, 주문·상품 매핑, 세트 상품 묶음, 해외창고 WMS 연동, 통관사 API 필드 매핑의 요건을 정의했다.
- 테스트: 채널별 양식을 지킨 무작위 주문을 자동으로 만들고 수기 주문을 더해 약 100건을 돌리며 결과를 추적했다.
- 경계: 개발은 개발 담당이 했다. 구 코드와 병행 중이라 이관이 끝난 것은 아니다.
- iCUBE: 직접 써 본 적은 없다. 2024년 SAP 운영 교육에서 구매·판매·생산·회계 흐름을 실습했다. 입사하면 품목·거래처·창고 기준정보, 수주부터 출고·정산, 발주부터 입고·수불 흐름을 먼저 익히고 실물·WMS·전표를 함께 대조하겠다.
- 입사 후: "ERP 구축이나 전환 때 물류 현업의 기준을 정리하고 테스트하는 역할을 맡고 싶습니다."
- 어필: 기준정보(코드 체계)를 직접 정해 본 경험, 테스트 데이터를 직접 설계한 경험
- 피할 것: ERP 구축 완료나 단독 구축. iCUBE 사용 경험. 테스트 자동화

**짧게 답할 확인 질문**
- 운전: 공고의 필수 조건이다. 면허 종류와 실제 운전 가능 여부를 면접 전에 정해 한 문장으로 답한다(현재 미확인).
- 경력 2년: 제출본에는 아이베 1년 1개월만 있다. 그 전에 2024.08~2025.08 1년 계약직으로 글로벌 IT 기업 국내 지사의 3PL에서 출고와 배차를 맡았다. 식품이나 프랜차이즈 경력으로 바꿔 말하지 않는다.
- 리콜 기간: 이력서의 2026.04~07은 3자 대면 전면 폐기 기간이고, 리콜 대응 전체는 1월부터 7월까지다.
- 외식·점포 경험: 없다. B2B 고객사·공급사 조율과 영업·CS 회의 경험으로 답한다.
- 주임~대리 역할: 인력 관리 경험은 없다. 맡은 프로세스를 끝까지 추적하고 문제가 생기면 영향과 선택지를 정리해 제때 올리는 책임으로 이해한다.
- 학력·SAP: 2027년 2월 졸업 예정(4.0/4.5). SAP는 교육 이수이고 회사 환경 실무는 없다.

### 3-3. 마무리와 질문
