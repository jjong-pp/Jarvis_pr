## 3. 설계한 것

**공고 1건 처리 루프** (`공고처리_공정.md`)

```text
S0 입수 → S1 공고 분석 → S2 독립 평가 3종(병렬) → S3 종합 판정
   → [사용자 결정] → S4 전용 이력서·포트폴리오 계획 → S5 재검 1회 → S6 기록 → S7 결과 회고
```

- **평가자 3명은 서로의 결과와 공고분석을 읽지 않는다.** 앵커링을 막기 위해서다
- Claude는 `.claude/agents/fit-eval-intent · fit-eval-evidence · fit-eval-redteam`(Sonnet, 읽기 전용)으로 병렬 호출한다. GPT는 같은 역할카드를 순서대로 실행하되 이전 평가를 보지 않는다
- **재작업은 1회**만 한다. 두 번째에도 READY가 아니면 멈추고 쟁점만 보고한다
- 판정은 `지원 / 조건부 / 보류`. 합격 확률 숫자는 쓰지 않는다. 하드 게이트가 미확인이면 최대 조건부
- 기본은 **토큰 우선 모드**. 사용자가 `정밀`·`울트라`라고 할 때만 외부 조사와 상위 모델을 쓴다
- 엔진 분업 권장: 작성한 엔진과 재검하는 엔진을 다르게 둔다. 상태는 대화가 아니라 `지원현황.md`로 넘긴다

**증거 강도** E4 반복 측정·제3자 확인 / E3 운영·테스트 결과 / E2 산출물·설계 / E1 자기 주장 / E0 없음

**문서 규칙** 이력서는 MD 내용만 만든다(양식 입력은 사용자). PM 포트폴리오는 계획을 누적하다가 `PPT 반영` 지시가 있을 때 PPTX를 한 번에 수정한다. PDF는 만들지 않는다.
