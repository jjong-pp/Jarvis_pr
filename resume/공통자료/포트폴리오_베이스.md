## 3. 작성 규칙

- **장 구성 순서:** 문제의 근거 → 판단(대안·제외) → 정책·요구사항·흐름 → QA·운영 전환 → 결과와 한계.
- **화면 라벨:** 실제 운영 화면, 재구성 화면, 계획 화면을 장마다 구분해 적는다. 개발사 처리결과 화면은 `직접 운영 캡처 아님`을 적는다.
- **역할 표기:** 장마다 `기획·검수: 본인 / 구현: 개발사`처럼 역할 경계를 적는다.
- **마스킹:** 고객정보, 주문번호, 단가, 공급사 수는 넣지 않는다.
- **협력사 표기:** 실명 대신 역할명(자사몰 개발사, ERP 개발사, 물류 개발사, 통관대행사, 본인확인기관)을 쓴다.
- **수치:** 모든 수치 옆에 기간·모수·측정 상태를 붙인다(예: `직전 6개월 월평균 대비, 가동 후 약 1개월`).
- **디자인:** 기본틀의 레이아웃·폰트·색·사진 비율을 바꾸지 않는다. 텍스트는 도형 안에서 수직 중앙에 맞춘다(2026-09-17 교정). 장을 옮기거나 지우면 `NN / 24` 번호와 p2 목차를 함께 고친다.

## 6. 대시보드 화면 재사용

`../PM용/증거/submission_safe/scm_dashboard/2026-10-08_현재고_합성데이터.jpg`와 `2026-10-08_발주검토_합성데이터.jpg`는 원본 v1 앱의 격리 복제본에 합성 데이터를 넣어 캡처했다. 운영 DB·실제 수량·가격은 사용하지 않았다. 재고 화면의 초기화 순서·창고 ID 타입·상품코드 매핑만 격리본에서 보정했으며 원본 앱은 변경하지 않았다. 재사용할 때 `샘플 실행 화면 · 합성 데이터 시연` 라벨을 유지한다. 화면은 구현 흐름의 설명이며 운영 성과의 측정 근거가 아니다.
