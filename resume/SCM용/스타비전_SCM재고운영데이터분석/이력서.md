# 스타비전 SCM 재고운영·데이터 분석 이력서 문안

## 1. 간략 소개

저는 판매·입출고·재고·정산에서 문제가 생기면 데이터와 현장을 함께 확인하는 SCM 담당자입니다. 익숙하지 않은 일도 필요한 지식을 찾아 익히고, 관계자들과 실행 기준을 정해 실제 운영까지 이어왔습니다. 물류·SCM 약 2년 동안 글로벌 IT 부품의 출고·배차에서 시작해 현재는 글로벌 영유아 영양 브랜드의 직구·내수 약 40개 SKU를 담당하며 해외 발주부터 수입·입고·다채널 재고까지 관리하고 있습니다. 인구보건복지협회의 특수분유 판매분과 산후조리원 판매상품의 월 정산도 직접 수행했습니다. 반복되는 자료 취합은 AI 코딩 도구와 Python·SQL을 익혀 대시보드로 바꾸고, 회당 6~12시간 걸리던 작업을 1시간 이내로 줄였습니다. ERP 전환에서는 주문·상품 매핑과 WMS·통관 요건을 정리해 약 100건을 검수했습니다. 서로 다른 숫자의 기준을 맞추고 운영 가능한 방법을 찾는 경험으로 스타비전의 판매량·입출고·재고·정산 정확도를 높이겠습니다.

## 2. 지원동기 및 일하는 방향

스타비전의 SCM 조직은 협력사와 가맹점 사이의 물동, PB상품 재고, 정산과 시스템 운영을 함께 맡고 있습니다. 판매량, 실제 출고, 입고 예정, 현재 재고와 정산 기준이 서로 다른 자료에 머물면 정확한 공급 판단을 내리기 어렵습니다. 저는 약 40개 SKU의 판매 전망과 실제 출고량을 주·월간으로 비교하고, 수입 입고부터 주창고·3PL·B2B 등 여러 채널의 출고와 로트·유통기한 재고를 관리해 왔습니다. 인구보건복지협회의 특수분유 판매분과 산후조리원 판매상품을 매월 정산한 경험도 있습니다. 판매량 집계, 입출고, 재고 분석과 판매상품 정산이 한 흐름으로 이어지는 스타비전의 업무가 제가 경험을 쌓아 온 방향과 맞아 지원했습니다.

저는 처음 접하는 문제를 경험 부족으로 남겨두기보다 필요한 업무 지식과 시스템 구조부터 익힙니다. 판매실적과 재고 수불 기준 출고량의 차이를 구분하고, 발주번호·생산월·제품코드처럼 누락되기 쉬운 필드를 표준화한 것도 같은 방식이었습니다. 34개 탭으로 나뉜 자료는 AI 코딩 도구와 Python·SQL을 익혀 대시보드로 만들고 약 2개월간 기존 자료와 병행 검증했습니다. 신규 ERP 전환에서는 채널별 주문 양식, 주문·상품 매핑, SKU 세트, 해외 WMS·통관 API 필드의 요건을 정의하고 자동·수기 테스트 약 100건을 수행하며 결과를 추적하고 있습니다. 개발사의 구현과 제 역할인 현업 요건 정의·검수를 구분하면서도 실제 운영에서 발생할 예외는 끝까지 확인했습니다.

입사 후에는 스타비전 고유의 상품·가맹점·창고 기준정보와 판매·입고·출고·반품·정산 마감 규칙부터 정확히 익히겠습니다. 이후 반복 집계 항목과 불일치 유형을 정리해 재고 차이와 이상 물동을 조기에 확인할 수 있는 관리 흐름을 만들겠습니다. 담당자가 같은 수치를 다시 모으는 시간을 줄이고, PB상품의 재고와 정산 판단에 사용할 수 있는 일관된 데이터를 제공하겠습니다. 정확한 운영 데이터를 바탕으로 결품·과잉재고 위험을 빠르게 공유하고 스타비전의 재고 운영 속도와 의사결정 신뢰도를 높이는 것이 제가 만들고 싶은 영향입니다.

## 3. 성공·실패 경험과 배운 점

월간 SCM 회의를 준비할 때 판매, 발주, 입고, 출고, 재고 자료가 34개 탭에 나뉘어 있었습니다. 담당자가 복사와 필터링을 반복해야 해 한 번 취합하는 데 6~12시간이 걸렸고, 취합 1회당 데이터 값 오류 2~3건을 다시 확인해야 했습니다. 저는 기존 자료의 입력 항목과 사용 순서를 먼저 분석한 뒤 Python·FastAPI·SQL 기반 대시보드를 만들었습니다. 현업이 새 도구를 배우느라 업무가 멈추지 않도록 기존 엑셀 업로드 방식은 유지했고, 약 2개월 동안 기존 집계 결과와 새 화면을 병행 비교했습니다. 그 결과 취합 시간이 1시간 이내로 줄었고, 취합 과정의 오류는 약 3개월간 0건을 유지했습니다. 현재 직접 사용자는 4~5명이며 약 15명이 이 자료를 바탕으로 업무를 진행하고 있습니다.

그러나 처음부터 모든 데이터가 정확히 연결된 것은 아니었습니다. 일부 발주 자료에서 발주번호가 빠지거나 생산월이 서로 다른 형식으로 입력돼 특정 주문이 조회되지 않거나 잘못된 월에 잡혔습니다. 또 재고 차감에 쓰이는 출고량과 판매 실적을 같은 숫자로 보면 교환·샘플 출고 때문에 결과가 어긋났습니다. 저는 문제를 발견한 뒤 발주번호와 생산월 입력 규칙을 보완하고, 생산월을 동일한 날짜 형식으로 변환했습니다. 판매 실적과 재고 출고의 목적도 분리해 지표별 기준을 다시 정리했습니다. 결과 수치만 맞추기 위해 예외를 덮지 않고, 어떤 입력과 규칙에서 차이가 생겼는지 추적할 수 있게 한 조치였습니다.

이 경험을 통해 데이터 개선의 성패는 화면이나 코드의 완성도만으로 결정되지 않으며, 현업이 같은 기준으로 입력하고 결과를 검증할 수 있어야 한다는 점을 배웠습니다. 또한 자동화 전 병행 검증 기간을 두고, 오류를 유형별로 기록해야 운영 중 문제가 다시 생겼을 때 빠르게 원인을 찾을 수 있었습니다. 스타비전에서도 판매량·입출고·재고 자료의 정의와 마감 기준부터 확인하고, 사용자가 실제로 유지할 수 있는 방식으로 개선하겠습니다. 작은 불일치를 조기에 발견하고 수정하는 습관으로 재고 데이터의 신뢰도를 높이겠습니다.
