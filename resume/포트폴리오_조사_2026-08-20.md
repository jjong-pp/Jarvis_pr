# IT 서비스 기획자·PM 포트폴리오 조사 (2026-08-20)

조사 목적: 제출 형식·구성·주제·평가 역량을 확정해 `resume/` 제출본 작업의 기준으로 삼는다.
조사 범위: 국내 채용 미디어(잡코리아), 커리어 콘텐츠 플랫폼(PUBLY·프라임커리어·요즘IT), 현직자 브런치, 채용 트렌드 조사(원티드랩/전자신문).
한계: 원티드랩 조사를 제외하면 대부분 단일 필자 의견이며 표본이 공개되지 않는다. 수치는 "업계 통용 기준"이지 검증된 통계가 아니다.

---

## 1. 제출 형식

### 1-1. 파일 형식 — PDF 기본 + 링크 보조

| 형식 | 위치 | 근거 |
|---|---|---|
| PDF | **필수·기본 제출본** | 회사 내부망·보안 환경에서 노션/피그마/비핸스 링크가 열리지 않는 사례가 반복 보고됨 |
| 노션 | 보조 링크 | 기획자는 IA·플로우·정책표 등 첨부물이 많아 PPT보다 노션이 담기 쉬움 |
| PPT | PDF 변환 전제의 저작 도구 | 대기업·SI 계열에서 여전히 표준 |
| 피그마/비핸스 | UI 중심일 때만 보조 | 기획 직무에서는 부차적 |

- 노션 → PDF 변환 시 권장 설정: 형식 PDF, Include content = Everything, 페이지 크기 **A3**.
- 링크를 낼 때는 **공개 권한**을 반드시 재확인한다. 권한 오류 = 미제출로 처리된다.
- 파일명은 `이름_직무_회사_YYYYMM.pdf` 형태로 수신자가 식별 가능하게.

### 1-2. 분량 — 출처별로 갈린다 (그대로 기록)

| 출처 | 전체 분량 | 프로젝트당 |
|---|---|---|
| 잡코리아 (기획자 포폴 5단계) | 10~15p | 3~5장 |
| 잡코리아 (경력직 일반) | 10~18장 | 2~3장 |
| 프라임커리어 | 15~25p (신입·주니어) | 5~8p, 2~3개 |

**해석**: 하한은 10p, 상한은 25p. 10p 미만은 "사고 과정을 판단할 정보 부족", 40p 이상은 "완독되지 않음"이라는 진술이 공통이다.
회사 유형별 조정(프라임커리어): 스타트업 15~20p / 대기업 20~30p / 서류전형용 압축본 10~20p.
**실무 결론**: 서류용 15p 내외 압축본과 면접용 25p 확장본을 분리 관리한다.

### 1-3. 서류 세트 내 역할 분담 (중복 금지)

| 문서 | 담는 것 |
|---|---|
| 이력서 | 경력·스킬 요약 |
| 경력기술서 | 프로젝트별 정량 성과 |
| 자기소개서 | 지원 동기, 일하는 방식 |
| **포트폴리오** | **과정·방법론·의사결정 근거·산출물** |

같은 내용을 네 문서에 반복하는 것이 흔한 감점 요인이다.

## 2. 구성 — 표준 목차

### 2-1. 문서 전체 골격

```
표지 → 목차 → 자기소개/핵심 강점(1p) → 경력 요약(1p)
→ 대표 프로젝트 리스트(1p) → 프로젝트 상세 2~3개(각 3~8p)
→ 사용 툴·링크·연락처(1p)
```

- **자기소개 페이지는 "어떤 방식으로 일하는 사람인가"를 4~5개 키워드로** 압축한다. 실제 경험으로 증명 가능한 것만 넣는다.
- 첫 화면(표지 또는 1p)에 **대표 성과가 보여야 한다.** 채용담당자는 자기소개보다 대표 프로젝트와 핵심 임팩트를 먼저 본다.

### 2-2. 프로젝트 상세 — 5단계 서사 (가장 널리 통용되는 구조)

| 단계 | 내용 | 작성 지침 |
|---|---|---|
| ① 문제 정의 | **지표 → 원인 → 문제 정의** 순서 | "불편함 나열"이 아니라 어떤 사용자군의 어떤 행동 패턴인지 특정 |
| ② 가설 수립 | 해결 방향 + 검증 기준(A/B 테스트 등) | 가설이 틀릴 수 있음을 전제로 서술 |
| ③ 설계 / PRD | **핵심 스펙 3줄 + 와이어프레임 1장**으로 압축 | 전체 산출물 첨부 금지, 의사결정 핵심만 1p |
| ④ 실행·론칭 | 우선순위 충돌 조율 과정 | 제약(예산·기간·인력)과 트레이드오프를 명시 |
| ⑤ 임팩트 | 정량 결과 + 다음 액션 | 실패도 숨기지 않고 원인과 재발 방지를 함께 |

동일 구조를 모든 프로젝트에 **반복 적용**해야 읽는 사람이 비교할 수 있다.
변형 표기: `WHY / HOW / WHAT / RESULT / LEARN`, `문제 → 목표 → 내 역할 → 실행 과정 → 결과 수치` — 실질은 같다.

### 2-3. 성과 표현

- 나쁜 예: "검색 기능 개편 → UX 개선 → MAU 증가"
- 좋은 예: "검색 이탈률 12%p 상승 → 개인화 가중치 적용 → 전환율 +7.2%p"
- 수치가 없는 프로젝트도 변화량으로 표현 가능: 빈도(주 2회 → 주 5회), 시간(리뷰 사이클 5일 → 3일), 오류 건수 감소.
- **기여도는 백분율보다 담당 범위 서술이 설득력 있다.** 예: "가설 수립과 PRD 작성을 직접 담당, 디자인·개발 우선순위 조율에 참여".
- 론칭 전 무산된 프로젝트도 "PRD와 정책 설계"만으로 논리적 완결성을 보일 수 있다.

### 2-4. NDA·보안 자료 처리

빼지 말고 **비식별화**한다. 회사명·제품명·세부 수치를 `A사`, `B서비스`, `약 20%대 개선`으로 치환하고 문제 정의 → 기여도 → 결과 중심으로 재구성한다.
사내 화면설계서 원본·실제 화면 캡처는 그대로 붙이지 않는다. 재작도한 와이어프레임으로 대체한다.

## 3. 주제 — 어떤 프로젝트를 넣는가

### 3-1. 선정 기준 3가지

1. **JD 일치도** — 지원 직무·도메인과 연결되는가
2. **성과 임팩트** — 수치나 변화로 설명 가능한가
3. **역할 깊이** — 개인 기여가 분명한가

"많은 경험보다 일관성". 모든 프로젝트를 관통하는 한 문장(예: "사용자 리서치에 강한 PM", "현장 데이터로 프로세스를 재설계하는 기획자")을 정하고 그것을 반복 증명한다.

### 3-2. 선호되는 프로젝트 유형

| 유형 | 보여주는 역량 |
|---|---|
| 데이터 분석 기반 개선 (GA·SQL·대시보드) | 지표 해석, 가설 검증 |
| UX 개선 (사용자 인터뷰·사용성 테스트) | 사용자 이해, 리서치 |
| 신규 서비스 기획 (시장조사·타겟 분석) | 0→1 설계, 사업 감각 |
| 시스템·프로세스 개선 (ERP/WMS/OMS, 사내 시스템) | 복잡한 비즈니스 로직 구조화, 이해관계자 조율 |
| 외부 연동·정책 대응 (API 연동, 규제 대응) | 요구사항 정의, 제약 조건 하 설계 |

**연차별 무게중심 이동** — 주니어는 PRD·와이어프레임 등 설계 산출물, 9년차 이상은 "왜 이 프로젝트가 사업적으로 중요했는가"가 핵심이 된다.

### 3-3. 도메인 적합성

- 커머스: 매출 분석, 화면기획서 설계 능력
- 미디어: 콘텐츠 이해도
- 금융·핀테크: 프론트~백엔드 전반 기획 경험, 론칭 후 운영 경험
- **지원사의 고객이 누구인지(B2B/B2C, 화주사/포워더 등) 먼저 확정하고 그 관점의 경험을 앞에 세운다.**

### 3-4. 지원사 연결 페이지

합격 사례의 공통 요소로 **지원 회사 서비스를 직접 써본 경험 + 개선 아이디어 + 내 프로젝트와의 도메인 연결**을 1~2p로 붙이는 구성이 반복 언급된다. 범용 포트폴리오를 모든 공고에 그대로 제출하는 것이 대표적 탈락 패턴이다.

## 4. 평가 역량 — 무엇을 보는가

### 4-1. 채용담당자가 실제로 보는 5가지

1. **문제 정의 능력** — 솔루션이 아니라 문제에서 출발했는가
2. **사용자·시장 이해** — 근거 데이터가 있는가
3. **우선순위와 트레이드오프 판단** — 제약 하에서 무엇을 버렸는가
4. **협업·커뮤니케이션** — 이해관계자 갈등을 어떻게 풀었는가
5. **성과와 학습** — 임팩트를 어떻게 측정했고 무엇을 배웠는가

면접관의 판단 축은 **포지션 적합도 + 조직 적합도** 두 가지이며, 결과물의 완성도보다 **사고 과정과 의사결정 방식**을 본다.

### 4-2. 채용공고에 반복되는 자격요건

- 비즈니스 요구사항을 IT 시스템 관점으로 분석·기획하는 역량
- 요구사항 정의 및 이해관계자 조율
- 문서 작성·커뮤니케이션 능력
- 프론트엔드~백엔드 전반의 기획 경험, 론칭 후 운영 경험
- 데이터 분석·리서치 기반 출시·개선 경험
- SQL·Python 등 데이터 도구 기본 이해

### 4-3. 2026년 채용 시장 신호 (원티드랩 조사, 2025-12 발표)

| 항목 | 수치 |
|---|---|
| 직무 전문성 | 64.7% |
| 팀워크·협업 | 37.9% |
| 조직 기여 의지 | 28.1% |
| **AI·데이터 활용 역량** | **24.2% (4위)** |

선호 연차: 4~7년차 49.7% > 1~3년차 19.6% > 8~11년차 17.6% > 신입 12.4%. **중간 경력직 선호가 뚜렷하다.**

### 4-4. 탈락 패턴 5가지

1. 화면 중심 구성 — 와이어프레임·UI만 있고 비즈니스 근거 없음
2. 솔루션부터 시작 — "왜 이 문제인지"가 없음
3. 현실 제약 부재 — 예산·기간·인력 제약 언급 없는 이상적 프로젝트
4. 역할 모호 — "우리 팀이 했다"로만 서술
5. 회고 부재 — 성공만 있고 실패·학습이 없음

부차적이지만 실제로 걸러지는 것: 회사명·직무명 오타, 맞춤법, 링크 권한, 타 서류와 과도한 중복.
**전제 조건**: 기업은 이력서의 학력·경력을 먼저 보고 포트폴리오를 연다. 포트폴리오 완성도만으로는 기초 적합도 미스매치를 뒤집지 못한다.

## 5. 제출 전 체크리스트

- [ ] JD와 맞는 프로젝트만 선정했는가 (나열 아님)
- [ ] 각 프로젝트에 before/after 수치가 있는가
- [ ] 수치에 **측정 범위**를 붙였는가 (시범 적용/전사/통계 검증)
- [ ] 첫 화면에 대표 성과가 보이는가
- [ ] 내 역할과 담당 범위가 프로젝트마다 명시됐는가
- [ ] 제약 조건과 버린 선택지가 서술됐는가
- [ ] 실패·회고가 최소 1건 있는가
- [ ] PDF 변환 완료 + 링크 권한 확인
- [ ] 이력서·경력기술서·자소서와 중복 제거
- [ ] NDA 자료 비식별화
- [ ] 회사명·직무명·맞춤법 재검증
