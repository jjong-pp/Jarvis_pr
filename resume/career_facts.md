## 0. 이 파일을 쓰는 법

### 검증 상태

| 상태 | 의미 | 제출문 사용 |
|---|---|---|
| `USER_CONFIRMED` | 사용자가 직접 확정 | 가능 |
| `SOURCE_VERIFIED` | 저장소 정본 문서에서 확인 | 가능 |
| `INFERRED` | 문서에서 추론 | **해석에만. 제출문장 금지** |
| `UNVERIFIED` | 근거 미확보 | **사용 금지. 사용자 질문 목록으로** |
| `CONFLICT` | 문서 간 값이 다름 | **해결 전 전 산출물 차단** |

### 우선순위 (지침 0절)

1. 2026-08-28 이후 사용자가 직접 확정한 값
2. 각 프로젝트의 최신 통합 기획서·리스크 대장·처리결과 문서
3. 계약서·견적서·과거 발표자료

충돌하면 임의로 섞지 않는다. `CONFLICT`로 두고 사용자에게 올린다.

### 트랙

같은 사실이라도 공고에 따라 앞세우는 면이 다르다. 각 claim에 `track` 태그를 둔다.

- `L` = 대장·검증 트랙 (규제대응·SI·PMO·운영기획·다자조율 공고)
- `P` = 제품·성장 트랙 (스타트업 서비스PM·B2B커머스PM·SaaS PM 공고)
- `LP` = 양쪽 공통

> 동료와 브레인스토밍으로 구체화해 **별도 SaaS로 개설**했고, 개발은 동료가 맡고 나는 제품 정의·사용자 플로우·기술이 내야 할 결과물·AI 응답 정책·사업 방향을 맡았다. 현재 운영 중이다.

### 쓴다 / 쓰지 않는다

| 쓴다 | 쓰지 않는다 |
|---|---|
| 아이디어를 **발의하고 기획을 맡았다** | 혼자 만들었다 / 창업했다 |
| 원래 있던 로직을 **고도화**해 제품으로 세웠다 | 크롤링 기술을 개발했다 |
| 제품 정의 · 사용자 플로우 · 기술 산출물 정의 · AI 응답 정책 · 사업 방향 | 직접 개발했다 / 코드를 짰다 |
| 동료와 **함께** 낸 아이디어 | 내 단독 아이디어 |
| 등록 사용자 약 20명, 활성·유료 미확인 | 활성 20명 / 180명 / 700명 |
| 유료 파일럿 **검증 기준을 설계**했다 | 유료 검증 완료 / PMF / CAC 측정 |
| 사업개발비 **상한 가설** 150~300만원 | 집행했다 / 성과가 났다 |

**회사 자산이 아니다.** 아이베 사내 프로젝트로 쓰지 않는다. 동시에 "개인 단독 프로젝트"도 아니다 — 동료와 함께 낸 아이디어에서 출발한 별도 서비스다. 이력서 고용형태 표기는 이 사실에 맞춘다.
