# 간략 소개

SCM 현장에서 주문·재고·통관 업무를 맡으며, 운영상의 불편을 시스템 도입과 업무 개선으로 연결해 왔습니다. B2B 주문몰에서는 솔루션별 운영 부담과 유지보수 조건을 비교해 도입 범위를 정했고, 관세청 연동에서는 현업의 요구를 데이터 항목과 처리 기준으로 구체화해 개발사와 조율했습니다. 시스템을 사용하는 입장에서 쌓은 업무 이해와 컴퓨터 지식을 바탕으로, 고객이 필요한 기능과 도입 조건을 이해하고 선택할 수 있도록 돕는 IT 기술영업을 하고 싶습니다.

# 경력기술서

## 1. B2B 주문몰 솔루션 도입

- 기간: 2026.06~08
- 역할: 도입 대안 비교, 정책·요구사항 작성, 개발사 조율, 운영 적용 및 기능 확인. 개발 구현은 외부 개발사가 담당했습니다.
- 배경: 구글 설문 주문, 입금 내역, Excel 정산 자료가 나뉘어 있어 계약별 상품·결제 조건과 주문 상태를 반복 확인해야 했습니다.
- 실행: 맞춤형 개발, 다른 쇼핑몰 솔루션, 기존 고도몰5 활용안을 비교했습니다. 운영팀의 학습 부담, 기존 인프라, 유지보수 책임과 비용을 고려해 기존 솔루션에 계약별 정책을 추가하는 방식을 선택했습니다.
- 범위 조율: 네 가지 계정 유형별 상품·결제 기준을 정리했습니다. PG 결제와 견적서 신규 개발은 제외하고, 월말 포인트 정리는 담당자가 대상과 차감 결과를 확인한 뒤 실행하도록 조정했습니다.
- 적용: 2026.07.16 핵심 주문·입금·정산 흐름을 가동하고 08.31 최종 확인을 마쳤습니다. 개발사의 완료 통보 후에도 운영 서버에서 고객 화면과 예외 조건의 동작을 확인했습니다.
- 결과: 운영팀 출고·CS 이력의 전체 측정 범위에서 직전 6개월 오출고 월평균 2~3건 대비, 핵심 흐름 가동 후 약 1개월간 0건을 관찰했습니다.

## 2. ERP·물류·관세청 통관 연동

- 기간: 2026.02 기획 착수, 2026.08.28 운영 전환 후 운영 중
- 역할: SCM팀 내 프로젝트 PM으로 연동 요건 기획, 관계사 조율 및 운영 테스트를 담당했습니다.
- 실행: 자사몰·외부 채널의 주문·상품·수하인 정보가 ERP·WMS·통관 시스템으로 이어지는 흐름을 정리했습니다. 원주문과 분할 포장의 처리 단위를 구분하고 API 필드 매핑, 처리 상태, 오류 수정·재제출 기준을 문서화했습니다.
- 제약 조율: 국내 상품과 해외직구 상품이 섞인 주문의 내수 선출고를 검토했습니다. ERP가 원주문 단위로 처리하는 제약과 중복 위험을 확인한 뒤 선출고 요청을 철회하고, 해외직구 신고가 확정될 때까지 함께 보류하는 방안을 협의했습니다.
- 테스트: 운영 환경 30건 검증에서 정상 접수, 의도한 오류 반환, 수정 후 재제출을 기대 결과대로 확인했습니다.
- 운영 결과: 2026.08.28~09.15 집계의 일평균 약 300건 발생 주문에 대해 전체 통관 완료를 확인했습니다. 신규 연동과 기존 통관 방식을 함께 사용한 결과입니다.

# 자기소개와 일하는 방향

저는 해결되지 않은 문제를 그대로 두기보다 필요한 지식과 도구, 함께 해결할 사람을 찾아 방법을 만드는 편입니다. SCM 업무에서도 반복되는 자료 취합이나 담당자의 기억에 의존하는 주문 처리를 당연한 일로 넘기지 않았습니다. 직접 업무 흐름을 정리하고, 개발사에 설명할 요구사항을 만들거나 AI 코딩 도구를 활용해 개선 도구를 구현했습니다.

일을 진행할 때는 요청한 기능이 실제 업무에서 어떤 문제를 해결하는지 먼저 살핍니다. B2B 주문몰에서도 운영팀이 익숙한 환경과 유지보수 부담을 함께 비교했습니다. 포인트 처리는 계약 변경과 잘못된 차감 위험을 고려해 담당자 확인을 남겼습니다. 기능을 선택하는 과정에서 사용자의 업무, 도입 비용, 운영 책임을 함께 설명하는 일이 중요하다는 것을 배웠습니다.

문제가 보이면 관련 예외까지 해결하려다 범위를 넓히는 경향도 있습니다. 이를 보완하기 위해 B2B 도입에서는 PG 결제와 견적서 신규 개발을 제외하고 핵심 주문 흐름부터 적용했습니다. 필요한 개선을 계속 찾되, 이번에 해결할 범위와 이후 과제를 구분하려고 합니다.

기술영업에서도 고객이 현재 어떤 방식으로 일하고 어디에서 어려움을 겪는지부터 이해하겠습니다. 현업의 말을 기술 담당자가 확인할 수 있는 요구사항으로 정리하고, 가능한 기능과 추가 개발이 필요한 범위를 구분해 설명하고 싶습니다. 제품 지식을 꾸준히 익히면서 고객이 도입 여부를 판단할 근거를 제공하고, 합의한 내용이 실제 업무에 적용되는 과정까지 책임 있게 연결하겠습니다.

# 성공과 실패 경험

## 성공 경험: 동료가 실제 업무에 쓰는 도구로 개선

발주 검토 자료를 취합할 때 한 사람이 3~4일에 걸쳐 약 6~12시간을 쓰고 있었습니다. 이 반복을 줄이기 위해 판매·출고·재고·입고계획을 모으는 대시보드를 직접 기획·구축했습니다. 기존 Excel 양식을 업로드하는 방식으로 시작해, 팀원들이 익숙한 업무 흐름을 활용할 수 있게 했습니다.

2026년 4월 시범 배포 후 약 두 달간 기존 시트와 결과를 대조했습니다. 팀원들의 사용 의견을 반영해 창고·유통기한별 재고 조회와 직접 입력·수정·삭제 기능을 보완하고, 판매실적과 실제 재고가 줄어드는 출고량의 차이도 구분해 설명했습니다. 운영 중에는 생산발주·입고 자료의 컬럼과 생산월 날짜 형식을 정비해 자료를 해석하는 기준을 맞췄습니다.

6월부터 취합 자료를 월간 발주 검토의 기준으로 사용했고, 시범·병행 기간을 포함해 4~8월 다섯 차례 발주 검토에 활용했습니다. 자료 취합은 Excel 업로드와 결과 확인까지 1시간 이내로 줄었습니다. 이 경험에서 업무 개선 도구의 가치는 실제 사용자가 자료를 이해하고 자신의 업무에 활용할 수 있을 때 생긴다는 점을 배웠습니다.

## 실패 경험: 화면에서 없앤 항목이 현장에서는 필요했던 일

B2B 주문몰의 1차 QA에서 배송 메시지 입력칸을 제거했지만, 운영 피드백을 통해 배송 시 요청을 받는 데 필요한 항목이라는 점을 확인했습니다. 화면에서 덜어낸 요소가 실제 주문·배송 업무에서는 필요한 정보였고, 입력칸을 다시 반영했습니다.

같은 과정에서 거래명세서도 고객이 자주 사용하는 주문내역에서 바로 출력할 수 있도록 조정했습니다. 화면의 구성뿐 아니라 주문 이후 담당자가 어떤 정보를 확인하고 사용하는지까지 살펴야 한다는 점을 배웠습니다.

기술영업에서 솔루션을 제안할 때도 기능 목록만으로 적합성을 판단하지 않겠습니다. 실제 사용자와 운영 담당자의 업무 순서를 함께 확인하고, 도입 후 필요한 정보나 작업이 빠지지 않도록 적용 조건을 구체화하겠습니다.
