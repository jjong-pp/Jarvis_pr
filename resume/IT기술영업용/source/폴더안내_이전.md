# 기술영업 이력서

갱신일: 2026-09-18. 업무용 솔루션 기술영업 지원을 위한 범용 이력서다. 사내 도입을 추진한 경험을 **업무 파악 → 도입 대안 → 적용 범위 → 기술·운영 조율 → 검수·결과** 순서로 설명한다.

## 현재 파일

| 용도 | 파일 |
|---|---|
| 계속 수정할 원고 | [source/이력서.md](source/이력서.md) |
| 내용과 순서 기준 | [source/구성.md](source/구성.md) |
| 현재 이력서 PDF | [박종혁_기술영업_이력서.pdf](output/박종혁_기술영업_이력서.pdf) |
| 같은 내용의 Word 출력 | [박종혁_기술영업_이력서.docx](output/박종혁_기술영업_이력서.docx) |
| 내부 문장 근거 | [source/문장근거.md](source/문장근거.md) |

1쪽은 소개·SCM 실무 경력·B2B 솔루션 도입 사례, 2쪽은 관세청 연동 사례·기술 활용·학력·수상으로 구성했다. 기존 PM 지향 소개를 기술영업 지원 방향으로 바꾸고, 사실 확인이 끝난 기간·역할·관찰 범위만 썼다. 면접 질문·시뮬레이션·긴 자기소개서는 포함하지 않는다.

## 계속 수정하는 방법

1. 새 경력·기간·성과가 생기면 [공통 경력 원장](../공통자료/career_facts.md)을 먼저 갱신한다. 연락처 변경은 `../공통자료/profile.json`에서 한다.
2. `source/이력서.md`의 문장을 수정한다. 사실 값은 공통 원장에서 가져오고, 해당 회사의 제품·고객·업무에 맞는 강조점만 바꾼다.
3. `source/재생성.ps1`을 실행하거나 이 작업에서 재출력을 요청한다. Word와 PDF를 같은 원고에서 생성하고, 교체 전 출력은 `versions/날짜_시간/`에 보관한다. 생성 환경은 번들 Python과 설치된 Microsoft Word다. 다른 기기에서는 스크립트의 Python 인수와 Word 설치 여부를 확인한다.
4. 새 PDF의 모든 쪽에서 누락·잘림·줄바꿈과 수치·기간을 확인한다. **Word·PDF를 따로 수정한 내용은 원고에 자동 반영되지 않으므로 문장 수정은 MD에 먼저 적용한다.**

본문의 연락처 토큰은 실제 Word·PDF를 만들 때 공통 연락처로 채운다. 문장근거·검수 기록에는 개인정보 값을 넣지 않는다.

## 보관 자료

- `검토대상/`: 사용자가 지정했던 기존 이력서와 22쪽 포트폴리오. 원본이며 현재 기술영업 이력서로 사용하지 않는다.
- `versions/`: 교체 전 출력과 생성 당시 원고 스냅샷. 현재 제출본이 아니다.
- `.qa/`: 문서 생성·화면 확인에 사용하는 내부 기록.

포트폴리오는 이번 작업에서 다시 만들지 않았다. 지정 22쪽 원본의 공급사 수 공개 제한과 기술영업용 첫 요약·순서 수정은 아직 남아 있다. 최신 이력서와 예전 포트폴리오를 검수 없이 묶지 않는다. 현재 이력서는 범용본이며 특정 회사의 자격 충족이나 외부 제출을 확정한 상태는 아니다.
