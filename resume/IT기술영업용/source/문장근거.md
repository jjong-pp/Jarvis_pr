# IT 기술영업 이력서 문장 근거

작성일: 2026-09-18. 대상: [이력서 원고](이력서.md). 이 파일은 내부 편집용이며 제출 PDF에 포함하지 않는다.

사실·수치·역할의 정본은 [SCM_업무성과.md](../../공통자료/SCM_업무성과.md)와 [PM_프로젝트성과.md](../../공통자료/PM_프로젝트성과.md)다(2026-09-23 이관, claim ID 동일). 아래 표는 정본을 복제하는 원장이 아니라 제출문이 참조한 claim의 연결표다. 수정 시 정본의 검증 상태와 후속 정정을 먼저 확인한다.

## 구성 의도

소개 → 공식 경력과 현업 범위 → B2B 도입 대안 비교 → 통관 연동 요건 조율 → 기술 활용 → 학력·수상 순서다. 사내 운영 담당자로 수행한 도입 경험을 ERP·물류·커머스 기술영업 지원 의도와 연결한다. 별도 자기소개서나 면접 질문은 포함하지 않는다.

원고의 `pagebreak`는 2쪽 편집을 위한 구분점이다. 1쪽은 소개·경력·B2B 도입, 2쪽은 통관 연동·기술·학력으로 배치한다. 이름 외 연락처·이메일은 자리토큰으로 보관하고 실제 제출 PDF를 만들 때 공통 개인정보에서 주입한다.

## 제외와 정본 우선 적용

- 비교 기간과 동일 업무 범위가 미확인인 정산 시간(C-041), 관계사 수(C-023), BIGSEE 시작월(C-051), 미확인 Figma·Notion·Jira·Confluence 태그를 사용하지 않았다.
- 신규고객 발굴·고객 데모·수주·매출·가격 협상·PoC·CRM 실적은 근거가 없어 추가하지 않았다. 본문의 도입 대안 비교와 검수는 사내 현업 담당자의 경험이다.
- 원장 C-029의 2026-09-17 정정은 customs 스킬의 2026-08-28 `HBL=TRA001 1건` 설명보다 최신이다. 원고는 최신 원장에 따라 원주문과 분할 포장을 구분하고 내부 필드명은 적지 않았다.
- 대시보드는 C-119의 자동취합·조회 콘셉트를 적용했다. 과거 재고 예측 기간·예측 정확도 분석은 재사용하지 않았다.
- 원문 PDF와 경력 원장을 변경하지 않았으며, 이번 원고가 사실 확정의 새 원장이 되지 않는다.
