# 비나우 자기소개서

## 1. 본인이 어떤 사람인지 소개하고 비나우에 지원한 동기를 설명해주세요.

저는 해결되지 않은 문제를 그대로 두지 못하는 사람입니다. 정해진 답이 없어도 필요한 지식을 익히고, 쓸 수 있는 도구와 함께 움직일 사람을 찾아 끝까지 해결 방법을 만듭니다. 문제를 해결한 뒤에도 운영 과정에 남은 불편을 다시 살피고 후속 과제로 정합니다. 그 결과 스스로 할 일을 늘리는 경우가 많지만, 더 나은 흐름을 만드는 과정에서 동기를 얻습니다.

관세청 통관 연동을 PM 역할로 주도할 때도 정해진 해법은 없었습니다. 주문이 ERP와 창고를 거쳐 통관·배송되려면 오류 주문을 어디서 멈추고, 어떤 정보를 보완한 뒤 다시 처리할지 새로 정해야 했습니다. 저는 ERP의 주문·상품 정보, 창고 출고, 통관, 택배 배송 지식에 컴퓨터 지식을 더해 처리 기준을 데이터 항목과 시스템 조건으로 바꿨습니다. 개발사·물류사·통관대행사와 요건을 조율하고, 정상 접수·오류 조건에서 예상한 응답·수정 후 재제출을 포함한 운영환경 시나리오 30건으로 검증했습니다.

운영 전환 후에는 신규 연동과 기존 통관 방식을 병행하며 오류 주문을 관리했습니다. 고객에게 보완 정보를 받는 과정의 불편을 줄이기 위한 웹서비스도 후속 과제로 기획하고 있습니다. 실제 운영에서 다시 막히는 지점을 찾아 다음 개선으로 연결한 사례입니다.

현재 SCM 업무에서도 반복되는 자료 취합을 당연한 일로 남겨두지 않았습니다. 약 40개 SKU의 판매·출고·재고·입고계획을 모으는 대시보드를 직접 기획·개발하고, 사용자 의견과 원천 자료의 양식 차이를 반영해 실제 발주 검토에 쓰이도록 개선했습니다.

비나우에 지원한 이유는 이러한 문제 해결 방식을 여러 자체 브랜드의 판매계획과 공급운영 전 과정에서 이어갈 수 있기 때문입니다. 넘버즈인·퓌·노크의 신제품과 프로모션, 채널별 판매 변화가 발주·생산·입고로 연결되도록 각 단계의 기준을 맞추고 실행까지 책임지고 싶습니다. 이후에는 해외 채널 공급과 수출까지 담당 범위를 넓히며 더 복잡한 공급 문제를 해결하겠습니다.

## 2. 가장 치열하게 노력했던 성공 또는 실패 경험과 그 과정에서 배운 점을 소개해주세요.

매달 반복되는 자료 취합을 줄이려고 만든 대시보드는 입력 방식과 데이터 기준까지 고치는 작업으로 이어졌습니다. 약 40개 SKU의 판매·출고·재고·입고계획을 모으는 데 한 사람이 3~4일에 걸쳐 약 6~12시간을 쓰고 있었습니다. 이 반복을 줄이기 위해 컴퓨터 지식과 AI 코딩 도구를 활용해 자동취합 대시보드를 직접 기획·개발했습니다.

2026년 4월 시범 배포 후 약 두 달간 기존 시트와 업로드 결과를 함께 대조했습니다. 도입 방식은 기존 Excel 업로드를 유지했습니다. 팀원들이 자료를 확인하는 순서와 사용 의견을 반영해 창고별 유통기한 재고를 함께 볼 수 있게 하고, 각 데이터의 의미와 확인 방법을 설명했습니다. 담당자가 데이터를 직접 고칠 수 있도록 입력·수정·삭제 기능을 추가하고, 가중치를 바꾸며 재고 흐름을 확인할 수 있게 했습니다.

도입 후 운영하는 동안에는 원천 자료의 양식 차이도 별도로 다뤘습니다. 생산발주와 입고 양식의 PO 번호·생산월 컬럼이 맞지 않아 입고 예정 SKU가 빠지거나 다른 월에 반영됐습니다. 새 양식을 마련해 컬럼을 정비하고, 한글 연·월로 적던 생산월을 ‘2026-08-01’처럼 일자를 1일로 고정한 날짜 형식으로 통일해 비교 기준을 맞췄습니다.

숫자의 의미도 구분했습니다. 교환 출고나 영업용 사용은 재고가 줄어도 판매실적에 잡히지 않았습니다. 팀의 재고 검토에 필요한 출고량을 반영하도록 판매실적과 출고량을 나눠 관리했습니다. 화면을 사용하는 사람이 어떤 숫자를 보고 있는지 이해하고, 필요하면 확인·조정할 수 있도록 보완했습니다.

6월부터 취합 자료를 월간 발주 검토의 기준으로 사용했습니다. 시범·병행 기간을 포함해 4~8월 다섯 차례 발주 검토에 활용했고, 자료 취합은 업로드와 결과 확인까지 1시간 이내로 줄었습니다.

처음에는 반복 취합을 줄이는 것이 목표였습니다. 그러나 함께 쓰는 도구가 실제 업무에 자리 잡으려면 입력 양식과 숫자의 의미, 팀원들이 자료를 확인하는 방식까지 맞춰야 했습니다. 제가 편한 화면을 만드는 데서 끝내지 않고, 동료가 숫자를 이해하고 발주 검토에 활용할 수 있도록 설명하고 사용 의견을 반영하는 일까지 맡아야 한다는 점을 배웠습니다.
