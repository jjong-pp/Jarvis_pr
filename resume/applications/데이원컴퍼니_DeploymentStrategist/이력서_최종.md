### 2. 통관 데이터 연동 — 다섯 개 회사가 같은 말을 쓰게 만들기

`2026.02 ~ 2026.08 · 개발비 약 4,000만 원`
`데이터를 나눠 가진 네 주체 · 조율한 회사 다섯 곳`

**상황** — 법령이 바뀌어 없던 제출 절차를 만들어야 했습니다. 그런데 주문 한 건의 데이터가 자사몰·본인확인기관·해외 ERP·통관대행사 네 곳에 나뉘어 있어, 어디도 신고 한 건을 혼자 완성할 수 없었습니다.

**어떻게 정의했나** — 기능 요구가 아니라 데이터 소유권과 책임의 문제로 정의했습니다. 이 정의가 이후 모든 대안 비교의 판단 기준이 됐습니다. 해외 ERP 중심 통제·기존 수기 유지·국내 DB 중심 통제 세 안을 비교하고, 판단 기준을 ① 개인정보 최소화 ② 제출 상태 통제 가능성 ③ 원천별 책임 분리 ④ 개발 난이도 순으로 고정했습니다.

**번역 작업** — 필드가 아니라 **값의 의미**를 고정하는 데이터 계약을 만들었습니다. 고객 최종 결제액과 운송장별 신고가액을 분리하고, 원주문번호와 분할번호·운송장을 별도 식별자로 유지하고, 인증 정보는 해외 시스템에 넘기지 않고 국내에서 직접 전달하도록 했습니다. 이 매핑표가 세 개발사의 개발 범위와 책임 경계를 정하는 기준 문서가 됐습니다.

실제로 막힌 지점도 뚫었습니다. ERP 개발사 쪽은 세관 제출용 로직과 정보 조회용 로직이 따로 돌아 데이터를 불러오는 데 시간이 걸렸는데, 두 로직을 잇는 중간 API를 새로 정의해 조회 경로를 하나로 만들었습니다. 통관대행사 쪽은 API 필수값이 제출 기준에만 맞춰져 있어 데이터를 취합하는 쪽 로직과 맞지 않았고, 용도별로 API를 분리해 달라고 요청했습니다.

**결과** — 운영 환경에서 30건을 검증해 테스트 목적 30/30을 통과했습니다(정상 접수 / 의도한 오류 반환 / 수정 후 재제출 성공). 리스크·질의 대장에 해결·기준확정 46건을 기록했고, 오픈 이틀 전 기준 잔여 P0 4건을 부풀리지 않고 그대로 남겼습니다.

**틀렸던 것** — 처음에는 관계사별로 개별 협의만 해도 맞출 수 있다고 봤습니다. 각 사가 대외비를 이유로 자기 몫의 필드와 내부 로직만 공유하면서 데이터 소유권과 인터페이스 불일치가 뒤늦게 드러났고 일정이 반복해서 밀렸습니다. 전체 흐름·필드 매핑·책임 구분·리스크 대장을 하나로 통합해 공동 검토로 전환한 뒤에야 원인이 잡혔고, 결과적으로 대외비 문제는 없었습니다.

### 3. B2B 주문 시스템 — 현업 워크플로를 통째로 바꾼 건

`2026.06 기획 → 07.02 개발 착수 → 07.16 핵심 서비스 전체 가동 → 08.31 최종 검수`
`계약처 약 140개소 · 공급사 5곳`

30개소에서 굴러가던 구글 폼·시트·통장 대조가 140개소에서 무너졌습니다. 매일 입금 대조 15~30분, 월말 정산 2명 × 약 7시간, 오출고 월 2~3건이 나왔습니다.

계약 예외를 코드가 아니라 `등급 × 카테고리` 관리자 설정값으로 분해해, 새 계약이 생겨도 개발 없이 대응할 수 있게 만들었습니다. 하나의 주문 데이터를 조리원 담당자·내부 운영팀·공급사가 권한에 따라 다른 범위로 보도록 정보 구조를 설계했습니다.

**결과** *(핵심 흐름을 07-16 전체 가동해 관찰한 값)* — 오출고 월 2~3건 → 0건(전체 측정 범위, 직전 6개월 월평균 대비 가동 후 약 1개월), 월말 정산 2명 × 약 7시간 → 1명 × 30~60분, 배송·주문·입금 문의 2주 32건 → 19건(초기 관찰값). 계약상 기본 개발요구 22건은 08-31 최종 검수를 기준으로 QA를 이어갔습니다.

배포 후 추가한 기능 셋은 전부 실제 업무를 보는 사람의 요청에서 나왔습니다. 기획서에는 없던 패턴이었습니다.

동료와 함께 낸 아이디어에서 출발해 별도 서비스로 개설했고 운영 중입니다. 저는 제품 정의, 사용자 흐름, 기술이 내야 할 결과물의 정의, AI 응답 정책, 사업 방향을 맡고 구현은 동료가 전담했습니다.

가설 14건에 각각 시험 방법·통과 기준·현재 증거·상태를 붙이고 증거를 A/B/C로 등급화했습니다. 실행 도중 가설 하나를 폐기하고 다른 설계로 대체했으며, 상태를 '수정'으로 남기고 지우지 않았습니다. 등록 사용자는 약 20명이고 활성·유료 여부는 확인되지 않았습니다.

AI 생성물의 품질 기준도 정했습니다. 모든 조사 결과에 출처·수집일·호출비용을 기록하고, 출처가 없는 값은 생성 입력으로 쓸 수 없게 차단하고, 확인되지 않은 값은 공백이 아니라 `UNKNOWN`으로 표기하도록 했습니다. 생성물은 사람 승인 전에 캠페인으로 나갈 수 없게 하고 승인자·승인 시각·버전 이력을 남기도록 설계했습니다.
