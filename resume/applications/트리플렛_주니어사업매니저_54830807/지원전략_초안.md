# 트리플렛 지원전략 초안

- 기준일: 2026-09-15
- 판정: `보류/BLOCK`
- 재개 조건: 경력증명 가능한 과거 실무를 합쳐 최소 2년이 되거나, 채용사가 총 경력 1년도 검토한다고 확인된 경우

## 1. 지원 목적

이 공고를 `제품 PM 입사`로 설명하지 않는다. 지원 목적은 다음처럼 잡는다.

> 현업·고객·개발조직 사이에서 요구사항과 후속 조치를 관리해 온 경험을 바탕으로, AI 솔루션의 수주부터 납품까지 배우고 프로젝트 PM 또는 기술영업으로 성장한다.

회사의 오프라인 AI 기술 자체보다 `현장 요구를 기술팀이 실행할 수 있는 문서와 과제로 바꾸는 역할`과 후보자의 경험을 연결한다.

## 2. 핵심 메시지

### 이력서 헤드라인

> 고객·관계사 요청을 요구사항과 검증 기준으로 정리해 운영까지 연결한 사업 운영 실무자

### 요약 초안

> 아이베 SCM팀에서 고객사·공급사·물류사·개발 파트너의 요청을 조율하고, 요구사항과 결정 상태를 문서로 관리해 왔습니다. 관세청 전자상거래 통관 API 연동에서는 관계사별 요건과 오류 수정·재제출 기준을 정리하고 운영 환경 검증까지 수행했습니다. 컴퓨터소프트웨어 전공과 생성형 AI 도구를 활용해 수요·재고 대시보드도 직접 구현·배포하며 현업과 기술 사이의 번역 역량을 넓혀 왔습니다.

### 지원동기 중심 문장

> 트리플렛의 솔루션은 관광지·물류시설·리테일 등 서로 다른 현장에서 수주부터 납품까지 이어집니다. 저는 규정·주문·재고처럼 서로 다른 언어를 쓰는 이해관계자의 요청을 요건과 검증 기준으로 바꾸고, 실제 운영에서 확인될 때까지 추적해 왔습니다. 이 경험을 AI 솔루션의 고객·기술 커뮤니케이션으로 확장하고자 지원합니다.

## 3. 이력서 구성

1. 지원 직무와 핵심 요약
2. 아이베 경력: 관계자 조율·요구사항·후속 조치·운영 검증 순서
3. 대표 프로젝트
   - 관세청 전자상거래 통관 API 연동
   - 수요·재고 대시보드
   - 산후조리원 B2B 폐쇄몰
4. 학력·기술: 컴퓨터소프트웨어과, AI·데이터과학부 재학, Python·FastAPI·SQLAlchemy·SQLite 등 실제 사용 도구
5. 프로젝트 관리 산출물: 리스크·질의대장, 정책 결정 이력, 필드 매핑표, UAT·운영 검증

`PM 철학`, BIGSEE의 미검증 시장 가설, 수요예측 세부 공식은 뺀다. 경력기간은 `2025.09.08~재직 중, 총 1년`으로 정확히 기재한다.

## 4. 포트폴리오 구성

별도 첨부가 허용되더라도 기존 22장 PM 포트폴리오를 그대로 제출하지 않는다. 트리플렛용 4~6장 사례 요약 PDF가 더 적합하다. 첨부가 불가능하면 같은 증거를 사람인 이력서 프로젝트란에 압축한다.

| 장 | 내용 | 공고 대응 |
|---|---|---|
| 1 | 지원자 요약과 세 가지 대응 역량 | 기록·조율·기술 이해 |
| 2 | 관세 프로젝트 관계자 요청→질의→결정→담당자→상태 구조 | 회의·요구사항·후속 액션 |
| 3 | 관세 오류 수정·재제출과 운영 환경 30건 검증 | 기술 요건 전달·오류 재처리·운영 검증 |
| 4 | 수요·재고 대시보드: 기존 양식 유지, AI 도구 활용 구현, 2개월 병행 이관 | IT·AI 학습과 문서·데이터 활용 |
| 5 | B2B몰: 고객사·공급사 요청과 완료 기준 관리 | 프로젝트 보조 PM 가능성 |
| 6 | 입사 후 기여: 정확한 회의 기록, 담당자·기한·상태 추적, 기술자료 학습 | 초기 6개월 업무 직접 대응 |

실제 산출물은 회사·개인정보·단가·주문번호·API 상세를 마스킹하고, 재구성 자료에는 재구성 라벨을 붙인다.

## 5. 제출하지 않을 자료

- 마켓빅시 서비스 정책 정의서: 이 공고와 직접 관련성이 낮고 현행·기획 정책 정본 문제가 남아 있음
- 기존 22장 포트폴리오 원본: BIGSEE 중심 순서가 이 공고와 맞지 않음
- 내부 발주금액·거래처 수·계약 단가·개발비·API 필드 상세
- `총괄 PM`, `기술영업 경험`, `AI가 수요를 예측했다`처럼 확인 범위를 넘는 표현

## 6. 면접에서 확인할 회사 조건

1. 대표·이사와 Business Associate의 의사결정·보고 관계
2. 첫 6개월 중 회의록·회신 추적과 프로젝트 일정·범위 관리의 실제 비중
3. 단독 PM 전환 기준과 기존 전환 사례
4. 기술영업 트랙 선택 여부와 수주 목표 부여 시점
5. 고객 현장 출장, 장비 설치, 야간·주말 대응 빈도
6. 근무시간, 수습 급여, 연봉 범위, 성과급
