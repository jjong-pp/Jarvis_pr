## 본문

안녕하세요, 과장님.

협력사별 관세청 연계 운영 여부 차이로 인해 개인통관고유부호가 누락된 상태로 자사몰에 수집된 주문이 다수 발생하여, 운영 공백을 해소할 임시 웹 서비스 개발을 요청드립니다.

첨부한 `20260831_통관번호 누락.xlsx`를 확인한 결과 총 91개 행, 90개 주문이며, 이 중 개인통관고유부호가 비어 있는 주문은 32건(회원 31명)입니다. 동일 주문의 복수 상품행이 포함될 수 있으므로 주문번호 기준으로 처리해 주시기 바랍니다.

가장 빠른 구축을 위해 아래 기능을 우선 범위로 검토 부탁드립니다.

### 1. 내부 운영 화면

1. CS팀이 사용하는 첨부 엑셀 양식 업로드
2. 주문번호 및 회원 아이디 기준 주문 목록 표시
3. 회원 아이디를 기준으로 자사몰 회원정보에 저장된 개인통관고유부호 조회
4. 조회값이 있으면 후보값으로 표시하고, 수취인 정보 일치 확인 또는 별도 유효성 검증 후 결과 화면과 다운로드 파일에 반영
5. 조회값이 없으면 `고객입력 필요`로 분류하고 알림톡 발송 대상 생성
6. 처리상태, 발송일시, 고객입력일시, 개인통관고유부호 반영 결과를 포함한 엑셀 다운로드
7. 동일 주문 또는 동일 회원의 중복 업로드·중복 발송 방지

처리상태는 주문번호별로 관리하고, 동일 회원이라도 수취인 정보가 다른 주문은 별도 건으로 처리해 주시기 바랍니다. 알림을 한 번으로 묶는 경우에는 동일 수입자임이 확인된 주문에만 적용해 주십시오.

첨부 Open API 명세상 주문조회 API(`Order_Search.php`) 응답에서 `memId`와 주문추가정보 `addField`는 조회할 수 있습니다. 다만 회원정보에 저장된 개인통관고유부호를 회원 아이디로 조회하는 전용 API와 기존 주문의 `addField`를 수정하는 API는 첨부 명세에서 확인되지 않았습니다. 해당 값은 자사몰 내부 DB 조회 또는 별도 커스텀 API 개발이 필요한지 검토 부탁드립니다. 1차 최소 기능에서는 자사몰 주문 원본을 직접 수정하지 않고, 검증된 결과를 화면과 다운로드 파일에 반영하는 범위로 요청드립니다.

회원정보에 저장된 부호가 현재 주문의 실제 수취인 부호와 다를 수 있으므로 회원 아이디 조회값을 곧바로 확정값으로 사용하지 말고, 수취인 성명·연락처·우편번호 일치 확인 또는 별도 유효성 검증을 거쳐 사용해 주시기 바랍니다.

### 2. 고객 입력 화면

회원정보에 개인통관고유부호가 없거나 후보값을 확정할 수 없는 경우 고도몰 카카오톡 알림톡으로 고객 전용 URL과 접근번호를 발송하고, 고객이 아래 절차로 직접 입력할 수 있도록 요청드립니다.

1. 고객별 일회성 URL 접속
2. 알림톡으로 받은 접근번호 입력
3. 본인 주문정보 확인
4. 개인통관고유부호 입력 및 저장
5. 이번 주문의 통관 처리용 정보로 저장하고 완료 안내 후 링크 만료
6. 내부 운영 화면의 처리상태를 `고객입력 완료`로 변경하고 엑셀 다운로드 값에 반영

고객 화면에는 주문번호, 주문일자, 상품 요약, 수취인 이름, 연락처 및 배송지의 일부 마스킹 정보만 표시해 고객이 본인 주문인지 확인할 수 있게 해주시기 바랍니다. 개인통관고유부호는 P 또는 O로 시작하는 13자리 형식을 1차 검증하고, 동일 요청의 중복 저장이 발생하지 않도록 처리 부탁드립니다.

### 3. 알림톡 발송

첨부 Open API 명세에는 일반 알림톡 발송 API가 포함되어 있지 않으므로, 현재 자사몰에서 사용하는 고도몰 알림톡 발송 기능 또는 기존 발송 연동을 활용할 수 있는지 확인 부탁드립니다. 알림톡 템플릿 승인과 발신 프로필 설정이 별도로 필요한 경우 필요한 정보와 일정을 회신 부탁드립니다.

고객 안내 문구 초안은 아래와 같습니다.

> [뉴트리시아몰] 주문정보 수집 과정에서 주문번호 {마스킹 주문번호}의 개인통관고유부호가 누락되었습니다. 아래 링크에서 주문정보를 확인한 후 개인통관고유부호를 입력해 주세요.  
> 입력 URL: {고객 전용 URL}  
> 접근번호: {일회성 접근번호}  
> 입력하신 정보는 해당 주문의 통관 처리 목적으로만 이용하며, 관련 법령 및 회사 정책에 따라 안전하게 보호·파기합니다.

원인이 확정되지 않은 상태에서 고객에게 `관세청 서버 오류`라고 단정하지 않도록 최종 발송 문구는 `주문정보 수집 과정에서 개인통관고유부호가 누락되었습니다`로 중립적으로 조정해 주시기 바랍니다.

### 4. 개인정보 및 보안 필수사항

개인통관고유부호는 도용 및 통관 오처리 위험이 큰 개인정보이므로 아래 보호조치를 반영 부탁드립니다.

1. 고객 입력 전 수집·이용 목적, 수집 항목, 보유·이용기간, 처리 근거를 안내하고, 별도 동의가 필요한지는 내부 개인정보 담당자 검토 후 확정
2. 전체 구간 HTTPS 적용
3. URL 또는 로그에 개인통관고유부호·전화번호 등 개인정보를 평문으로 포함하지 않음
4. 개인통관고유부호 저장 시 암호화하고 화면·로그·다운로드 권한을 최소화
5. 고객 전용 링크와 접근번호는 충분한 난수로 생성하고, 1회 사용 또는 짧은 유효기간 적용
6. 접근번호 반복 오류 시 잠금 또는 호출 제한 적용
7. 운영자 로그인, 권한관리, 조회·수정·다운로드 감사로그 적용
8. 서비스 종료 또는 보유 목적 달성 후 데이터 파기

원본 엑셀, 임시 웹 데이터베이스, 결과 엑셀의 저장 위치와 자동 삭제 시점은 개인정보 담당자 검토 후 오픈 전에 확정 부탁드립니다. 고객 입력값을 회원정보에도 갱신하는 기능은 이번 주문만을 위한 수집 목적과 범위가 달라질 수 있으므로 1차 최소 기능에서 제외하고 별도 승인 후 개발해 주시기 바랍니다.

접근번호를 URL과 동일한 알림톡으로 전달하는 방식은 별도 채널 인증보다 보안성이 낮으므로, 가능하면 추가 본인확인 수단 적용 여부도 함께 제안 부탁드립니다. 다만 긴급 임시 개발 목적을 고려하여 일정과 보안 수준의 현실적인 대안을 회신 부탁드립니다.

### 5. API 인증 및 확인 요청

API 인증정보는 기존에 별도로 전달드린 값을 사용해 주시고, 메일 본문에는 재기재하지 않겠습니다. 첨부 명세의 기본 인증 변수는 `partner_key`와 `key`로 표기되어 있으므로, 전달드린 `secret_key`가 실제 `key`에 대응하는지와 운영·샌드박스 키 구분을 확인 부탁드립니다.

또한 첨부 명세상 API는 1초에 100회 이상 호출 시 429 응답이 발생할 수 있으므로, 대량 처리 시 응답 헤더의 `ratelimit-available-level` 확인, 호출 속도 제한 및 재시도 처리가 필요합니다.

### 6. 요청 일정 및 회신사항

업무 영향이 큰 긴급 건으로, 전체 자동화보다 실제 운영 가능한 최소 기능을 우선 개발하고자 합니다. 아래 항목 회신 부탁드립니다.

1. 임시 웹 서비스 개발 가능 여부
2. 가장 빠른 착수일 및 사용 가능 예정일
3. 자사몰 회원정보의 개인통관고유부호 조회 경로: 표준 API, 내부 DB 또는 커스텀 API
4. 고도몰 알림톡 연동 가능 여부와 템플릿 승인 필요사항
5. 최소 기능 범위 기준 예상 공수 및 비용
6. 개인정보 보호조치와 추가 확인이 필요한 정책 항목

가능하면 아래 순서로 우선 오픈을 요청드립니다.

- 1차: 엑셀 업로드 → 기존 회원정보 후보값 조회 → 확인·검증 결과 엑셀 다운로드
- 2차: 고객 전용 입력 페이지 → 저장 → 내부 결과 반영
- 3차: 알림톡 자동 발송 및 재발송·만료 관리

첨부자료는 아래와 같습니다.

1. `20260831_통관번호 누락.xlsx` - CS팀 현재 사용 파일
2. `godomall5_openAPI_spec_v1.0_20250616.pdf` - 고도몰5 Open API 명세서

확인 후 가장 빠른 구현안과 일정을 회신 부탁드립니다.

- 수신자 이름과 회사 표준 서명 입력
- API 인증키를 본문·첨부 문서에 추가하지 않기
- 대화 중 공유된 API 인증키는 운영 적용 전에 재발급하고 기존 키 폐기
- 개인정보 수집·이용 안내의 보유기간과 개인정보처리자 명칭을 내부 개인정보 담당자에게 확정
- 알림톡 템플릿의 고객센터 연락처와 링크 도메인 입력
- 테스트 고객정보로 정상·오류·만료·중복 제출 시나리오 검증 후 실고객 발송
