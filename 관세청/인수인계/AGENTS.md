# 관세청 인수인계 작업 규칙

이 폴더의 목적은 지윤환(후임 PM·운영)의 인수인계 요청에 회신하는 것이다. 박종혁(현 PM)이 퇴사 전 답한다.
새 대화·다른 PC에서도 이 폴더만 열면 이어서 작업할 수 있게 한다. 이미 확인한 사실을 다시 조사하지 않는다.

## 폴더 구조

```
관세청/
├─ 전달용/                          ← 지윤환에게 보내는 것만
│  ├─ 관세청_통관연동_인수인계.md   단일 인수인계 문서 (과거 기획서·대장·협의 원문 전부 흡수)
│  └─ 회신메일_지윤환.txt           회신 메일 본문
├─ documents/                       원본 자료 (전달용과 함께 보냄)
└─ 인수인계/                        ← 내부 작업용 (보내지 않음)
   ├─ 01_작성자_확인목록.md          박종혁에게 물을 질문 대장 + 요청 메일 원문
   ├─ AGENTS.md / CLAUDE.md         이 작업 규칙
```

계정·비밀번호·API Key는 박종혁이 별도 계정 정리 txt로 전달한다. 이 폴더들에 값을 쓰지 않는다.
새 파일을 만들지 않는다(사용자 지시: 전달물은 메일 + md, 내부 파일은 확인목록 하나).

## 시작할 때 읽는 순서

1. 이 파일
2. `01_작성자_확인목록.md`의 "열린 질문" — 남은 일
3. `../전달용/관세청_통관연동_인수인계.md` — Grep으로 고칠 절만 읽는다

## 원본 삭제 예정

사용자는 `관세청/planning/`(과거 포함), `outputs/`, `test/`, `tmp/`를 삭제한다. 그 내용의 유일한 기록은 인수인계 문서다. 사실 확인이 필요하면 git 이력이나 customs 스킬(`.claude/skills/customs/`)을 쓴다.

## 작성 원칙

- 새 매뉴얼을 만들지 않는다. 기존 자료는 문서명과 위치만 적는다.
- 추측하지 않는다. 표기: `없음` / `미정` / `해당 담당자 확인 필요(회사)`. 박종혁이 "필요 없다"고 한 항목은 문서에서 정리한다.
- 날짜·필드·경로에는 근거를 붙인다. 문서 기록은 2026-09-17 11:40까지, 이후는 박종혁 답변으로만 채운다.
- 흐름도는 Mermaid로 쓴다. 고친 뒤에는 Mermaid 10으로 렌더링해 문법 오류를 확인한다.

## 확정된 사실 (2026-10-06 박종혁)

- 자사몰 신규 방식 가동은 대기. 동수·자이언트 테스트 미완료.
- 자사몰은 08-31부터 결제 단계 통관부호 간편인증에서 오류를 내 고객이 P부호를 직접 입력하는 구조. 전 주문 적용.
- 계정 메일 인계 대상은 유니패스 하나(`https://unipass.customs.go.kr/ecb/index.do`). 다른 화면·URL·계정은 인수인계 불필요.
- NICE·관세청 신청 명의는 아이베 신선일 이사, 현장담당 박종혁. 박종혁이 각 기관에 메일로 인계.
- 키는 재발급하지 않는다. GitHub 저장소는 비공개 전환 예정 — **전환 확인 전 push 금지**(연락처가 문서에 있음).
- 단톡방은 모두 초대 완료. PCCC 대응 메일 초안은 미발송.

## 답변 반영 절차

1. 답을 받으면 `01_작성자_확인목록.md`에서 "답변 완료"로 옮기고 일자를 적는다.
2. 인수인계 문서 해당 칸을 고친다. 기존 판정을 뒤집으면 `[YYYY-MM-DD 정정] 종전 → 신규 (근거)`로 남긴다.
3. 관세청 프로젝트의 새 사실은 `project_state.md` 관세청 절에도 반영한다.

## 다른 PC에서 이어갈 때
