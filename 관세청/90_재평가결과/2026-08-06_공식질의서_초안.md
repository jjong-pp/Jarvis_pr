# 관세청·Giant·개발사·법무 공식질의서 초안

기준일: 2026-08-06

구두·메신저 답변이 아니라 담당부서명, 답변자, 답변일, 적용 규격 버전이 포함된 서면 회신을 요청합니다. 답변은 쟁점대장의 근거 링크와 테스트케이스에 연결합니다.

## A. 관세청 질의

1. **혼합 주문 수량**  
   국내상품과 해외직구 상품이 한 주문에 섞인 경우 `tot_stlm_amt`는 국내상품 금액을 제외하는 것으로 이해했습니다. `tot_ord_prod_qty`도 해외직구 상품 수량만 기재하는지, 주문 전체 수량을 기재하는지 확인 바랍니다.

2. **다중 HBL 상품목록**  
   한 `ord_no`가 여러 HBL로 분할되는 경우 각 `order_info`에 전체 주문의 `product_info`를 반복하는지, 해당 HBL에 실린 상품만 기재하는지 확인 바랍니다. 전체금액·전체수량 반복과 상품순번의 예시 JSON을 요청합니다.

3. **세트·묶음상품**  
   고객이 하나의 세트상품으로 결제했으나 물류상 여러 구성품으로 포장/신고되는 경우 `ord_prod_nm`, `prod_ord_qty`, `prod_unprc`, `ord_amt`를 판매단위와 구성품 중 어느 단위로 작성해야 합니까? 구성품 분할 시 할인·금액 배분 허용규칙도 요청합니다.

4. **부분오류 재제출**  
   `txif_prcs_stcd=02`에서 정상 상품은 유지되고 오류 상품만 수정해 새 제출번호로 다시 보내는지, 동일 주문/HBL의 전체 상품을 새 제출번호로 다시 보내는지 확인 바랍니다. 중복 등록 방지키도 요청합니다.

5. **판매유형 A/B/C**  
   판매자 명의, 대금수취자, 구매대행 약관, 통관대행 역할이 서로 다를 때 A/B/C를 판정하는 우선기준을 요청합니다. 오픈마켓 입점판매가 항상 B가 되는지 확인 바랍니다.

6. **판매 페이지 URL**  
   주문시점 실제 상세페이지가 로그인/만료/동적 URL이고 장기 접근이 불가능한 경우 허용되는 대체값과 보존방법을 확인 바랍니다. 채널 대표 도메인 사용 가능 여부를 명확히 회신 바랍니다.

7. **Z99999**  
   `Z99999`의 정확한 허용기간, 대상 신고서/목록 필드, 대상 사업자/주문, PER 응답과의 관계를 확인 바랍니다. 2026-09-14 이후 대체정책도 요청합니다.

8. **2026~2028 단계적 적용**  
   2026-08-15 이후 부분 적용, 2027 확대, 2028 전면 적용의 대상선정 기준과 사업자별 확인방법을 요청합니다. 2026-08-28을 별도 전면 오픈일로 볼 근거가 있는지도 확인 바랍니다.

9. **PER 장애 예외**  
   PER 장애 중 주문 접수 후 PER003 등으로 사후 확인할 수 있는 범위, TRA 제출 가능시점, 소비자 안내 및 보류기한을 요청합니다.

10. **테스트 환경**  
    운영환경에 허위 주문을 전송하지 않고 TRA/PER 전체 분기를 검증할 수 있는 공식 테스트/파일럿 사업자, 데이터, 삭제절차 및 승인방법을 요청합니다.

## B. Giant 물류 질의

1. `totalValueUsd`, `unitPrice`, `itemAmount`, 관리자 “신고 단가”가 각각 고객 결제금액, 공급사 조달금액, 수입신고가격 중 무엇인지 정의와 계산식을 요청합니다.
2. 환율 출처, 기준시각, 소수점 자리수, 반올림 방식, 할인·쿠폰·운임·보험 포함여부를 요청합니다.
3. HBL이 생성 전/생성 후/출고 후/24시간 후 각각 어떤 API에서 얼마나 오래 조회되는지 공식 SLA를 요청합니다.
4. HBL 정정·취소·재발급 시 식별자 변경규칙과 변경이력 API를 요청합니다.
5. 동일 주문 재호출/재전송의 멱등키와 중복방지 규칙을 요청합니다.
6. 세트상품 분할, 다중 HBL, 부분출고 시 상품순번·수량·가격 배분 예제를 요청합니다.
7. 실제 판매페이지 URL, 판매기업, 채널식별자를 어느 원천에서 보존하며 과거 주문도 재조회 가능한지 확인 바랍니다.

## C. Dongshu WMS/채널 운영 질의

1. 29개 채널 각각의 판매자 명의, 약관상 거래당사자, 대금수취자, 구매/배송대행 역할을 표로 회신 바랍니다.
2. 주문시점 고객 결제통화·상품단가·상품할인·주문할인·배송비·환불을 변경불가 스냅샷으로 제공할 수 있는지 확인 바랍니다.
3. 상품명과 1·2차 카테고리가 주문시점 값인지 현재 상품DB 값인지 확인 바랍니다.
4. 실제 상세페이지 URL의 원본, 리다이렉트 전후 URL, 상품/옵션 ID를 장기 보존하는지 확인 바랍니다.
5. 다중 HBL과 부분출고에서 `ord_no-HBL-상품순번-수량` 관계를 누락 없이 제공하는지 확인 바랍니다.
6. 중량이 실측인지 추정인지, 갱신시점과 오차보증 범위의 근거문서를 요청합니다. “±5~10% 공식 허용” 근거가 없다면 해당 표현을 철회해 주십시오.

2. TRA002 조회주기, 3030 대기, 01/02/03 분기, TRA003 반복조회 및 7일/50건 제한 구현설계를 제출 바랍니다.
3. 수정 재제출 때 새 `txif_sbmt_no` 생성과 이전 제출과의 계보 저장방식을 제출 바랍니다.
4. 주문오류·상품오류·전체반려 각각의 관리자 보류/수정/재제출 UI를 제시 바랍니다.
5. “상태목록 제거”와 “오류 시 주문삭제”가 원계약 검수범위와 충돌하지 않는다는 변경합의 근거를 제출 바랍니다.
6. 엑셀 업로드가 선택 주문만 처리하는지, 전체 대기열을 일괄 전송하는지, 실행 전 예상건수·취소·롤백 기능을 설명 바랍니다.
7. 운영환경 가상 주문 테스트의 관세청 승인 및 자동삭제 근거를 제출 바랍니다.
8. 고객 결제값과 Giant 조달/신고값이 섞이지 않도록 한 데이터모델과 대사 리포트를 제출 바랍니다.
