Dongsu-GNG原有/新版通关流程说明

编制日期 2026-09-04 · 发送对象 Dongsu中国物流负责人 · 名称统一使用 GNG
【当前核心问题】
同一个MAWB下，同时包含采用电子商务专用申报的自营商城HBL和采用原有进口申报的外部平台HBL。
当前导入Dongsu ERP的外部平台订单数据尚未接入PER认证信息，因此缺少电子商务专用申报所需的信息。
所以，仅将全部订单发送到新版GNG V2-1并不能解决此问题。
【最新确认事项】
GNG已经调整为可以通过新版GNG V2-1接收自营商城订单。
自营商城具备PER认证信息，因此可以使用新版GNG V2-1，并采用电子商务专用申报。
如果继续使用Geek V2-2，则仅作为补充自营商城通关及认证信息的路径。

1. 术语区分

销售类型A/B与API类型是两个不同的分类。
为避免翻译和沟通时混淆，API类型不称为A/B，而统一写为原有GNG API和新版GNG V2-1。
分类名称含义当前对象
销售类型ecTypeCode=A直接销售自营商城订单

API类型新版GNG V2-1本次新接入的GNG API当前为自营商城；今后为准备完成的外部平台
认证PER认证核验个人通关识别码并取得新申报方式所需的认证信息当前仅自营商城已接入
运输单证HBL / MAWBHBL为分运单；MAWB为主运单一个MAWB可包含多个HBL

3. 发送给Dongsu的说明

经理，您好。 我们已确认您昨天反馈的内容。 首先，为避免混淆，我们先统一以下术语。 - 销售类型 ecTypeCode=A：直接销售，目前对应自营商城订单。 - 销售类型 ecTypeCode=B：代购，目前对应外部平台订单。 - 原有 GNG API：韩国关税厅制度调整前一直使用的 GNG API。 - 新版 GNG V2-1：本次新接入的 GNG API。 销售类型 A/B 与原有 GNG API/新版 GNG V2-1 是两个不同的分类，请不要混用。 目前，自营商城已经接入订单 API，Geek也会处理PER认证。因此，自营商城可以取得电子商务专用申报所需的个人通关识别码、一次性个人通关识别码、认证号码等信息。 另外，GNG已经调整为可以通过新版 GNG V2-1 接收自营商城订单。因此，自营商城订单可以使用新版 GNG V2-1，并采用电子商务专用申报。 如果后续继续使用 Geek V2-2，则仅作为补充自营商城通关及认证信息的路径。自营商城订单的主要传输可以使用新版 GNG V2-1。 另一方面，外部平台订单目前通过 Excel 文件导入 Dongsu ERP。当前导入 Dongsu ERP 的外部平台订单数据尚未接入 PER 认证信息。 因此，这些订单目前没有电子商务专用申报所需的一次性个人通关识别码和认证号码。即使通过新版 GNG V2-1 传输数据，接口也不会自动生成原本不存在的 PER 认证信息。 所以，在各外部平台完成 PER 对接、新版 Excel 字段、Dongsu ERP 字段映射以及 GNG 全流程测试之前，外部平台订单仍需使用原有 GNG API，并采用原有进口申报。 当前的核心问题是：同一个 MAWB（主运单）下，同时包含以下两种 HBL（分运单）。 1. 自营商城 HBL：使用新版 GNG V2-1，采用电子商务专用申报。 2. 外部平台 HBL：使用原有 GNG API，采用原有进口申报。 仅将所有订单统一发送到新版 GNG V2-1，并不能解决这个问题。原因是外部平台订单目前缺少电子商务专用申报所需的必要信息。 我们希望按以下顺序确认解决方案。 1. 先在 GNG 登记一个 MAWB，再确认同一 MAWB 下的 HBL 是否可以分为两组，分别通过不同 API 传输。 2. 自营商城 HBL 通过新版 GNG V2-1 传输。 3. 外部平台 HBL 通过原有 GNG API 传输。 4. 确认 GNG 是否能够在同一 MAWB 下同时管理这两类 HBL。 如果以上方式无法实现，则需要为新版 GNG V2-1 增加处理逻辑。 新版 GNG V2-1 接收所有 HBL 后，需要根据每个 HBL 所包含的信息选择申报方式。 - 有 PER 认证信息的自营商城 HBL：采用电子商务专用申报。 - 没有 PER 认证信息的外部平台 HBL：采用原有进口申报。 对于采用原有进口申报的 HBL，不应强制要求一次性个人通关识别码和认证号码。 如果 GNG 无法支持上述功能，则需要在出库前，按照申报方式拆分实际 MAWB。 - 电子商务专用申报 MAWB：自营商城订单。 - 原有进口申报 MAWB：外部平台订单。 预计截至2026年11月左右，各外部平台的 Excel 模板会陆续增加新字段。每次收到新的 Excel 模板后，Dongsu都需要检查其中是否包含 GNG 要求的字段，并确认这些字段能否映射到 GNG API 后再进行应用。 只有在 PER 认证信息及电子商务专用申报必填信息全部确认，并完成 GNG 全流程测试后，对应渠道才能切换到新版 GNG V2-1。 请协助确认以下事项。 1. 同一个 MAWB 下，能否同时关联通过原有 GNG API 传输的 HBL和通过新版 GNG V2-1 传输的 HBL？ 2. 如果目前无法实现，限制来自 Dongsu系统还是 GNG 系统？请提供具体技术原因和错误代码。 3. Dongsu系统能否将 API 选择单位从 MAWB 改为 HBL？ 4. 新版 GNG V2-1 能否按 HBL 区分电子商务专用申报和原有进口申报？ 5. 新版 GNG V2-1 接收没有 PER 认证信息的 HBL 后，能否将其按原有进口申报处理？ 6. 如果上述方式均不可行，是否必须将实际 MAWB 拆分为两个？ 7. 请提供原有 GNG API和新版 GNG V2-1 各自准确的 HTTP Method（如 POST）及完整 URL。 确认后，我们希望再协商开发方式和出库方式。 谢谢。
