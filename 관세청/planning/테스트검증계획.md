# 관세청 연동 오픈 전 검증 계획 (테스트서버 종료 역산)

기준일 2026-08-13 · 근거: `리스크_질의대장.html`(2026-08-12 통합본) · `planning_v6.html` Stage 0-A~7 · 관세청 REST API 명세서 v1.4.1 · 자이언트 GGATE API V2 v1.3.5 · 고도몰5 openAPI v1.0
**관세청 테스트서버 종료 D-8(2026-08-21) · 오픈 D-15(2026-08-28 09:00)**

## 0. 이 계획의 전제

1. **2026-08-21이 진짜 마감이다.** 이후 관세청 대상 검증 창구는 오픈일 새벽 03~04시 단 한 번뿐이고(관세청 공식 허용), 그 시간대는 재작업이 불가능하다.
2. 08-13~08-21 사이 **가용 영업일은 7일**이다 — 08-15(광복절·토) · 08-16(일) 제외. 동수(중국)는 해당 휴일 영향을 받지 않으므로 주말 구간은 동수 측 작업 배치에 쓴다.
3. 관세청 대상 검증(AUT·PER·TRA)과 협력사 대상 검증(동수·자이언트·NICE)은 **마감이 다르다.** 협력사 검증은 08-21 이후에도 가능하지만, 관세청 제출 데이터를 만들어내는 쪽이 동수라 **동수가 늦으면 관세청 검증이 통째로 밀린다.**
4. 상태 라벨은 고정 세트만 쓴다 — `QA 대기` / `QA 실패` / `확인 불가` / `부분 완료` / `완료`.
5. 주문 처리 상태는 `HBL_WAITING`(전부 null·재조회 유지) / `HBL_READY`(전 HBL 확보·대사 완료) / `TRA_SENT`(관세청 제출 완료)로 구분한다.

## 4. 판정

`[조건부 진행]` — 조건은 다음 두 가지다.

1. **2026-08-14까지 자이언트 PER 엔드포인트 회신**. 없으면 ⓑ(동수 선등록 후 `PATCH`)를 가정하고 개발에 들어가되, 이 경우 자사몰 전송이 17:00 이후로 밀리고 **수하인 성명·주소는 `PATCH`로 갱신 불가**라는 제약을 오픈 전 CS 정책에 반영해야 한다.
2. **2026-08-17까지 동수 다건 조회 + `prod_srno` 제공**. 없으면 T-03 이후 관세청 검증 전체가 08-21 안에 들어가지 못하며, 그 시점에 오픈일 새벽 창구 단독 검증이라는 미검증 리스크를 받아들일지 별도 판단이 필요하다.

미검증 상태로 오픈에 들어가는 항목은 반드시 `확인 불가`로 표기해 남긴다. 검증하지 못한 것을 완료로 적지 않는다.
