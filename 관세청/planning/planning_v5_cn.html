KCS 预先交易信息申报(TRA) E2E 整合策划书 (planning_v5 Full Spec)

[2026-08-10 更正] 依据韩国关税厅 REST API 规格 v1.4.1 修正字段名与类型：dlvr_vcex_bsmn_* → shpn_vcex_bsmn_*、sale_ents_biz_no → sale_ents_bsns_no、prod_mnfcr_nm → prod_mkr_nm、prod_mdl_no → prod_mkr_mdl_no。另新增必填项 ord_site_url（详见 risk_list.html）。
[自营商城主 E2E 及东数系统双轨制定义] 本策划书是基于 Geek Studio (自营商城: KRONE) - 东数(EIBE ERP / DS Logistics) - GIANT 特快专递 - 韩国海关 REST API 之间直接销售(A类型) 的实务数据与逻辑整合编写。
- EIBE ERP: 每天 10:00 KST 发货前将预估数据 (14个属性) 传输给 Geek (供海关 TRA001 预先申报使用)
- DS Logistics: 每天 17:00 KST 实物出库后将真实物流数据 (MAWB、实测重量等) 直送至 GIANT (供海关进口申报使用)
[重量微小误差风险核查结果]: 10:00 EIBE ERP 传输的预估重量(tot_wt)与 17:00 DS Logistics 秤重机测得的实测重量(weight)之间的微小小数位误差，在韩国海关规定中属于预先交易信息(预估)与实物进口申报(实测)之间的正常误差范围 (±5~10%以内)，在通关中没有任何错误或风险。

Stage 1. 结账环节 PER001 个人通关固有符号预先有效性验证 顾客结账瞬间 (实时)

详细发送及处理逻辑 (Geek 自营商城实务):

  • 背景及目的: 在自营商城结账阶段预先验证个人通关固有符号，拦截因错误符号或姓名不符导致的通关被拒及延迟。
  • 处理流程:
    1. 自营商城顾客在结账页面输入收件人姓名(cnsi_nm)、个人通关固有符号(cnsi_pers_ecm)、电话号码(cnsi_telno)。
    2. 自营商城(Geek)后端实时同步调用海关 PER001 API，验证姓名-符号-电话号码三者一致性。
    3. 验证成功时: 将海关响应的 6位认证号码(su_crtf_no)保存至自营商城 DB 订单表，并完成结账批准 (订单状态 p1)。
    4. 验证失败时: 立即拦截结账批准，并在页面弹出 "您输入的通关符号与姓名不符" 警告提示。

Stage 2. 09:00 东数 EIBE ERP 订单采集及订单状态变更 g1(商品准备中) 每天 09:00 批处理

详细发送及处理逻辑 (Geek - 东数 EIBE ERP 联动):

  • 背景及目的: 东数 EIBE ERP 采集订单以备当日海外发货，并锁定个人中心取消功能，保障物流作业安全。
  • 处理流程:
    1. 每天 09:00 东数 EIBE ERP 调用自营商城 Open API 批量采集 p1(支付完成) 状态订单。
    2. 自营商城(Geek)收到采集请求后，立即将对应订单状态更新为 g1(商品准备中)。
    3. 进入 g1 状态后，个人中心 "取消/退款" 按钮自动隐藏，禁止顾客直接取消。
