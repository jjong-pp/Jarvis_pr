룰 총량이 임계를 넘었을 때 실행하는 정리 의식입니다. `/정리`가 룰을 늘리는 절차라면 이건 줄이는 절차입니다.
$ARGUMENTS 에 대상 파일이 지정되면 그 파일만, 없으면 전체를 대상으로 합니다.

**대원칙: 아카이빙은 삭제가 아니다.** `CLAUDE.md` 5번(정정은 삭제가 아니다)이 그대로 적용됩니다. 옮긴 내용은 반드시 되찾을 수 있어야 하며, 룰에는 아카이브 경로를 남깁니다.

## 1. 계측

먼저 실제 수치를 나열합니다. 추측하지 않습니다.

- `wc -l CLAUDE.md .claude/rules/*.md` 로 전체·개별 줄수
- 임계: 전체 700줄 / 개별 파일 180줄 / `90_학습로그.md` 각 절 10건
- 어느 파일이 얼마나 초과했는지 표로 보고한 뒤 다음 단계로 갑니다. 초과가 없으면 "압축 불필요"로 끝냅니다.

## 2. 중요도 3분류

초과한 파일의 각 항목을 아래 셋 중 하나로 판정합니다. 판정 결과를 항목별로 보고합니다.

| 등급 | 기준 | 처리 |
|---|---|---|
| **상시** | 모르면 재작업이 발생하고, 지금도 유효하다 | 룰에 유지 |
| **참조** | 과거엔 중요했으나 지금은 안 쓴다. 종결된 프로젝트의 사실. 해결된 리스크의 상세 경위 | `.claude/archive/`로 이동, 룰엔 한 줄 포인터 |
| **소멸** | 다른 곳에 정본이 있는 중복이다 | 정본 경로만 남기고 제거 |

판정이 애매한 항목은 **상시로 남깁니다.** 지우는 쪽으로 기울지 않습니다.

## 3. 함축

같은 주제의 항목이 3개 이상 쌓였으면 상위 원칙 1줄로 승격하고 개별 사례는 참조로 내립니다.

- 예: "규격 문서와 실제 동작이 다르다" 유형 함정이 여러 건 → 원칙 1줄로 올리고 개별 사례는 아카이브
- 함축한 원칙에는 근거가 된 사례들의 아카이브 경로를 붙입니다
- **함축으로 뉘앙스가 사라지면 함축하지 않습니다.** 항목마다 조건이 다르면 그건 별개 지식입니다

## 4. 아카이빙 실행

- 위치: `.claude/archive/{원본파일명}_{YYYYMM}.md`
- 아카이브 파일 상단에 `원본: {경로} · 이관일: YYYY-MM-DD · 이관 사유` 를 적습니다
- 원본 룰 파일에는 `> 과거 항목 n건은 .claude/archive/… 참조` 한 줄을 남깁니다
- 아카이브 파일은 세션에 로드되지 않습니다 — 필요할 때만 읽습니다

## 5. 검증

- 압축 후 다시 `wc -l` 로 재계측해 before/after를 보고합니다
- 아카이브로 옮긴 항목 중 다른 룰 파일이 참조하던 게 있는지 grep으로 확인하고, 있으면 참조를 아카이브 경로로 갱신합니다
- 죽은 참조가 남지 않았는지 확인합니다
