세션 마무리 절차를 실행하세요. $ARGUMENTS 에 특별 지시가 있으면 반영합니다.

1. **정리**: organizer 서브에이전트를 호출해 이번 세션 산출물을 PARA 볼트에 정리하고 `project_state.md`를 갱신하게 한다 (마지막 갱신일 = 오늘).
2. **룰 축적** (메인이 직접, `.claude/rules/00_운영_프로토콜.md` 7번 승격 기준): 이번 세션에서 나온 것 중 **모르면 재작업이 발생하는 것**만 골라 해당 룰 파일에 반영한다.
   - 확정된 결정·함정·지침 → `.claude/rules/2x_{프로젝트}.md`
   - 실수와 교정, 통한 방식 → `.claude/rules/90_학습로그.md`
   - 형식: `- [YYYY-MM-DD] 내용 (출처: …)` 한 줄. 진행 상황은 승격하지 않는다 (그건 `project_state.md`).
   - 기존 내용을 지우지 않는다. 뒤집힌 결정은 `[정정] 종전 X → 신규 Y` 로 남긴다.
   - 승격할 게 없으면 "없음"으로 보고한다. 억지로 채우지 않는다.
3. **모순 점검**: `project_state.md`와 룰 파일·정본 문서가 같은 사실에 다른 말을 하는지 확인한다. 갱신일이 다르면 최신 쪽이 이긴다. 임의로 고르지 말고 근거와 함께 보고한다.
4. **회전 점검**: `90_학습로그.md`의 각 절이 10건을 넘으면 오래된 것부터 `.claude/archive/학습로그_YYYYMM.md`로 옮긴다. 룰 파일이 200줄을 넘으면 정본 문서로 뺄 후보를 제시한다.
5. **커밋**: 변경 파일을 명시적 경로로 스테이징 (`git add -A` 금지, 시크릿 여부 확인) 후 영문 명령형 한 줄 커밋.
6. **푸시**: 원격(origin)이 있으면 push. 실패(충돌) 시 우회하지 말고 상태를 보고한다.
7. **보고**: [정리된 파일 → 위치 / 룰에 승격한 줄 / 현황판 변경 줄 / 발견한 모순 / 커밋 해시 / 푸시 여부]를 표로 보고한다.
