# 운영 — 서브에이전트 · 성장 관리 · 심층 검증 모드

`SKILL.md`에서 분리한 상세 절차. **삭제가 아니라 이동이다** (2026-08-15, 스킬 본문 5,000토큰 상한 대응).
이 셋은 특정 상황(위임·임계 초과·울트라 지시)에서만 필요하므로 본문에서 내렸다.

## 서브에이전트

- 외부 조사·확정 전 검토·사용자가 명시적으로 요청한 경우에만 실제로 호출한다. 단순 질문이나 직접 처리 가능한 파일 작업엔 부르지 않는다 — 왕복 지연과 호출 비용이 이득보다 크다. **호출 자체가 수천 토큰이다.**
- "호출하겠습니다"라고 쓰고 실제로 부르지 않는 시늉은 금지한다.
- **서브에이전트는 부모의 지시 파일(`AGENTS.md`·스킬)을 상속하지 않는다.** 위임할 때 필요한 사실을 프롬프트에 직접 넣는다. 배경·읽을 파일 경로·판단 기준·출력 형식을 자기완결적으로 적는다.
- 에이전트 보고는 액면 그대로 받지 않는다. **파일·원본과 대조한 뒤 반영한다.** 실제로 2026-08-15 평가에서 에이전트가 P0로 올린 항목 1건이 반증됐고 1건은 과소 집계였다.
- 룰 파일과 에이전트 정의 수정은 메인만 한다. 병렬 수정으로 규칙이 깨진 전례가 있다.

| 이름 | 역할 | 언제 |
|---|---|---|
| `researcher` | 외부 조사 — 소스/요약/시사점 | 외부 정보·동향·사례가 필요할 때 |
| `reviewer` | 리스크 검토 — 리스크마다 대응책 | 확정 전 |
| `organizer` | 프로젝트 폴더 정리 + 현황판 갱신 | 세션 마무리 |

## 성장 관리

**룰은 `/정리`로 늘어나고 `/압축`으로 줄어든다.** 늘리는 절차만 있으면 단방향으로 비대해져 결국 준수율이 떨어진다. 임계값은 `harness/SPEC.md` 6절.

- 세션 시작 시 훅이 현재 수치를 자동으로 띄운다. **경고가 뜨면 사용자에게 `/압축`을 권한다 — 임의로 실행하지 않는다.**
- 룰을 새로 추가할 때는 **기존 항목과 합칠 수 있는지 먼저 본다.** 비슷한 항목 3개가 쌓이면 상위 원칙 1줄로 함축할 후보다.
- 새 스킬을 만들기 전에 업무 모드 4가지와 기존 스킬에 비추어 정말 새 카테고리가 필요한지 확인한다. **업무 모드는 4가지에서 늘리지 않는다.**
- **검증되지 않는 필드는 만들지 않는다.** 훅이 검사할 만큼 중요하지 않으면 지운다. 경고 없는 수동 값은 시간이 지나면 반드시 낡고, 낡은 값이 사고 유형 4를 만든다 (2026-08-15 평가 지적 — 선언 헤더 `상태` 앵커 7개 중 5개가 틀린 채 출발했다).

## 심층 검증 모드

사용자가 `울트라` 또는 `ultra`라고 지시하면 다음 4단계를 순서대로 집행하고, 각 단계 결과를 나눠서 보고한다.

1. **심층 추론** — 요청의 전제부터 의심한다. 무엇이 참이어야 이 계획이 성립하는지 나열한다.
2. **팩트체크** — 주장마다 원본 대조. 확인된 것과 미확인을 나눠 표기한다.
3. **반대 검토** — `reviewer`로 실패 시나리오를 뽑고 각각에 대응책을 짝짓는다.
4. **최종 판정** — `[진행 가능 / 조건부 진행 / 보류 권고]` 중 하나와 조건.
