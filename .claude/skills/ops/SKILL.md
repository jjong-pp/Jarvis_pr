## 한 줄 정의

`AGENTS.md` 2번(판단 원칙 3축)의 실행 절차. 매 세션·매 응답에 적용한다. 계층 구조 자체의 규격은 `harness/SPEC.md`.

## 절대 규칙

1. **룰 파일과 에이전트 정의 수정은 메인 에이전트만, 증분 수정으로만.** 전체 재작성은 사용자 승인이 필요하다. 병렬 수정으로 규칙이 깨진 전례가 있다.
2. **커밋은 `/정리` 절차 안에서만.** 세션 중간에 임의로 커밋하지 않는다. push는 항상 사용자가 직접 한다.
3. **룰끼리 모순되면 임의로 하나를 고르지 말고 즉시 보고한다.**

## 확정 사실

### 요청 접수 절차

1. **의도 추론** — 문장 그대로가 아니라 그 뒤의 목적을 먼저 잡는다. 이 요청이 어떤 결정을 위한 것인지, 결과물이 누구에게 가는지.
2. **대상 확정** — 파일·범위가 불명확하면 실행 전에 한 번만 확인한다. 추측으로 고치지 않는다.
3. **실행** — 결과물을 먼저 만든다.
4. **자기 점검** — 내놓기 전에 요청한 것이 맞는지, 출처가 붙었는지, 지운 내용이 없는지 확인한다.

### 선택지 제시

방향성 선택지·대안·확인 질문은 텍스트 나열이 아니라 `AskUserQuestion`으로 낸다.
권고안을 첫 번째 항목에 두고 라벨에 `(추천)`을 붙인다. 각 항목에 그 선택의 결과를 한 줄로 적는다.
한 번에 묻는 질문은 최대 4개. **답이 작업을 바꾸지 않는 질문은 묻지 않는다.**

### 검증 루프

- **중간**: 작업이 길어지면 방향 정합성을 한 번 확인한다. 이미 확정한 결정을 다시 묻지 않는다.
- **종료**: 결과 발표 전에 요청 대비 누락, 근거 미표기, 문서 간 모순을 점검한다.
- 검증에서 문제를 찾으면 **고친 뒤 내놓되, 사용자 판단이 필요한 것은 함께 보고한다.**

**자기 점검** — 도구 호출이 10회를 넘은 긴 작업이 끝나면 조용히 아래를 확인한다. 매 응답마다 하지 않는다.

1. 출처 없이 쓴 숫자·날짜·필드명이 있었나
2. L2에 이미 있는 사실을 원본에서 다시 조사했나
3. 요청하지 않은 작업을 했나
4. 기존 문서에서 조용히 지운 내용이 있나

위반을 찾으면 그 자리에서 `90_학습로그.md`에 적고 사용자에게 보고한다. **위반이 없으면 아무 말도 하지 않는다.**
같은 유형 위반이 2회 반복되면 준수 실패가 아니라 **룰 문장이 모호한 것**을 먼저 의심하고 개정안을 제안한다.

### 세션 절차

**시작** — `project_state.md`는 훅이 주입한다. 따로 읽지 않고 폴더 전체를 스캔하지 않는다. 다른 기기에서 이어받는 세션이면 `git pull`부터.

**작업 중** — 상황이 바뀌면 `project_state.md`의 해당 항목만 갱신하고 마지막 갱신일을 기록한다. 실수·교정은 그 자리에서 `90_학습로그.md`에 남긴다.

**마무리** — `/정리`. 볼트 정리 → 룰 승격 → 모순 점검 → 커밋. 푸시는 하지 않는다.

### 룰 승격 기준

`/정리`에서 아래에 해당하는 것만 올린다. **모르면 재작업이 발생하는 것**만이다.

| 대상 | 올라갈 곳 |
|---|---|
| 확정된 결정, 번복된 결정 (안 바뀌는 것만) | 해당 L2 스킬 |
| 겪은 함정, 규격과 다른 실제 동작 | 해당 L2 스킬 |
| 사용자 지침·선호 | 해당 L2 스킬의 지침 로그, 또는 `AGENTS.md` |
| 실수와 교정, 통한 방식 | `.claude/rules/90_학습로그.md` (L1) |
| 진행 상황, 다음 할 일, **아직 안 끝난 미확정 사안** | 룰 아님 — `project_state.md` (L3) |

형식은 `- [YYYY-MM-DD] 내용 (출처: …)` 한 줄. 기존 줄을 지우지 않는다.
"확정된 결정"이라도 다음 주에 또 바뀔 가능성이 있는 사안(협력사 회신 대기, 미해결 P0 등)은 L3에 둔다.

### 상세 절차는 별도 파일

**서브에이전트 위임 · 성장 관리 · 심층 검증 모드(울트라)는 `references/procedures.md`에 있다.** 위임하거나, 훅이 임계 초과를 경고하거나, 사용자가 `울트라`라고 지시하면 그 파일을 읽는다.

## 함정

- **토큰 비용은 응답 문장이 아니라 대용량 정본 파일을 여는 행위에서 난다** (`planning_v6.html` 13만 자 등). 대용량 HTML은 Grep으로 위치를 먼저 잡고 관련 절만 읽는다.
- **상시 로드 파일의 금전 비용은 프롬프트 캐싱이 대부분 상쇄한다.** 상시 로드의 진짜 비용은 돈이 아니라 준수율이다 — 모델이 안정적으로 지키는 지시는 150~200개이고 시스템 프롬프트가 이미 ~50개를 쓴다. L1을 늘리면 기존 룰의 준수율이 같이 떨어진다.
- **`paths:` 프론트매터를 룰에 붙이면 컴팩션에서 유실된다.** 하위 폴더 `CLAUDE.md`도 같다. 온디맨드가 필요하면 `.claude/skills/`를 쓴다 — 호출된 스킬 본문은 컴팩션 후 재주입된다(스킬당 5,000토큰 상한, 앞쪽을 남김).
