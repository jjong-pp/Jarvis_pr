## 절대 규칙

1. **경력 사실·수치·기간은 `resume/career_facts.md`에서만 가져온다.** 이 파일이 단일 정본이다. 기업별 제출본에 새 성과나 숫자를 창작하지 않는다. 원장에 없으면 쓰지 않는다. 종전 정본 `이력서_마스터_통합.md`·`전체_이력_마스터_v2.md`는 작업 트리에서 삭제돼 git 이력에만 있다 — 값이 필요하면 git에서 꺼내 원장에 반영하고 출처를 적는다.
2. **수치에는 측정 범위를 함께 쓴다.** "TMS 기사 생산성 14% 향상"이 사내 시범인지 통계 검증인지 불분명하다는 것이 실제 탈락 사유였다.
3. **과장 수식어를 쓰지 않는다.** "산업 전반의 낡은 프로세스를 개편하는 빌더" 같은 표현이 오만함으로 읽혀 탈락 요인이 됐다. 톤은 실무자·겸손·빠른 실행.
4. **기업별로 파일을 분리한다** (`resume/applications/{회사}_{직무}_{공고ID}/이력서.md`). 마스터를 회사용으로 덮어쓰지 않는다.
5. **개인정보(전화번호·이메일·주소)는 실제 제출본에만.** 블로그·포트폴리오·공유 문서로 옮기지 않는다.
6. 관세청 프로젝트를 서술할 때는 `관세청` 스킬의 사실과 대조한다. 두 문서가 다른 말을 하면 그대로 두지 말고 어느 쪽이 맞는지 확정한다.
7. `resume/AGENTS.md`의 로드 순서와 질문 규칙을 따른다. 이미 답한 질문을 반복하지 않고, 결과를 바꾸는 미확인 사항만 한 번에 1~3개 묻는다.

- **지침을 만들고 적용하지 않음** — `PM_PO_포트폴리오_PPT_제작지침_2026-08-28.md`이 B2B 일정을 `07.02 착수/07.16 전체가동`으로 확정하고 종전 `07.14`를 폐기하라 했으나, 같은 날 만든 신규 PPT가 `07.14`를 그대로 썼다. **지침을 새로 쓸 때가 아니라 산출물을 만들 때 지침을 다시 읽는다.** (2026-08-29 발견)

- **성과와 진행상태의 충돌** — B2B몰은 운영 성과(오출고 0건 등)와 진행 현황(BR 22건 중 17건 배포·QA 필요)이 동시에 사실이다. 숫자를 지우지 말고 **범위를 분리해** 쓴다. 안 그러면 면접에서 "그래서 끝난 건가"로 무너진다.

## 파이프라인 — 공고 1건 처리 루프

기업별 맞춤본은 아래 순서로만 만든다. 단계를 건너뛰면 창작이 섞인다.

```text
공고 입수
  ├─ jd-analyst      : 공고 원문 보존 · 요구사항 원장 · 트랙 판정      [병렬]
  └─ (필요 시) researcher : 회사·산업 외부 조사                        [병렬]
        ↓ 둘 다 COMPLETE
  fit-strategist     : 자격게이트 · 증거강도 · 공백 · 메시지맵 · 트랙 결정
        ↓ 게이트 통과 + 사용자 지원 결정
  application-writer : 이력서 · 자소서 · 포트폴리오 배치안 · 문장근거표
        ↓
  application-auditor: 8개 렌즈 독립 검증 → BLOCK / REVISE / READY
        ↓ REVISE면 writer 재작업 (최대 1회)
  사용자 최종 승인 → 제출 직전 공고 상태·마감 재확인
```

**루프 규칙**

1. **병렬은 앞의 두 읽기 작업만.** writer와 auditor가 같은 파일을 동시에 만지지 않는다.
2. **auditor가 `BLOCK`이면 writer로 돌려보내지 않는다.** BLOCK은 사실 원장 문제이므로 사용자에게 올린다.
3. **`REVISE` 재작업은 1회.** 2회째도 `READY`가 안 나오면 루프를 멈추고 사용자에게 쟁점을 보고한다. 무한 수정 금지.
4. **auditor는 writer가 될 수 없다.** 자기가 쓴 것을 자기가 검증하면 놓친다 (2026-08-15 하네스 사고와 같은 유형).
5. **`CONFLICT` claim이 핵심 근거면 파이프라인을 시작하지 않는다.** `career_facts.md` 8절 미해결 질문부터 닫는다.
6. 산출물은 `resume/applications/{회사}_{직무}_{공고ID}/`에만 쓴다. 정본과 마스터는 건드리지 않는다.

## 파일 지도

`resume/` 루트의 **사실 정본은 `career_facts.md` 하나**다. `AGENTS.md`는 자동 진입 규칙일 뿐 사실을 복제하지 않는다. 분석 문서는 루트에 새로 만들지 않는다.

**정본** `career_facts.md` — 경력 사실 원장(claim ID·검증상태·트랙) · **공고별** `applications/{회사}_{직무}_{공고ID}/`에 공고 원문·적합도·제출문·근거표 · **감사 기준** `_eval/rubric.md` · **증거물** 현재 `resume/` 루트의 PPTX·PDF·실운영 화면 · **아카이브** `_archive/` 과거 제작지침·진단. 아카이브는 현재 정본으로 사용하지 않는다

**에이전트** `jd-analyst` 공고 해부 · `fit-strategist` 적합도·메시지맵 · `application-writer` 제출본 작성 · `application-auditor` 독립 검증. 서브에이전트는 이 파일을 상속받지 않으므로 위임할 때 정본 경로와 금지 규칙을 프롬프트에 직접 넣는다.
