# resume 이전 공정·파일 지도 보관

[2026-10-07 정정] 아래는 Claude 스킬에서 분리한 과거 설계 기록이다. 현재 실행 절차와 정본은 resume/공고처리_공정.md, resume/AGENTS.md, 두 성과 파일을 따른다.

### 종전 4에이전트 설계 — 실행 금지

기업별 맞춤본을 아래 순서로 만들도록 설계했었다. 현행 S0~S7 공정으로 대체됐다.

```text
공고 입수
  ├─ jd-analyst      : 공고 원문 보존 · 요구사항 원장 · 트랙 판정      [병렬]
  └─ (필요 시) researcher : 회사·산업 외부 조사                        [병렬]
        ↓ 둘 다 COMPLETE
  fit-strategist     : 자격게이트 · 증거강도 · 공백 · 메시지맵 · 트랙 결정
        ↓ 게이트 통과 + 사용자 지원 결정
  application-writer : 이력서 · 자소서 · 포트폴리오 배치안 · 문장근거표
        ↓
  application-auditor: 8개 렌즈 독립 검증 → BLOCK / REVISE / READY
        ↓ REVISE면 writer 재작업 (최대 1회)
  사용자 최종 승인 → 제출 직전 공고 상태·마감 재확인
```

**종전 루프 규칙 — 현행 여부는 `resume/공고처리_공정.md`에서 확인**

1. **병렬은 앞의 두 읽기 작업만.** writer와 auditor가 같은 파일을 동시에 만지지 않는다.
2. **auditor가 `BLOCK`이면 writer로 돌려보내지 않는다.** BLOCK은 사실 원장 문제이므로 사용자에게 올린다.
3. **`REVISE` 재작업은 1회.** 2회째도 `READY`가 안 나오면 루프를 멈추고 사용자에게 쟁점을 보고한다. 무한 수정 금지.
4. **auditor는 writer가 될 수 없다.** 자기가 쓴 것을 자기가 검증하면 놓친다 (2026-08-15 하네스 사고와 같은 유형).
5. **`CONFLICT` claim이 핵심 근거면 파이프라인을 시작하지 않는다.** 두 성과 파일의 `미해결 질문` 절부터 닫는다.
6. 산출물은 해당 공고 폴더(`resume/{PM용|SCM용}/{회사}_{직무}_{식별명}/`)에만 쓴다. 정본과 기본틀은 건드리지 않는다.

## 종전 파일 지도

**[2026-10-07 정정: 아래는 과거 파일 지도이며 사용 금지]** 종전에는 `resume/` 루트의 사실 정본을 `career_facts.md` 하나로 두었다. 현재 정본은 `resume/AGENTS.md`가 지정한 성과 파일 두 개다. 분석 문서는 루트에 새로 만들지 않는다.

**종전 정본** `career_facts.md` — 경력 사실 원장(claim ID·검증상태·트랙) · **종전 공고별** `applications/{회사}_{직무}_{공고ID}/`에 공고 원문·적합도·제출문·근거표 · **종전 감사 기준** `_eval/rubric.md` · **종전 증거물** `resume/` 루트의 PPTX·PDF·실운영 화면 · **종전 아카이브** `_archive/` 과거 제작지침·진단. 현재 작업 경로로 사용하지 않는다.

**종전 에이전트** `jd-analyst` 공고 해부 · `fit-strategist` 적합도·메시지맵 · `application-writer` 제출본 작성 · `application-auditor` 독립 검증. 현재 위임은 공통 공정의 평가 A·B·C를 따른다. 서브에이전트가 필요한 지침을 모두 상속한다고 가정하지 말고 정본 경로와 금지 규칙을 위임 입력에 명시한다.
