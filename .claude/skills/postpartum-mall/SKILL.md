## 한 줄 정의

아이베와 계약한 산후조리원 전용 B2B 쇼핑몰(고도몰5) 구축·운영. 개발기간 2026-07-01~08-31, 최종 검수 기준일 2026-08-31, 유상 유지보수 2026-09-01~09-30 월 최대 40시간. 출처: `PROJECT_STATUS.md` 3절(원본: 개발계약서). 형식 기준은 `pm-방법론` 스킬.

## 절대 규칙

1. **배포 통보와 완료를 구분한다.** 운영 서버에서 확인한 증빙(화면 캡처·계정 유형·재현 절차·기대 결과)이 있어야 완료다.
2. **새 요청은 먼저 분류한다** — 기본 개발 / 하자 / 프론트 조정 / 추가 개발 / 별도 견적. 분류가 곧 비용 판단이다.
3. **계약 범위 안의 오류·누락은 40시간에서 차감하지 않는다.** 차감 대상은 계약 범위를 벗어난 신규 기능뿐이다.
4. **시간 차감은 서면 확정 후에만 장부에 반영한다.** 요청 ID·합의 시간·작업일·배포일·검수 결과가 모두 있어야 한다. 채팅에서 나온 숫자는 제시값이다.
5. **비밀번호·인증정보·개인 연락처는 어떤 문서에도 적지 않는다.** 테스트 계정은 별도 보안 저장소.
6. 금액·시간·날짜는 계약서와 견적서 원본에서 재확인하고 인용한다. PDF·DOCX 원본은 수정하지 않는다.

## 확정 사실

### 문서 우선순위 (충돌 시)

개발계약서 → 첨부1 과업 상세 → 첨부2 개인정보 처리위탁 → 첨부3 구축 견적서 → 첨부4 유지보수 견적서 → 이후 서면 합의한 변경

- 구축 견적서의 "1차 QA 수정 1회"보다 **계약서의 프론트 조정 2회차가 우선**한다.
- 하자 수정은 프론트 조정 회차에 산입하지 않는다.

### ID 체계

`BR-nn` 기본 개발 요구사항(01~18, `PROJECT_STATUS.md` 4절) · `AR-nn` 추가·범위 밖 요청(5절) · `OP-nn` 40시간 장부(6절)
상태값은 `QA 대기` / `QA 실패` / `확인 불가` / `부분 완료` / `완료` 다섯 가지만 쓴다.

### 도메인 사실

- 회원 등급별 결제수단 자동 분기: 일반 물품은 포인트만, 분유·입금 상품은 무통장만, 후불은 발주하기. **결제방식이 다른 상품의 혼합 주문은 차단**되어야 한다 (BR-05·06).
- 주문번호 접두어 `JO_` (BR-14).
- 예치금은 매월 말일 자동 정산, 5만 포인트 이월 후 초과분 소멸. 기준금액은 관리자 설정 (BR-15).
- 무통장 자동매칭은 뱅크다. 고객 계좌번호를 매칭 조건으로 쓸지는 미확정 — 실제 현금 입금 테스트로 검증해야 한다 (AR-04).
- 등급명·금액·정책값은 코드 하드코딩 금지, 관리자 설정값으로 (BR-16).

## 함정

- "운영 배포 완료" 메시지가 곧 반영은 아니다. 실제 배포 항목과 버전을 따로 확인한다 (2026-08-07 01:34 사례).
- 채팅에서 합계로 제시된 공수에는 기본 요구사항이 섞여 있을 수 있다. 배송정보 복사 0.5시간이 실제로 그렇게 재분류됐다.
- 유지보수 시작일(2026-09-01) 이전 작업을 9월 40시간에서 선차감하는 것은 별도 서면 합의 사항이다. 자동으로 차감되지 않는다.
