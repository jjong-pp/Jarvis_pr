## 절대 규칙

1. 협력사 공유 양식(`planning_v5.html` · `api_field_mapping.html`)은 **구조를 바꾸지 않는다.** 값·설명 정정만. 중문판은 동시에 정정한다.
2. 자이언트 규격은 Postman 화면으로 판단하지 않는다. **컬렉션 원본 JSON을 내려받아 대조한다.** 화면은 지연 로딩되어 일부만 보인다 (2026-08-10 1차 검토 오판 원인).
3. 관세청 필드는 **명세서 v1.4.1 원문과 대조한 값만** 쓴다. 기획 문서에 있다고 맞는 값이 아니다 — 실제로 필드명 5건이 틀려 있었다.
4. 리스크·결정·질의의 정본은 `planning/risk_list.html` 하나다. 다른 문서에 새로 적지 않는다. 단 `리스크_질의대장.html`·`협력사_질의응답.html`이 더 최신이면 **날짜가 최신인 쪽이 이기고, risk_list를 갱신한다.**
5. 협의가 생기면 `planning/협의이력.html`에 **먼저 한 줄** 추가하고 기획서에 반영한다. 합의 재논의와 번복 미통보가 이 문서를 만든 이유다.
6. `documents/`의 PDF는 원본이다. 수정하지 않는다.

## 확정된 사실

출처: `planning/risk_list.html`(2026-08-10 재평가) · `planning/리스크_질의대장.html`(2026-08-11)

- **신고금액은 동수 ERP의 USD 단가 기준** (2026-08-10 결정). `tot_stlm_amt`·`prod_unprc`·`ord_amt`와 자이언트 `totalValueUsd`·`unitPrice`·`itemAmount`를 동일 기준으로 맞춰 3사 정합을 우선한다. 규격 문언은 "구매자가 결제한 최종 결제금액"이므로 **동수 단가와 고객 실결제액 대사표를 주문 단위로 보관**해 소명에 대비한다.
- **`sellerName` 채움 규칙** (2026-08-10). A 자사몰 = `(주)크로네`를 Geek이 고정 주입 / B 입점채널 = 실제 해외 판매업체명을 동수가 채널코드 기준 제공. 관세청 `sale_ents_nm`과 동일 값. **종전 "전건 Null 통일" 폐기.** 잔여: A유형 표기를 `(주)크로네`로 할지 `뉴트리시아몰`로 할지는 제출자 상호와 함께 확정.
- **`items[].hsCode`는 자이언트에만 6자리 전송** (2026-08-10). 종전 "HS코드 제거" 지침 폐기. 값의 원천은 동수 ERP 고정값이며 동수가 매핑한다. 관세청 TRA001에는 해당 항목이 없다.
- **동수 전송 완료 판별은 `POST /api/hwb/search` 응답의 `mwbNo` 채움 여부** (2026-08-10). 종전 "MAWB 필드가 없다"는 현행 규격 기준 해당 없음.
- **오류 수정 재제출은 `PATCH /api/hwb/:hwbNo`.** Body 4개 전부 필수: `consigneeTel` · `pccCode` · `tempAuthNo` · `totalValueUsd`. **이 4개 외(상품명·수량·주소)는 수정 불가** — 취소·재등록 절차를 자이언트에 확인해야 한다.
- **PER001 앞 2자리 이슈는 우리에게 해당 없음 → 계도기간 종료로 결제가 차단되지 않는다** (2026-08-10 재평가). 앞 2자리 응답은 관세청 직접 연동 시에만 해당하고 우리는 NICE 경유다. SMARTPCC_11이 `otp` 6자리 전체와 `pers_ecm`을 반환하므로 체크디지트 자체 구현도 불필요. 인증 모달은 2026-07-23 시연 완료. 남은 것은 모달 노출 증가에 따른 결제 이탈.
- **협력인정업체(K26000099) 신청은 보류·대기** (2026-08-10). CI 인증에 NICE 통합인증 모듈 선행 개발이 필요하고, Track B만으로 결제·통관이 성립해 오픈 일정에 영향 없음.
- **2026-08-11 확정 12건**: `ord_prod_nm`은 동수 ERP 기존 영문명 · `hs_cd`는 동수 ERP 고정값 · PCCC는 주문 `addField`에 적재(운영·개발 모두 확인) · PCCC 조회는 `개인통관부호`/`개인통관고유부호` 두 명칭 모두 허용하고 번호·키·정렬값에 의존하지 않음 · 국내외 혼재 주문은 동수가 해외직구 출고분만 반환 · 오류 건은 `p1` 원복 · 관세청 `ord_qty_ut`는 규격 외라 미전송이며 자이언트 `qtyUnit=EA`는 별도 필드 · 자이언트 PCC 검증 API의 GET/POST 표기 충돌은 NICE 검증 사용으로 개발 범위 제외.

## 함정

**관세청 TRA**
- "오류 없음 = 성공"은 거짓이다. TRA002 하나가 성공·부분오류·전체반려를 모두 반환한다(`txif_prcs_stcd` 01/02/03 + `errors[]`). TRA003은 보조이며 **택일 관계**지 후속이 아니다.
- TRA002로 `0000`을 받은 제출번호는 TRA003에 나오지 않는다. "TRA002 → TRA003" 순차 호출은 항상 빈 값이다.
- `txif_rgsr_err_cnt`가 0이어도 상품 개별 오류가 있을 수 있다. `errors[]`를 반드시 확인한다.
- `3000`은 동일 `txif_sbmt_no` 중복이다. IP 차단이 아니다. 진짜 30분 규정은 PER001에서 `ord_no_icln_tp=01` 발급 시 30분 내 주문완료 의무.

**자이언트 GGATE**
- `POST /api/hwb/search`는 없는 `hwbNo`를 에러 없이 조용히 제외한다. `transportType`(AI/OI 필수)을 틀려도 같다. **"결과에 없음"과 "동수 미전송"이 구분되지 않는다.**
- 중복 등록은 `H006`. **DELETE 엔드포인트가 없다** — 기획서의 `DELETE /api/hwb/{hwbNo}`와 "미완성 HBL 24시간 자동 소멸"은 컬렉션에서 확인되지 않는다.
- `PATCH` 예시의 `consigneeTel`은 대시 포함(`010-4024-3740`)인데 관세청은 하이픈 제외다. 포맷 분기가 필요하다.
- 소수점 자릿수가 어긋난다. `unitPrice` 3자리 / `totalValueUsd` 2자리 / 관세청 (16,3).
- 문자열 길이는 기획 문서보다 자이언트가 짧다(`productName` 200 등). 대조표는 `documents/자이언트_API_메모.md` 4절.
- `weight`가 0이면 `H014`.

**NICE**
- 가이드와 실제 동작이 다르다. 주문자와 수하인이 달라 일반인증을 요청해도 구매간소화로 응답이 내려온다(2026-08-06). **서면 회신 전까지 이 경로를 신뢰하지 않는다.**
- 제공된 테스트 데이터의 90% 이상이 실패하고 비갱신자(`03`) 시나리오는 테스트가 불가능하다.
